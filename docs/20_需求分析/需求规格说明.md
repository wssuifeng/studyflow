# StudyFlow 需求规格说明 · v1.19

直接上游：[系统定义](../10_系统定义/系统定义.md)。本文件是软件需求，不是私人学习计划。

| 需求 | 功能 | 验收要求 |
|---|---|---|
| R1 | C1 | 计划内顺序课程、当天排课；控制台按计划聚合，不重复主推进容器 |
| R2 | C2 | 知识与对应练习同屏；导航自动保存、允许跳题；整课事务提交，正式提交校验完整性；学习中的材料版本固定 |
| R3 | C3 | 原答案、评语、修正/复测父子版本可查；说明错误位置、原因和下一动作 |
| R4 | C4 | CLI提供JSON、稳定错误码、能力发现和准确待批改队列 |
| R5 | C4 | Skill适用任意Agent；不伪造答案、不直接SQL、不盲重试写入 |
| R6 | C5 | 文件限制于选定工作区；迁移有快照、清单和校验和 |
| R7 | C6 | 自动启停Engine；一体窗口保留拖动、最大化、最小化、关闭 |
| R8 | C2/C3 | 中文emoji原样往返；版本、幂等、状态冲突不产生部分写入 |
| R9 | C5 | 日志不记录答案、SQL参数和凭据；公开仓库无用户数据和私人历史 |
| R10 | C2/C6 | 可切换全应用展示主题，可改变布局/容器/教学表现/排版与本地图片，保护接口/学习核心及输入，不仅换色 |

## 已知限制

旧course import不能作为无条件增量更新使用；1.7.0课程修订需先preview再apply并保留学习快照。1.7.0安装候选包含独立CLI/Skill资源，不自动配置系统PATH或覆盖公共Skill。旧Web是兼容入口，不是第二套正式UI。THEME-BASE色板/预设切换已实现；布局视觉深化为最新授权，尚未编码；工程检查与用户验收分开。

## 业务闭环

Agent准备课程 → 本地固定本轮材料 → 用户逐知识点同屏学习/作答与自动草稿保存 → 整课提交 → Agent逐题批改 → 原位修正或复测 → Agent再批改 → UI分别展示本轮通过与下一学习课程。

2026-10-01用户采纳补充：允许暂时跳题；版本保护不做复杂平台功能。等待批改不默认阻塞后续课程；阅读、学习提交和本轮通过分别表达。见[一体化设计](../30_系统设计/学习与作答一体化设计.md)。

## 2026-10-02 用户确认增量：计划笔记和工具停靠

属于既有个人学习工作台范围，不新增平台业务。默认学习笔记贯穿整个学习计划，能兼容课程/知识点关联；前端支持正文摘录与来源标记。侧栏标签可调整、关闭/重开、展开和拆成原生工具窗。独立窗默认跟随主窗课程，可浏览全部知识点；同轮答案和笔记共享，不能重复建立课程轮次或割裂存储。笔记不当作作业、不触发批改。保存失败仍必须允许显式不保存退出。详细约束见[增量设计](../30_系统设计/学习与作答一体化设计.md)。

## 2026-10-02 用户确认增量：应用级右工具区

工具区属于应用整体而不是课程正文内卡片。默认关闭，只保留紧凑入口；展开时导航、阅读和工具等高且前两栏让出宽度。窄窗不得牺牲可用性，切到工具内容时仍可继续/提交并返回阅读。外观统一，提供即时、克制的视觉和可选音效反馈；不增加积分、排行等平台化功能。

## 2026-10-02 用户确认增量：结构化教学内容与阅读优先

对应R1、R2、R4、R5、R8、R9；实施证据于2026-10-03收口，不新增平台业务或第二套前端。

- Agent通过CLI输入具有知识点、内容块、题目稳定ID的整课JSON；软件校验后渲染受控教学组件，不接受Agent生成的可执行前端模板。
- 顶部保留紧凑导航，课程简介只在计划详情展示；正文知识点标题与教学小节分层，状态同时使用颜色、文字/图标，不以阅读完成冒充批改通过。
- 导入先整包校验、单事务登记，同包重放返回已有课程；冲突明确拒绝，不静默覆盖或追加。现有学习轮次内容、题目、答案保留。
- 练习链接定位同一答题入口，摘录保留冻结内容块来源；旧Markdown内容兼容，但不要求学习者查看原文。
- 当前测试课程可以重新导入，原始学习资料仍保留；材料生成和试点导入不标记学习完成。具体设计见[结构化课程组件设计](../30_系统设计/结构化课程组件设计.md)。

## 2026-10-03 用户确认增量：可切换主题专项

- 用户要求样式为可切换配置，不再只挑一个固定风格；保留唯一Vue前端。主题覆盖全部工作面及七类教学组件、Markdown兼容、练习/反馈/计划笔记与原生工具窗，不只覆盖首页。
- 主题切换保留当前答案/笔记/轮次/焦点/阅读锚点；已存阅读偏好、静音和减少动态效果优先于主题预设。配置异常回退，不阻塞学习写入。
- 可用轻量即时视觉与可选短音效，默认静音；成功只响应真实确认，跨窗不重复发声，不加入积分排行或装饰仪表盘。
- 外部主代理复用已经实现的主题契约，以不同真实设计Skill实现候选，子代理最多5并发、统一渠道/模型；每方向选一份进入同一应用。具体选择及未支持渠道须如实报告。
- 上述是早期交接；后续THEME-BASE已实现，外部旧wave矩阵当前40项submitted，不等于视觉通过。最新布局扩展另见下节。既有v1契约详见[主题与交互契约](../30_系统设计/前端主题与交互契约.md)。


## 2026-10-03 用户最新确认：主题不能只是换色

用户明确允许布局、容器、CSS与纯展示Vue/template调整，可用imagegen及相关Skill生成本地背景/纹理/局部插画；主题需要改善中文阅读、教学层次与操作体验，不把前端结构全部冻结为同一个模板。

锁定的是Core/CLI/Engine/API语义、学习轮次/冻结内容、答案/笔记/事务/幂等/保存失败与退出保护、窗口协调；展示允许有不同组织，但原有功能仍存在、可达且状态清楚。仍是一份正式Vue工程/业务实现，不建立十份保存/提交逻辑或任意脚本插件运行时。

旧studyflow.theme/1及40份旧色板保留兼容，新共享展示底座与候选overlay尚未实现。先补可运行能力，再做三个有结构差异的真实试点，效果合格才批量深化其余方向；模板/色板数量不能代替体验。图片本地化、可关闭/纯色fallback，不在正文上堆复杂背景，不传私人课程/答案/凭据到生成服务。

详见[布局视觉设计](../30_系统设计/主题布局与视觉扩展设计.md)与[执行计划](../40_开发实施/主题布局与视觉扩展实施计划.md)。布局换主题不能丢输入/焦点/IME/阅读锚点或重发未确认请求，浏览器真实渲染、Core闭环、原生窗口/系统DPI、用户长期体验分层验收。
