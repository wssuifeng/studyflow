# 桌面主题设计方向卡 · T01—T10 · v2

修订日期：2026-10-04。

本文件是新一波主题设计的唯一详细方向来源。旧 v1 方向卡已复制到 `docs/archive/2026-10-04-桌面主题设计方向卡-v1.md`，旧矩阵、旧候选和旧用户筛选结论不改写。新方向仍沿用 T01—T10 编号，避免破坏历史索引，但每个方向都重新定义了桌面工作面的结构签名。

## 1. 共同产品基线

StudyFlow 是本地个人学习桌面应用，核心连续关系是：

```text
学习计划 → 课程路径 → 多知识点阅读 → 同轮作答 → 批改反馈 → 修正/独立复测 → 计划级笔记
```

所有方向必须遵守：

- 直接服务窗口内的阅读、作答、反馈、笔记和退出，不做网页落地页、营销首页、监控大屏或积分系统。
- 课程可以包含多个有序知识点；知识点切换、答案草稿、整课提交、批改和复测语义不能被主题改变。
- 右侧工具区默认收起；宽窗展开后与阅读区等高并共同让宽；窄窗可以转为抽屉/工具工作面，但答题、笔记、反馈、提交和退出必须可达。
- 标题栏、窗口拖动、最小化/最大化/关闭、置顶、返回、失败保存后的“不保存离开”均保留。
- 七类教学块、旧 Markdown、作答、反馈、计划笔记、设置、空态和错误态必须统一设计，不只美化首屏。
- 正文、笔记、题目和中文输入使用正常中文排版；等宽字体只用于代码、编号和数值局部。
- 默认静音，减少动态优先；图片可关闭、缺图可回退，素材不能遮挡正文，也不能依赖网络资源。
- 相对于正式基座至少有三项可观察的非颜色变化，其中至少一项是布局、容器或教学组织变化。只改色板、阴影、纹理、圆角或几像素栏宽不算完成。

### 不允许的共同偏航

网页式英雄区、巨大仪表盘、重复卡片墙、全页玻璃、强 blur、霓虹 HUD、黑金、全文终端化、复杂背景压正文、伪造进度、隐藏错误、用颜色单独表达状态、为了主题新增无意义功能。

## 2. 新十方向

### T01 · 章节书签台

- **核心感受**：像一本可操作的学习工作册，而不是文章阅读网站。
- **结构签名**：窄章节书签轨 + 连续纸面阅读区 + 语义边注；知识点导航在左侧或阅读面上沿形成章节定位。
- **教学组织**：定义、对照、案例和小结以“章节带/边注/条件—推导—结论”分层；相邻概念可以形成连续阅读组。
- **工具关系**：答题与笔记作为右侧“工作页”展开，不把正文挤成窄列；笔记摘录保留来源标识。
- **交互反馈**：知识点定位像翻到书签，但只用短定位过渡，不做翻页动画。
- **禁区**：不做杂志刊头、首字下沉、页码装饰或棕色复古网页。

### T02 · 净白精密台

- **核心感受**：准确、清楚、低噪声，适合长时间学习和查找下一步。
- **结构签名**：紧凑顶栏 + 内容/工具分割面 + 精密索引条；减少大卡片，使用细分割线和对齐基线建立层次。
- **教学组织**：表格、步骤和提示使用不同密度的实体表面；标题、正文、状态和动作有明确阶梯。
- **工具关系**：作答区像轻量 inspector，题目导航、草稿状态和整课提交集中在一个可扫描区域。
- **交互反馈**：焦点、保存、定位和错误使用不同的微反馈，不靠颜色单独区分。
- **禁区**：不把“白”做成空白大页面，不堆透明卡片或仪表数字。

### T03 · 午夜聚焦台

- **核心感受**：进入夜读专注状态，但仍是实体桌面工具，不是赛博 HUD。
- **结构签名**：深色阅读主面 + 低亮导航轨 + 可收起的答题抽屉；当前知识点成为稳定焦点，不使用发光边框抢注意力。
- **教学组织**：正文表面、题面表面和反馈表面通过明度/边界区分；错误与待修正状态保留清楚文字。
- **工具关系**：工具区展开时从侧边切入，收起后阅读面恢复完整宽度；独立窗口使用同一轮内容。
- **交互反馈**：使用短暂明度变化、焦点线和状态图标；默认不播放声音，不做呼吸脉冲。
- **禁区**：不做霓虹、代码雨、黑亮玻璃或整页纯黑。

### T04 · 石墨模块台

- **核心感受**：成熟、稳重、像个人研究工作台。
- **结构签名**：不对称模块布局；导航、阅读和工具拥有不同但稳定的层级，不使用所有区域相同卡片。
- **教学组织**：教学块可采用“标题边栏 + 内容面”的模块结构；例题与反馈形成可折叠的分析模块。
- **工具关系**：右侧工具以标签组/模块组组织，笔记和答题可以在同一工具面切换，不能重复打开编辑器。
- **交互反馈**：模块展开、分栏调整、保存结果有明确按下和完成反馈。
- **禁区**：不把石墨做成黑色终端，不让灰色层级吞掉中文正文。

### T05 · 海盐层叠台

- **核心感受**：轻盈、清透、持续阅读不疲劳，但依旧是实体桌面应用。
- **结构签名**：层叠工作面；课程阅读、知识点导航和工具面通过浅层次前后关系组织，而不是十几个浮动卡片。
- **教学组织**：概念、对照、案例和提醒使用不同的边界密度；长正文保持一块稳定阅读面。
- **工具关系**：工具区像一层可推入的工作面，默认隐藏，展开时明确占据空间；不使用真正玻璃质感遮挡内容。
- **交互反馈**：切换知识点采用短距离滑移/淡入；保存状态使用轻量状态点和文字。
- **禁区**：不做玻璃拟态、强 blur、透明叠层过多或海报式大背景。

### T06 · 林间边注台

- **核心感受**：自然、安静、适合阅读和回顾，但不是壁纸软件。
- **结构签名**：正文与边注形成稳定的双列关系；边注可以收束为窄边轨，工具区仍独立于边注。
- **教学组织**：提醒、易错点和个人笔记优先落在边注层；定义和推导仍在正文主列，避免正文被切碎。
- **工具关系**：计划笔记可以在侧边查看，摘录保留冻结来源；答题工具展开时边注降级，不遮挡题目。
- **交互反馈**：滚动到教学块时边注定位，减少大幅动画；缺图时保持纯色阅读面。
- **禁区**：不铺满植物背景、不做自然风营销页、不把边注变成第二篇长文。

### T07 · 赤陶修订台

- **核心感受**：温暖、有触感，重点帮助学习者处理“原答案—问题—修正—复测”。
- **结构签名**：反馈/修正优先的阶梯工作面；阅读、原答案、反馈和修正入口有清楚的顺序，不只用红绿颜色。
- **教学组织**：案例和练习强调条件、错误位置、原因、修正提示；保留原答案与新的独立复测题的区别。
- **工具关系**：答题区在课程学习中仍可用，批改后可以快速回到错误知识点和复测任务。
- **交互反馈**：保存确认、反馈到达、修正完成、复测待处理分别有轻量但可区分的反馈。
- **禁区**：不整页棕色、不做复古海报、不把错误状态变成刺眼警报。

### T08 · 深海蓝图台

- **核心感受**：适合理解复杂过程和推导依据，像分析工具而非监控屏。
- **结构签名**：步骤轨道/依据索引 + 中央推导面 + 右侧练习工具；轨道可以独立于正文，也可以嵌入教学块。
- **教学组织**：条件—过程—结论、输入—处理—输出、对照表和步骤块必须形成可定位的结构。
- **工具关系**：大纲、题目和笔记均可通过步骤定位，不伪造知识图谱或新增业务字段。
- **交互反馈**：定位到步骤时显示短焦点和当前路径，不发光、不脉冲、不改变正文顺序。
- **禁区**：不做科幻 HUD、霓虹连线、监控大屏或满屏网格。

### T09 · 代码知识双台

- **核心感受**：代码、表格和参数精准，中文讲解与笔记舒服。
- **结构签名**：代码/数据表面与解释面成对出现；代码只有局部使用等宽，中文正文不终端化。
- **教学组织**：代码—解释、条件—运行/推导—结果成对布局；没有代码的课程也必须自然降级。
- **工具关系**：答题区与代码/解释同一工作面，笔记可引用正文或代码来源；长表只在内部横向滚动。
- **交互反馈**：代码定位、复制/阅读、题目保存和批改状态清楚分开；不模拟终端命令。
- **禁区**：不做代码雨、黑客霓虹、全文等宽或让代码块占领整页。

### T10 · 单色键盘台

- **核心感受**：可访问、可键盘操作、状态准确，同时保持设计层次。
- **结构签名**：键盘优先的稳定工作区；焦点轨、语义标签和边界形态承担状态表达，不能依赖色相。
- **教学组织**：七类教学块按职责而非颜色区分；错误、退出确认、不保存离开和禁用态都保留可读文本。
- **工具关系**：答题、笔记、反馈、提交和退出都可通过 Tab/键盘到达；右工具区减少不必要嵌套。
- **交互反馈**：焦点环、按下态、展开态和状态图标在减少动态模式下仍可理解。
- **禁区**：不使用刺眼纯黑白、不把所有内容包进粗黑框、不以极小文字换取高对比。

## 3. 派发判定

每个方向的第一份候选只做 30% 可操作骨架，必须覆盖：

1. 窗口壳和标题栏视觉关系；
2. 课程首屏与知识点导航；
3. 七类教学块中的至少一个中段；
4. 右侧工具区收起/展开；
5. 答题、笔记、反馈或错误态中的至少一项；
6. 720×600 或 800×600 的可操作退化；
7. 设计差异表、使用的 Skill 和真实截图证据。

每个方向必须证明三项以上非颜色差异，其中至少一项为布局/容器/教学组织。旧颜色-only 候选不得作为基座、不得直接修色后重新提交；如需参考，只能作为反例审计输入。

主代理可以替换方向中的推荐结构，但必须写明：

- 哪个学习任务得到改善；
- 哪个现有容器被合并、拆分或重新定位；
- 如何保留同轮答案、计划级笔记、整课提交、批改/复测和可靠退出；
- 如何在缺图、无图、减少动态和窄窗模式下保持可用。

用户先看十方向的 30% 骨架，再决定哪些方向进入第二轮精修；不把 10 个 submitted 当作 10 个已采纳主题。
