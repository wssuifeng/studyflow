# 学习与作答一体化设计

依据：用户于2026-10-01采纳同屏学习、整课提交及改进建议，并确认允许暂时跳题、保护学习中版本；随后明确授权优化核心业务链。
直接上游：[需求规格](../20_需求分析/需求规格说明.md) R1—R5、R7—R9。

## 产品边界

StudyFlow是本地开箱即用的个人学习软件。沿用唯一Vue前端、Tauri自动管理Engine、Python Core和默认SQLite，不要求手动启动数据库/后端。外部Agent经CLI准备课程和批改，学习者不需要Agent在线才能阅读和保存。
不做账号/租户/SaaS、排行榜、积分、内置AI API、复杂版本管理界面或多份前端。控制台简洁展示继续学习和需要处理的反馈。

## 连续学习流程

计划 → 课程 → 当前知识点材料与对应练习 → 保存并切换下一知识点 → 最后一项检查整课必答题 → 统一提交 → 逐题反馈 → 原位修正/复测。

知识点目录可直接切换；允许空题保留草稿，不在导航时阻塞学习。整课首次提交仍校验全部必答题，缺题定位到对应知识点与输入区。已提交题只读；修正/复测仅编辑需要处理的题，不覆盖原答案。

输入防抖自动保存到工作区；所有导航先强制保存。保存失败留在当前知识点并保留输入，显示可重试状态。本设备缓存用于故障兜底，不冒充数据库保存。恢复时不静默覆盖其他窗口的新版本。保存/提交串行化，重试必须复用原载荷和幂等键。

阅读确认、本次学习提交、本轮通过分开。没有练习的课程可明确完成阅读。等待批改不阻塞下一课程，除非另有明确先修约束。本轮通过不宣称长期掌握。

## 轻量版本与批次

新增一个课程学习会话表：冻结知识点正文、题干和约束，保存该轮阅读位置；提交记录与现有整课写入凭据关联会话。正文内容固定，不复制一套课程/题目关系模型。
打开课程时开始或恢复当前会话；文件后来被Agent修改，不改变当前会话材料。来源变化仅提示，不静默升级。只有本轮收口后，才允许显式开始新版学习；旧作答仍引用旧快照。已有历史无快照的作答如实标注，不伪造其当时题面。
复用整课写入凭据作为提交批次，不另建平台式批次系统。按批次和逐题状态汇总待批改、部分反馈、待修正、待复测和本轮通过。Agent队列保留逐题载荷，附带批次/冻结上下文，避免读取已变更文件进行批改。

## 交互与验收

同屏材料与练习，桌面宽屏可用双栏，窄屏顺序排列；只在当前知识点渲染题目，切换不丢整课草稿。保存反馈在底部轻量显示，不对每次自动保存弹Toast。支持键盘焦点、缺题跳转、减少动画偏好。
必测：空题跳转、导航保存失败、关闭恢复、重复提交、并发版本冲突、批改部分返回、原位修正/复测、源材料修改后保持冻结、旧记录迁移不丢失、待批改不占学习推进点、纯阅读完成。
