## 1. 要解决的问题与方案选择

用户目标不是课程版本管理系统、在线教务平台或十套独立前端，而是：正确的课程一次生成得更好，必要纠错立即可见，两套主题长期维护一套交互。

| 路径 | 收益/代价 | 结论 |
|---|---|---|
| 继续增加提示词、逐张截图修CSS | 改动少；仍依赖生成者自证，主题分支与旧材料问题继续积累 | 不作为主方案 |
| 生成侧有证据的审查闭环 + 当前材料纠错 + 共享骨架/主题参数/程序门禁 | 复用现有Core、CLI、Vue与Skill；把问题前移，不建设第二套系统 | 推荐 |
| 内置AI制课后台 + 自由文档/CMS + 新主题框架 | 运行依赖和维护成本高，超出本地个人学习定位 | 不采用 |

约束：不加账号/权限/多租户；不内置模型密钥；不更换Vue/Tauri/Python技术栈；不把Skill写成特定课程专用；TTS预生成、考试/试题专项继续暂缓。普通课右工具只有练习/笔记，英语右工具只有笔记。

## 2. 两条闭环，而不是发布后一直返工

### 2.1 主闭环：生成侧质量控制

```text
有界读取目标/现有学习证据/必要资料
  → 目标与先修对齐、挑选少量合用材料
  → 先写自然准确的目标表达/知识主线
  → 反推教学过程与检验，生成完整课程数据
  → 作者逐项自检 + 独立内容复核
  → 确定性校验 + 同模板/跨链复核
  → 实际Vue代表状态呈现与交互检查
  → 小样确认后同规则扩批
  → 发布前绑定内容hash的复核结论
  → 正常CLI写入、回读、核对用户实际读取材料
  → 学习反馈回到阶段目标与下一段课程
```

每个箭头都有输入、输出和失败回流。题目语义失败回到目标/讲解/同链改写；数据失败回到序列化；显示失败回到软件，不要求作者牺牲教学结构绕布局。不是所有失败都退回重写整课。

### 2.2 补充闭环：低成本纠错与规则改进

发现问题 → 区分内容错误/呈现错误/操作失败/真实知识缺口 → 确定同类影响范围 → 最小纠错 → 复审受影响链 → 当前界面回读 → 加反例回归/更新可泛化规则。

纠错是安全网，不是默认制课方式。把一次错误归纳成“缺隐藏主语的屈折动词片段不能充当独立动作表达”，而不是不断追加单句替换黑名单。内容错题不能被当成学习者能力不足继续生成补课。

## 3. 生成前与生成时：先保语义，再决定展示形式

### 3.1 共同规则

- 先写可观察目标、先修、必要事实和合格证据，再编教学与题目；不按固定知识点数、字数或题量凑课。
- 作者资料按当前目标有界读取。母表按目标取出持久小表，不一次性无目的拆完或反复全读。
- 草稿源、对齐表和审查报告是作者工件，不渲染进学生正文。正文不出现Agent流程、revision治理或审核口号。
- 正文是一篇有逻辑关系的课文。定义/条件/关键推理常显；非必需扩展采用现有details或/5 supplement，不能为短而隐藏必要知识。
- 例子、steps、comparison、callout按语义使用；不把内容全写成长body，也不凑固定六件套。
- 事实不确定时查证或降低断言；未核实不编造权威来源、IPA来源或词典调用结果。

### 3.2 普通课程的生成期复核

逐知识点核对首次术语定义、条件/单位/公式、解释与案例一致性；逐题从作答前可见信息检查可解性、作答要求与解析分离、等价解的容纳范围。折叠详解后，学习者仍应能理解主干并完成对应基本检验。

对程序、计算、数据表示等可确定验证的内容，优先运行小型可复现算例；测试环境与语言版本写进作者证据，不冒充用户学习记录。对比较表逐列检查维度和例外，而非只看表格是否存在。

### 3.3 英语课程的生成期复核

1. **先终点后递进**：先确定自然、准确且有用途的完整目标句，再挑必要单词、自然词组/简单句、组合与迁移。允许重写终点，不为保留错误切片硬补语境。
2. **练习单位明确**：单词、词组、完整句、明确给上下文的语法题分开。自然名词/介词词组合法；动作词组默认自然原形搭配。屈折谓语需要可见主语/上下文，不把它藏进中文暗示或英文挖空载体。
3. **语义三读**：独立读每个目标及全部变体；连同中英文提示读；按教学链通读。分别核对自然度、专业事实、已学先修和负荷。
4. **成分不按词性硬贴**：完整句先写“角色→实际词段”，再由真实token序列计算范围。情态/助动词与实义动词、限定词与名词、介词与宾语按实际结构处理；短语不伪装完整主谓宾。
5. **解析派生同源**：目标、tokens、角色框、短义、词性、IPA、解释和完整答案变体一起校对；不另建一套手填数字范围。软件只投影，不擅自用POS猜句法。
6. **变体逐条审查**：每条变体须在题面条件下等义；can do与does不能仅因主题相似混为一谈。不支持的开放表达不要装成唯一正确答案题。即时训练仍只用实际支持的local_exact和完整变体；不新增“提交给Agent审核”入口，作者内容审查不进入学习页面。
7. **IPA由作者编写核对**：分清口音与词形；词典发音兜底不是自动补齐IPA。IPA缺口记录为作者问题，不在学生页面加大段工程提示。

工具可提出候选，不机械给所有-s去尾、不用简单词性规则宣布语法正确、不为覆盖全部词汇牺牲句子自然性。

## 4. 审查机制：有证据、不自证、不无限循环

### 4.1 最小作者工件

一次课程交付只保留：课程包、目标/教学链蓝图、合并质量报告、发布回执。完整来源清单可复用已有小型索引；截图只保留代表状态及缺陷证据。不要每次为同一课程再造几十份平行文档。

质量报告绑定：package SHA-256、规则版本、能力配置、课程/题语义ID、目标与全部变体的hash、检查范围、每项结论、未检查范围。包内容改变即使ID不变，旧审查结论也不能直接复用。

### 4.2 结论类型与责任

| 类型 | 例子 | 处置 |
|---|---|---|
| deterministic_error | token越界、断链、无效字段、无法解析的包 | 修正前不进入发布 |
| content_defect | 事实错误、无语境屈折片段、错误成分、变体不等义 | 修正及复核同类范围后再发布 |
| review_required | 专业语义/IPA来源待核实、自动候选未裁决 | 记录理由和明确复核结论，不能按零告警放行 |
| presentation_defect | 必要信息不可读、按钮不可达、折叠失去条件 | 修软件或适配；不能让作者改成错误内容绕过 |
| advisory | 不影响正确性的次要表达/可选压缩 | 允许带理由保留，不冒充阻塞错误 |

生成Agent逐项自审是基本职责。独立复核者应只接收课程源、目标与判据，先形成意见，再看作者自评，减少互相迎合。可以是另一个执行上下文或人工，不强制某供应商；仍要注明是否同模型/同上下文。没有独立复核能力就标记未完成该关口，不伪造“独立审核通过”。本稿不授权当前会话启动子代理。

### 4.3 增量复核与成本上限

新课或大规模语义变更要覆盖全课；之后小改复核修改项、全部变体、前后依赖链及同模板项，确定性校验仍跑全包。不能把第一次只抽3题当全课语义基线。

同类问题修一条后主动查同模板，避免用户逐题报错。连续两轮仍无法消除关键语义问题，暂停该批发布并返回更小目标/更简单教学设计，而不是无限付费重试。模型调用按宿主实际额度调度，独立复核不以铺开大量并发代替质量。

## 5. 软件审查工具与发布关口

复用 `skills/studyflow-agent/scripts/authoring_quality.py`，不要另造不一致的第二套规则。Core/CLI保有协议与业务检查；Skill保有教学审查说明；Vue保有真实呈现验证。可把质量脚本中的确定性部分下沉为Core共享检查，由Skill薄适配调用，迁移时逐条行为回归。

**拟新增能力（不是现成命令）**：作者只读检查入口，接受显式课程包/蓝图/来源/旧包，返回结构错误、风险候选、角色实际词段、教学链与变体清单。不得自动访问所有真实答案或把真实课程上传外部模型。CLI的具体命令拼写与Engine方法须在实施时按现有注册方式确定，并通过capabilities发现。

作者发布流程分开显示：协议校验、内容复核、实际渲染、写入回读四项结论。对于新流程，关键错误未修/必须复核项未处置则停止制课发布；本地软件不新增账号审批或伪安全签名。旧课程/旧导入流程可兼容但标记“未经过新质量流程”，不能因没有历史报告而禁止打开旧课。

发布后还须核对**用户当前实际读到的材料**，不是只核对最新课程表。当前/历史读源不同，要明确未交付；新材料生效机制见下一节。所有审查、模拟学习用合成隔离工作区，不把测试写入真实掌握证据。

## 6. 课程修改的产品设计：更新成功后直接重置学习状态

### 6.1 已确认选择与范围

2026-10-16用户明确选择“直接重置课程学习状态即可”。因此取消v1中按题目影响分类、保留当前进度、逐题增量切换/映射/合并的方案，不再开发该复杂路径。

统一行为：**内容更新成功 → 目标课程学习状态重置 → 下次打开从当前最新材料开始。** 不要求先学完错误材料，不要求用户操作版本/冻结/轮次。现有内部机制可复用，不新建用户可见版本管理平台。

适用于普通和英语课程的内容替换、正文/题目/解析/音标等实际材料修改。纯主题/CSS变化不重置；相同内容的无变化更新不重置。只影响指定课程/计划挂载项，不批量重置其他课程或计划。

### 6.2 重置后的状态

| 对象 | 处置 |
|---|---|
| 当前阅读进度、知识点/题目位置 | 归零，使用最新材料的起点 |
| 当前训练检查、跳过、揭示、错误次数、当前作答/完成标记 | 新一次学习从初始状态开始，不复用旧答案/通过状态 |
| 目标课程的当前待学/完成分组 | 回到待学习；重新计算相应计划汇总，不影响其他课程 |
| 已有答案、反馈等历史证据 | 可用现有历史机制留存，但不计入这次学习，也不回填新材料；不开发逐题迁移/映射 |
| 计划/课程笔记、引用 | 保留；旧来源保留出处，无法定位到新版锚点时合理回退，不静默指向错误段落 |
| 其他课程、其他计划、工作区设置 | 不变 |

“重置学习状态”不等于删除课程实体、清空笔记或清理整个工作区。若当前数据模型需要封存旧活动会话并在下一次打开创建新活动会话，可沿用该内部实现；用户只看到课程从最新内容重新学习。

### 6.3 最小可靠性要求

- 沿用CLI/Core的正常更新入口、工作区租约、CAS与幂等，不直接SQL，不全局关闭版本检查。
- 更新失败时保留原材料和原学习状态；同一次幂等请求重试不能反复重置。更新与重置须作为一致的业务操作处理，复用现有事务/文件补偿。
- 打开的旧训练/阅读窗口收到重置后，停止旧会话自动保存与导航，读取新的课程状态。旧草稿不回填新版；未提交输入不能无提示丢弃，可留作旧草稿/导出。
- 迟到的旧保存/检查请求不能写入新学习状态；丢回复先核对原请求回执。不要为规避此项又建立一套题级增量材料合并系统。
- 提交、目录和首个未完成定位统一使用重置后的材料与状态；应用重启后不恢复旧材料活动轮次。

最少隔离回归：普通/英语更新后归零并读最新材料、已完成课回待学、有草稿/保存中更新、失败不重置、相同幂等请求不重复重置、无变化包与纯CSS不重置、旧请求不污染新版、笔记保留、重启恢复正确。**真实工作区不作为实现试验场；本轮没有执行真实重置。**

### 6.4 页面说明

移除“课程已有新修订，请先做完旧材料”等常驻技术说明。必要时仅提示“课程内容已更新，学习进度已重置”，不再提供继续旧材料/手动换版等复杂选择。成功朗读、正常保存也不常驻大段工程说明。不能只隐藏提示而仍恢复旧活动材料。

## 7. 前端交互与页面设计处置

### 7.1 反馈语义统一

| 事件 | 表现/恢复 | 禁止 |
|---|---|---|
| 空输入、格式缺项 | 输入附近短说明，焦点留在输入，不记答错 | 导出输入/离开训练/保存失败 |
| 答案不匹配 | 词位定位、保留错误输入；按既有连续错误/快捷键规则显示解析 | 自动认定未收录表达语法错误 |
| 正常异步保存 | 轻量页级状态，输入不等待持久化 | 每词触发阻塞、常驻故障横幅 |
| 写入失败/结果未知 | 区分确定失败与未知结果，只有对应场景提供重试/导出/离开 | 所有DomainError共享一套恢复按钮 |
| 发音失败 | 非阻断提示与必要重试 | 阻止检查/提交、冒充保存失败 |
| 材料改变 | 按§6重置目标课程并读取最新材料 | 要求先完成错误教材或静默恢复旧状态 |

用明确类型表达状态，不能靠解析错误字符串。自动保存、检查和导航分别管理，不让一次空答案校验污染整个会话的保存状态。

### 7.2 页面空间与组件职责

- 普通阅读：一个紧凑上下文区、一个主要正文滚动区、一个稳定动作区；左栏已有课程/本节大纲，顶部不再重复铺完整知识点导航。正文有合宜行宽，但不在一层大居中卡片内再套一层厚留白。
- 英语训练：保留全界面专注模式；输入前后位置与比例连续。通过反馈轻量、不额外渲染巨大独立答案页；只在规则允许时展开答案/解析。底部一行快捷键，词/句朗读、错误前移与一次Enter再检查保持一致。
- 控制台/计划：页面标题与区块标题不机械重复；筛选区与列表统一布局节奏；卡片随信息量而定，不为空内容撑成展示大屏。移除无实际任务价值的营销落款/口号。
- 侧栏/独立工具窗：工具子页导航与所属容器同宽；笔记保持连续文档和三级折叠；主题不能把共享编辑交互改成另一套。英语不出现重复练习标签。
- 弹窗：共享标题/正文/动作/焦点/键盘退出规则；确认动作说明具体影响。错误条不是万能弹窗，不用危险色展示普通输入提醒。

原项目只能借鉴有效的输入/反馈/排版规律。复用素材或代码前核对实际license与来源，不把商业保存页面或AGPL代码/音频未经审查复制进本仓库；不承诺法律结论。

## 8. 主题契约v3：程序层面控制维护成本

### 8.1 一套业务与布局，多套视觉配方

```text
AppShell / 页面结构 / 业务状态与动作（唯一实现）
  → 共享布局计算（导航/正文/工具预算、断点、scroll owner）
  → 共享UI组件及有限variant（按钮/表单/状态/弹窗/文档组件）
  → 语义token与组件token（主题提供受控值）
  → 纯装饰资产槽（可关闭、无图回退、不参与功能几何）
```

业务组件不得通过activeTheme.id决定导航是否存在、按钮集合、读源、保存行为或工具标签。主题ID只允许在主题注册/转换、资产查找和纯视觉调试边界出现。模式差异由ordinary/english、页面类型与可用能力决定，不由颜色主题决定。

### 8.2 token与布局的权限

| 层 | 可配置 | 不可配置 |
|---|---|---|
| 主题视觉 | 语义色、受控字号/字重、圆角、边框/阴影、插图、动效强度 | 业务条件、工具集合、错误恢复动作 |
| 共享密度profile | compact/comfortable有限枚举，统一映射间距和控件尺寸 | 每主题任意padding/width覆盖正文骨架 |
| 应用布局/用户偏好 | 导航宽度预算、阅读字号/行宽、工具宽度、窗口断点 | 主题各算一套grid或改变scroll owner |
| 组件配方 | 有文档的有限variant、组件语义token | 通用深层选择器随意修改其他组件 |

旧主题JSON继续解析，旧layout/reading_shell等字段通过迁移适配映射到受支持profile；不能无声丢弃用户配置。旧主题CSS逐组件迁移，不能一次删除后把外观回归称为统一完成。

### 8.3 需要真实实施的四道门禁

1. **配置门禁**：扩展现有 `shared/themes/contract.ts` 与 `scripts/check-theme.cjs`。拒绝未知布局能力/越界数值/可执行内容，兼容迁移产生明确warning。主题切换不触发Core写入。
2. **源码门禁**：AST检查业务Vue/TS中主题ID分支与未授权主题依赖，路径白名单只放注册/资产层。不是正则搜一个sequenceTheme变量名就算完成。
3. **样式门禁**：解析CSS AST，对主题作用域中的布局越权（grid、功能区display/position、viewport高度、overflow/scroll owner、结构尺寸等）按selector和property检查。装饰绝对定位只准在专用装饰槽、pointer-events:none且不遮挡。禁止新增布局!important；既有债务先精确列白名单，再只减不增。
4. **运行时门禁**：同数据/同窗口/同密度切换双主题，比较功能区域与交互状态，验证固定左栏、正文空间、工具开关、焦点和输入保持。静态检查不能替代真实computed style与浏览器布局。

拟新增 `theme:lint`、`test:ui-contract` 是实施目标，不是现有可运行脚本。先增加有意违规的合成fixture证明门禁会失败，再放进CI；不能只添加一份永远返回true的检查。例外记录必须限定文件/选择器/属性/理由/收口任务，不允许整个主题目录跳过。

### 8.4 控制组件与样式债务

复用/整理shared UI，不强制换设计系统依赖。按钮保留主、次、文本、危险四种语义与loading/disabled/focus状态；表单、tabs、状态提示、确认弹窗使用同一契约。功能特有组件仍留features；不把所有东西堆入一个万能组件。

`sequence-light.css`、`white-violet.css` 最终只含可解释的视觉配方/装饰，不再定义两套阅读导航、工具几何和滚动。遗留覆盖删除以状态回归为前提；不按CSS行数减少来宣称体验变好。

## 9. 可测量的视觉与交互验收

使用CSS像素而非图像文件标注分辨率判断布局；Windows缩放另做原生验证。桌面产品不强行改成移动端模板。

| 场景 | 约束/目标 |
|---|---|
| 1920×1080普通阅读、工具收起 | 正文滚动容器高度至少为窗口内容区65%；避免顶部重复上下文。行宽与外框宽分离，不把正文拉成无边界长行 |
| 1440×900、1280×720 | 正文分别争取至少60%/55%内容高度；控件不盖正文/动作区，低高度时压缩次要信息而非全局缩字 |
| 双主题工具展开/收起 | 同一几何预算、相同工具归属；不足宽度使用现有共享compact/dock策略，不由主题另造覆盖 |
| 960宽压力窗口 | 不横向整页溢出，主要操作可达；代码/表格局部横滚；仍有合理退出与导航方式 |
| 长文/折叠/长标题 | 基本文字默认16—18px级、行高约1.7—1.9为起点；真实中文/英文可读，用户字号偏好不被主题覆盖 |
| 英语输入与检查 | 按键本地更新不await持久化；修正首个错词后一次Enter可重新检查；末项有遗漏自动定位首个未完成 |
| 弹窗/工具独立窗 | Tab焦点受控、关闭后返回触发点、Escape按保存保护执行；无被遮挡操作 |
| 原生 | 实测Windows100%/125%/150%DPI、工具置顶/多窗与实际可用多屏；无法实测的物理条件明确未验 |

以上百分比为设计验收目标，实施试点可在用户可读性确认后校准，不把数字优化凌驾于使用体验。输入/检查/保存分别记录基线与改进后的p50/p95；不把Engine持久化时间混成输入耗时，不凭任意sleep造顺滑截图。

页面覆盖须从实际App路由与独立窗口清单建立，不仅阅读页：学习控制台、计划列表、计划详情/课程路径/补充学习、普通阅读与练习、英语概览/训练/复测、作答队列与反馈、错题工作区、设置/Agent接入、计划笔记、独立工具窗口。普通/英语是不同业务模式，可以不同构图；双主题在同一模式内共享结构与状态语义。

每个主题覆盖：正常、空、加载、长文、工具展开、输入错误、保存失败、结果未知、主题切换、确认弹窗。通用组件覆盖全部状态；页面挑真实关键组合，不为追求笛卡尔积生成海量无意义截图。截图必须实际查看并有检查范围；测试通过不替代用户视觉采纳。

先读当前任务所需入口，再按引用加载，不要求每次读完所有Skill。公共Skill不放项目路径、主题名单、课程ID或供应商密钥；项目约束留在本稿/派发提示词。

## 12. 独立克隆工作区与并行安全

独立克隆只写自己的仓库、隔离工作区与测试输出。禁止连接真实学习工作区、自动同步公共Skill、改本工作区、覆盖安装应用、改共享工具配置、启动其他会话或推送主分支。

**关键：仅克隆远程不足以得到本轮基线。** 当前有未提交源码/规则增量，必须使用交接包中的base.bundle、base SHA、完整软件快照与文件清单恢复（binary patch供差异审阅），核对每个文件hash和删除清单。安装公共Skill与源码交接是两件事；公共文件不替代仓库源。

交接包不含真实课程、答案、数据库、模型配置、安装包、运行日志或node_modules。远程第三方执行环境不得自动上传私人截图/商业保存页面；使用合成复现材料。若跨机器不能获取本机公共Skill，可按锁定来源安装到该执行环境，不要求复制密钥。

本工作区与独立克隆不共同编辑同一目录。主工作区如同时开发共享接口，先形成变更清单；合并通过commit/cherry-pick/patch完成，不复制整个src覆盖，不覆盖后来的无关修改。返回时基于交接基线报告自己的增量，不能把交接包已带的改动再次当新成果。

## 14. 完成判据与不交付的内容

- 生成侧：真实规则可被入口发现；故意错误课程被拦/明确复核，不接受“脚本零告警=内容合格”；修正后的包才使用相同hash审查回执。
- 材料：实际内容更新后目标课程状态归零并读取最新材料，旧作答不回填；失败不重置，重试不重复重置，笔记保留；不要求学完错误教材。
- 前端：截图所涉问题由统一组件/骨架解决；双主题功能/状态一致，不只截成功首页；内容正确与视觉合格分开报告。
- 程序约束：故意主题分支/越权样式/非法token在CI失败；合法装饰和兼容旧配置不被误杀；主题切换不写业务数据。
- 交付：提供增量、验证回执、版本/迁移说明、未验清单与可复现演示。安装包只在用户另行授权时编译/安装，Git推送同样另行授权。
- 不交付：真实课程批量修订、两专项新课、TTS、考试、知识库、账号平台、自动上传私人数据。后续课程任务提示词在软件与小样确认后更新，不让课程作者先猜未发布能力。
