## 1. 先看结论与范围

建议统一采用以下方向：

| 项目 | 推荐方案 | 不采用 |
|---|---|---|
| 学习正文 | 一篇有内部层级的连续课文；叙事正文弱化卡片，例题/对照/提醒保留必要边界 | 所有内容都装同一种卡片；或把所有文字挤成一个无结构巨块 |
| 小节折叠 | 结构化小节、稳定ID；主干常显，补充解释可折叠；与大纲/笔记引用联动 | 任意HTML、按字数截断、所有块一律折叠 |
| 批改依据/答案解析 | 同一本地制课包组织题目/参考；解析可折叠，错误后说明为什么；版本与题面匹配 | 账号权限系统、提前把答案塞入作答要求 |
| 计划课程实例 | 待学习/已完成/其他三组；学习事实与特殊管理状态分开，暂缓不删除历史 | 全局Course一次完成影响所有计划，归档冒充学完 |
| 制课质量 | 情景化模板 + 明确审核判据 + 少量真实课程试点 + 分关口扩批 | 继续堆叠抽象要求，或把validate/测试通过当教学质量合格 |

适用普通与英语两种模式；英语训练仍占主界面，侧栏只保留笔记。本轮不做TTS，不启动词群全量标注/补释义，不改真实18门课程、不重开轮次、不同步公共/安装副本或发布。

### 1.1 备选路径与取舍

- **只改CSS和Skill**：成本最低、兼容容易，可减轻碎片感；不能解决可定位的小节折叠与批改参考版本链。可作为显示兼容层，不作为完整方案。
- **共享课文流 + 受控小节 + 本地批改参考（推荐）**：保留组件和JSON作者模式，用有限结构补齐核心能力；只有一个Vue前端和一套学习状态。
- **自由排版/CMS或通用递归文档平台**：表达能力强，但增加编辑器、转换、安全和主题维护成本，不适合当前个人本地学习软件。

## 2. 不变的边界

1. 计划 → 课程 → 知识点/英语训练组保持不变；不因为小节增加第四级软件导航，也不将每个词/段落拆成课程。
2. 左栏仍是课程大纲/本节大纲切换；主阅读区与右工具区几何不改。普通课右工具为练习/笔记，英语仅笔记。
3. 自动保存、暂时跳题、整课提交、修正/复测、CAS/幂等、冻结轮次、失败重试和不保存退出链不改义。
4. 主题只调整排印、颜色、留白、边界和轻量反馈；不能决定某功能或大纲是否存在。
5. 课程内容继续使用受控JSON/Markdown片段，不接受作者CSS/JS/任意HTML。Markdown是内联表达方式，学习者不需要看原文件。
6. Skill负责教学规则和任务组织；CLI/schema负责合法数据及安全操作；前端负责实际展现。不能让作者改成巨块以掩盖软件布局缺陷。

## 3. 连续课文流：正文是主线，功能块是工具

### 3.1 阅读页结构

```text
现有课程路径/退出按钮
当前知识点标题 + 精简学习状态
正文主线
  小节标题 → 段落/定义/公式 → 必要例子
  补充理解（简述常显、详解可展开）
  对照或例题（仅确有独立作用时）
  独立尝试入口（仍打开现有练习工具）
现有上一知识点 / 下一知识点 / 完成课程
```

不新加仪表盘、六格路线图或一套重复进度卡。导航继续来自实际知识结构，而不是内容块类型列表。

### 3.2 块的展示职责

| 类型 | 展示方式 |
|---|---|
| concept | 默认进入同一正文流；无独立大底色/厚边框/重复类型徽章，使用真正的小节标题和段落留白 |
| example | 保留轻量范例区域；条件、推导、理由、结论有内部层次，不拆成多张孤立卡 |
| comparison | 保留语义比较表；列标题、首列关系及窄窗横向滚动清楚 |
| steps | 仅展示有顺序/状态意义的过程，不把普通段落装成步骤 |
| callout | 低面积提醒，仅用于真实边界/易错点；不每块重复“重点” |
| summary | 短回收段落/列表；不与正文机械重述；不强制每个知识点存在 |
| practice | 简洁试题入口/必要指引，具体题面和输入仍由现有练习工具承担 |
| details | 保留已实现的独立补充解释；视觉并入课文，不再增加外层重复卡片 |

相邻concept只按原顺序连续显示，不自动配对、不合并底层数据、不吞掉ID。必要边界、块类型和笔记引用标识在数据中保留；弱化视觉容器不等于删除组件。

### 3.3 标题与阅读密度

- 知识点标题是阅读主标题；有内容职责的块/小节形成后续层级。内部Markdown标题相对该位置归一化，禁止外层h4、内层h2的层次倒挂。
- 块标题与知识点标题完全重复时只显示一处，并明确共同导航锚点；不能只用CSS藏掉后让大纲丢失定位。
- 正文行宽使用共享阅读宽度token；宽窗不无限拉长，窄窗使用可用主区。具体字号/行高/留白由双主题实机样本校准，不以单一字数作为内容删改依据。
- 必要定义/条件在主干，补充推导/延伸案例可折叠；不是全部短段化或全部折叠。

### 3.4 旧课程更新与最低读取保障

用户已明确：旧课程的内容/结构适配交给对应学习会话，在最终方案确认和能力到位后由提示词分发、通过CLI原位更新。本轮不为旧排版长期保留两套前端，也不替学习会话重写真实课程。

软件只保留最低安全读取保障：已有轮次/块/题ID、顺序和已保存内容不会因显示壳变化丢失。纯CSS不冒充正文修订；改正文/小节结构仍走既有preview/apply。已开始轮次不静默替换冻结题面，更新回执要区分新课程版本与当前轮次。这里是保存和版本安全，不是额外的老版主题/组件维护专项。

## 4. 块内小节折叠：可控，而非通用排版语言

### 4.1 最小数据扩展

建议在新的课程包 **/5（1.8.0已实现，须实际安装能力发现）** 中，为concept增加结构化sections，与原body二选一。/5统一包含既有普通、英语、details和progression能力，不另建英语专用第六套数据格式。

以下是现行/5的小节片段，完整包仍须带schema/course/lessons等字段并通过validate：

```json
{
  "id": "instruction-cycle",
  "type": "concept",
  "title": "指令的执行过程",
  "sections": [
    {"id": "core", "title": "基本过程", "role": "main", "body": "必要定义、基本过程与可见条件。"},
    {"id": "extension", "title": "进一步理解", "role": "supplement", "summary": "这个补充解释哪一个边界问题。", "body": "完整补充解释。"}
  ]
}
```

- section由稳定id、title、role、body和可选子小节组成；supplement必须有summary。
- 主干role=main始终常显；supplement简述常显、正文可展开。未知role和字段拒绝。
- 首版最多两层section（小节/子小节），只限定文档内部复杂度，不改变计划/课程/知识点导航。需要第三层时先审教学结构，不无限递归。
- sectionID在所属块内唯一（含子小节）；首版每块最多40个section、深度最多两层，所有摘要/正文合计沿用既有concept的20000字符上限，避免递归结构绕过原内容预算。
- 仅concept首次扩展sections；example/comparison等维持原受控字段，避免所有块一次增加递归能力。
- 必要定义、先修、求解条件不能因为作者选了supplement就自动视为合理；语义审核仍要阻止不当隐藏。

### 4.2 操作与引用

1. 折叠按钮明确显示标题/摘要、展开状态，键盘可达；使用原生details或等价button语义，Enter/Space可操作。
2. 每小节锚点由知识点ID + 块ID + sectionID确定，不能根据易变标题生成唯一身份。
3. 左栏本节大纲点击折叠内容时先展开祖先小节，再定位并保留可见焦点；搜索/笔记来源回跳也使用同一revealing入口。
4. 手动展开偏好按工作区、冻结内容哈希、块/sectionID隔离，仅本机展示偏好；不写学习完成状态。
5. 主窗/工具窗来源定位依赖冻结文本和锚点；已有引用继续兼容旧块锚点。新引用可带sectionID，不能因显示去卡片化改变原文含义或位置。
6. 不把引用定位所需原文放入默认不会加载的网络内容；展开无外部依赖，不触发“已学习”或自动提交。

### 4.3 失败与回退

未知包/5能力的旧程序拒绝写入，Agent停在草稿，不悄悄丢字段。需要兼容旧程序时明确生成线性body + 已支持的独立details回退稿；报告小节折叠不可用，不能称完全等效。

## 5. 本地批改参考：按用途组织，不做公开/私有权限系统

### 5.1 对上一版术语的纠正

本软件是单人、本地桌面应用，所有题目、参考、答案和笔记都属于用户本地数据。上一版“公开/私有”“权限读取”的表述过重，容易被理解为平台账户机制；本版删除该设计，不引入登录、角色授权、秘密材料目录或独立参考权限。

需要解决的是教学问题：题干在作答前展示完整求解条件；参考答案不要混进requirements，让学习者未思考就被答案引导。参考供外部Agent批改，也可由用户主动查看。查看参考属于有提示学习，不应自动当作独立掌握证据；不做题目上的繁琐状态栏，更不是防作弊平台。

### 5.2 一个制课包，三种用途

- **题干/作答要求**：学习页面正常显示，包含完整条件和交付要求。
- **review_reference（/5已实现）**：作者在同一课程包中附带参考结果、合格依据、可接受方案与出处；不再要求一套“公开包+私有sidecar”。使用/5且发现相应能力后可写该字段；旧协议仍拒绝未知字段。
- **反馈/解析**：Agent根据用户实际作答编写修正说明，不机械复制整份参考。

软件按调用/页面用途返回所需内容，而不是按账户分权：普通阅读/作答页默认不加载整份参考，制课/批改CLI可明确读取，用户可查看和导出自己的完整材料。DTO裁剪用于减少干扰和数据量，不声称构成安全访问控制。

英语即时训练继续使用已有target/accepted_answers和冻结检查器，不强行搬走其必要数据；额外Agent评判说明可沿用本地参考结构。

### 5.3 数据与版本

参考在本地保存不可变版本，并关联课程内容版本、知识点/题的稳定ID与题面指纹；可与正文分表，但仅为版本治理，不是公开/私有分区。

- 课程内容版本取Course.version/content_revision；学习轮次revision是轮次序号，不能混用。
- 完整作者包哈希、阅读/作答内容哈希、冻结轮次快照哈希用途不同，不直接比较为同一个值。
- 题面指纹按规范化原始题干/要求/类型及必要英语规格计算，不能只看题ID或易变HTML。
- 首次发布先用package_id定位，成功后关联真实course_id与内容版本；学习内容和对应参考一起验证/关联。
- 正文改变而未修订参考时，只有题面指纹一致的旧参考可明确沿用；变化题面不得默默套旧答案。缺参考要报告，旧课不会因此无法阅读。
- 参考更正追加版本，不改题面/用户答案、不强制重开轮次；批改旧作答时显式选择适用的更正版并留原因，记录实际依据。

复用现有import/update preview/apply流程，按已采纳方案扩展参考输入/差异预览，不另造独立后台。必要文件先在软件专属暂存目录准备，数据库版本关联在事务内完成，不宣称文件系统和数据库天然一起原子提交。

### 5.4 外部Agent与界面

批改时从选中的作答/冻结题面读取对应参考，不默认全库加载。若所用安装CLI没有参考字段/读取能力，仍按获授权作者文件核对版本，并报告不能自动读取。

用户主动查看参考后，若软件没有可靠的提示使用记录，长期制课Agent应将相关掌握判断标为“提示情况未知”，不能凭一次本地匹配成功猜测无提示通过。反馈链、修改记录和版本治理不需要账号才能成立。

### 5.5 折叠答案解析与错误反馈（用户方向已采纳）

解析应说明参考结果、关键推理/适用条件、常见误解和可接受变体，不是仅显示“标准答案”。

- 作答前默认收起，不占题面；用户可主动打开“答案与解析”。所谓私有/隐藏在这里仅指折叠显示，不涉及账户权限。查看后属于有提示学习。
- 批改指出错误后，显示简短“错在哪里、为什么、怎样改”的反馈；本地检查只定位实际匹配差异，不能自行把差异诊断成语法原因，已有作者解析可查看。完整参考解法仍可折叠，避免一次把整页答案铺开。
- 正确作答也可查看解析，理解原因而非只得到对号；合理等价答案不能因未照抄参考而判错。
- 英语即时纠错继续定位错误词和保留输入，不在未请求时自动填出完整目标句；必要语法/词义解析按当前题面/版本展示。
- 解析内容与本轮题面绑定；当前题未配解析时明确缺失，不能临时生成未经核实的“标准解析”。提示使用仅在数据层记录，前端不增加逐题繁琐状态栏。

## 6. 计划课程实例分组与特殊状态治理

### 6.1 挂载项才是计划内的学习实例

用户已明确计划挂载课程、正常计划课程应学习；默认显示三组：**待学习、已完成、其他**。待学习中卡片可轻量标“未开始/学习中”；这只是计划详情的列表分组，不再加全局导航层或仪表盘。

复用现有PlanCourseItem（plan_line_id + course_id唯一），不要把Course全局status当作所有计划的完成状态。学习记录按冻结计划归属解析；同一材料挂载到不同计划时不得串用完成结果。旧记录归属不清需显式校准，不能猜测。

### 6.2 两类事实，一套显示规则

- **学习事实**：未开始/学习中/本轮学习已提交，来自实际轮次和CLI回执；不是人工整理文档后的判断。
- **管理位置**：正常/其他；其他可记录暂缓、待补资料、已被替代或备用等原因。它不清除原学习事实。
- 正常挂载项按学习事实进入待学习或已完成；其他位置优先进入其他组，恢复后按原事实回到相应组，不重新制造课程/轮次。

“已完成”推荐表示已完成本计划要求的课程学习/本轮提交，不等同所有知识永久掌握。批改待处理、待修正/复测仍在该卡片和必要任务入口显示；不能因此要求整课从头学习或把已保存记录清零。一般临时复习不自动重置已完成；新增必学目标/明确重新纳入待学需有计划决定。

普通/英语都用实际完成/提交契约判断，不能只凭阅读滚到100%。允许跳题的确认行为和已保存答案保护沿用原学习链；批改通过与提交完成分别呈现。

### 6.3 其他组与临时归档

其他承接原“临时归档”的实用部分，而不是再造一个独立课程归档系统：停止新的自动安排，保留课程详情、来源、轮次、草稿、作答、反馈和笔记；已有轮次/批改仍可从卡片进入继续处理。

进入其他必须写清原因，可选复查条件/时间或替代课程ID。移到其他不表示不需要学习，不自动提高计划进度或阶段目标达成；只有明确的目标取消/替代决定才能改变原学习义务。恢复保留原ID、顺序和事实。

### 6.4 最小实现与操作安全

已有PlanCourseItem.status=PLANNED等语义必须先核对；在挂载项中规范/补充组织状态和原因，优先复用既有PlanLine.version与规划写入回执的CAS/幂等保护，必要时才追加挂载项版本；学习事实尽量派生自现有轮次，不复制第二套作答状态机。

计划详情的三组在双主题共享；今日课程以计划卡片聚合正常待学和必须处理的既有反馈，其他组不自动生成新任务但不隐藏未结处理。

## 7. 制课质量优化：从规则说明变成可核对的作者工件

### 7.1 规则分层与单一来源

- Skill入口只保留发现、安全边界和任务路由；共用制课规定教学底线，英语参考规定模式差异，展示参考规定现有组件的正确使用。
- 作者提示词给出具体输入/交付工件，链接规则，不复制几份彼此可能过时的正文。
- 规则发布记录版本、适用能力、已验证样例范围；仓库、公共同步、安装副本分开报告。
- 语义冲突回归仅能捕捉已知过时口径，不声称已自动证明整份规则无矛盾。

本轮已修复入口重复/英语旧口径，仓库Skill2.5.1；外置参考增加版本绑定底线。用户已采纳其余方案方向，但尚未实施对应检查器/软件能力，不能把文档更新冒充已完成。

### 7.2 全计划蓝图与跨课依赖

计划作者工件至少能说明：目标主题、先修来源、课间递进、首次术语定义位置、复习/迁移节点和范围边界。

用稳定目标ID和简单索引即可，不建立复杂知识图谱平台。资料覆盖、课程编写覆盖、检验覆盖和实际掌握分开记录；回顾有理由，不为每课机械加同一复习容器。

### 7.3 五类组织样例，不是五张固定表皮

| 类型 | 正例应示范 | 反例应揭示 |
|---|---|---|
| 概念 | 定义/边界/正反情景/关系检验 | 首次术语未定义，反复贴同义解释，例子只是重述结论 |
| 计算 | 变量/假设/单位、每步依据、独立核验和变式 | 答案数字写进requirements，例题与练习只换编号，忽略位宽/单位 |
| 代码 | 环境/输入输出、执行状态、边界与等价方案 | 只贴代码、未验证却说能运行、用唯一写法批错合理实现 |
| 案例 | 给全业务约束、区分假设、说明取舍与可接受模型 | 凭作者暗藏条件判错，把开放任务变成标准句背诵 |
| 英语 | 已知/新增成分可解释，词义→组合→回顾/迁移按目标选择，变体与token真实相容 | 随机句堆积、多项未知同时加入仍称渐进，把字符串不匹配直接当语法错误 |

样例包括内容、作者对齐表、题目参考、审核理由、实际展示；不是仅供schema通过的极短JSON。语法/技术事实必须有资料核对，合成样例只演示结构，不能替代真实材料审查。

### 7.4 审核判据与发布门槛

| 等级 | 例子 | 处理 |
|---|---|---|
| 阻断 | 关键事实/公式错误、必要先修缺失导致不可理解、缺条件不可解、题面泄漏待求答案、题目/参考错版本、能力/格式不受支持 | 修复并复核后才能发布；不能用总分抵消 |
| 必须解释/建议修订 | 目标和练习偏离、新增难度说不清、明显重复/机械模板、等价答案标准缺失 | 明确影响与依据，内容作者修订或给出合理说明；疑及公平判错时升级为阻断 |
| 展示体验 | 行长/留白、标题层次、过密表格、组件割裂、折叠/导航体验 | 在软件中复核；软件缺陷给开发，不迫使作者改成巨块 |

每条结论记录位置、具体证据、影响、最小修法、验证结果；允许“未核实”，不强行写所有项通过。不搞个人学习积分/排行榜，也不把作者质量压成无根据的百分比分数。

### 7.5 内容检查工具与人工复核

首版只考虑轻量、离线、只读检查：ID/引用/配对、明显答案标签、重复块序列、长段/标题预警、英语token相容、参考版本完整性与孤立题目。

输出预警及定位，不自动删改正文或宣判教学质量。关键词零命中不能证明无泄漏，长度不能证明复杂度，校验通过不能证明语法自然。语义审核和必要来源核对仍由Agent/人工承担。

多个Agent可做独立复核，但必须有用户/宿主授权和统一资源预算；不默认开启子代理、双倍并发或同模型自评就等于独立可信。

### 7.6 真实课程试点与反馈闭环

1. 从已有普通课程选概念、计算、代码、案例各一个代表知识点，同时保留所在课上下文；不是只抽第一页。
2. 首先只读审查，保留原稿/哈希、问题清单与依据，不改真实轮次。
3. 离线生成最小修订小样，在隔离工作区用实际CLI/Vue检查双主题、折叠/大纲/引用/题面。
4. 由用户看软件实际体验；问题归到内容或软件，修正模板/规则后再扩批。
5. 英语先一个词群切片/一课蓝图和渐进训练试点；原料标注、补释义须单独范围和授权，不能从英语功能实施推导全词表授权。
6. 正式扩批前先验一个完整课发布/版本参考链，然后按获授权范围原位修订；不为显示优化清理重建、自动重开或代作答。

## 8. 设计落点与实现差异（具体方法以当前schema为准）

保持模块化单体；复用现有实体/Facade委派，不在CLI或一级目录堆新业务。

## 10. 验收要点

- 阅读：双主题共享正文结构，无重复大仪表和类型徽章；长文/代码/表格/窄窗均可读；不删必要信息。
- 小节：默认闭合仍能理解主干，大纲/引用可自动展开定位，稳定ID与冻结偏好正确；旧课程无需强制迁移。
- 参考：题目与作者参考用途清晰，用户可访问全部本地材料；作答默认不被答案干扰；同ID改题仍匹配正确冻结参考，缺失/错配明确提示，更正留版本和原因。
- 学习链：自动保存/原键重试/修正复测/安全退出不回归；未授权不改变真实轮次。
- 分组：按计划挂载项而非全局材料判断完成；其他不冒充完成，移入/恢复不删历史，已完成但待批改/修正入口不丢。
- 质量：至少存在五类经过解释的样例和反例；检查器明确机器/语义/体验的边界；用户反馈确实回写规则，不以日志数量宣称质量。
