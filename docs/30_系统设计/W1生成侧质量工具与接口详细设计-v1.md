# W1 · 生成侧质量工具与接口详细设计 v1

日期：2026-10-16。性质：供用户审阅的功能设计稿，未实施。上游：[主设计](生成侧质量闭环与主题统一设计-v1.md)§2—§5、§4.2结论分类、§4.1报告绑定。本稿只覆盖功能契约：命令/参数、报告结构、规则与分类、兼容与验收判据。

## 1. 目标与非目标

目标：把 `skills/studyflow-agent/scripts/authoring_quality.py` 的确定性检查升级为可被发现、结论分类明确、绑定内容hash的单一质量检查实现，供作者在发布前获得结构错误、风险候选、角色实际词段、教学链与变体清单，并在发布后核对学习者实际读源。

非目标：机器语义/语法判定（结论一律区分"确定性错误"与"需人工复核候选"）；自动修改课程；访问真实学习作答数据；把作者审查结论渲染进学习页面；新增账号/审批/签名。

## 2. 单一实现与入口

```text
Core 模块（唯一规则实现）
  ├─ CLI：studyflow course quality-check（作者主入口，只读）
  └─ Skill 脚本 authoring_quality.py（薄代理，转发到CLI；无CLI时明确报错，不再内置第二份规则）
```

- Core 落点：[Core质量模块](../../packages/core/src/studyflow/modules/courses/authoring_quality/)（`rules.py`+`report.py`+`chains.py`），`courses` 业务模块内两级职责；规则实现逐条从现脚本迁移，行为不变（见§7）。
- CLI 只读边界：不初始化/升级数据库、不建租约、不写文件；与 `validate-package` 同类（`fail(exc, read_only=True)`）。仅当显式传入 `--course`（见§6）时以只读运行时读取工作区。
- 能力发现：`studyflow capabilities` 的 CLI 清单新增 `course quality-check`（kind=read）。不新增 Engine 方法：作者=外部Agent走CLI；学习页面不展示作者审查结论（主设计§3.3），当前无前端消费方；后续如需再按现有注册方式扩展。
- Skill 侧 [呈现规则](../../skills/studyflow-agent/references/authoring-presentation.md) 的调用说明改为 CLI 命令；`RULE_VERSION` 升为 `authoring-quality/4`，报告schema见§5。

## 3. CLI 命令契约

```
studyflow course quality-check --file <package.json> [--blueprint b.json]
    [--sources s.json] [--related p.json ...可重复] [--validation-receipt r.json]
    [--rendering-receipt e.json] [--long-section-chars N]
studyflow course readback-check --course <course-id> [--plan-line <id>]
```

| 参数 | 语义 |
|---|---|
| `--file` | 必填，显式整课包路径；UTF-8(-BOM)读取，字节hash即报告绑定的 `package_sha256` |
| `--blueprint` | 目标/教学链蓝图JSON（objectives、teaching_ids、frames） |
| `--sources` | 作者声明来源清单（记录 `source_verification: declared_not_verified`，不访问网络） |
| `--related` | 同模板/同链追查的对照包，可重复；输出复用与近似模板候选 |
| `--validation-receipt` | `validate-package` 的结果包成 `{"package_sha256":…,"result":{…}}`，决定 `protocol_validation` |
| `--rendering-receipt` | 实际渲染检查的作者证据（同构绑定），进入发布关口槽位 |
| `--long-section-chars` | 阈值，正整数，默认400 |

错误码沿用 `DomainError` 体系：`DOCUMENT_UNREADABLE`（读不了包）、`INVALID_ARGUMENT`（阈值/JSON非法）。`readback-check` 需要 `--course` 存在，否则 `OBJECT_NOT_FOUND`；其运行使用只读运行时（同 `workspace purge-courses --dry-run` 的无租约只读模式）。

## 4. 规则与结论分类

报告 `advisories[]` 每条增加 `classification` 字段，取值即主设计§4.2五类。现有单一 `manual_review_candidate` 拆分如下；新增规则为确定性触发、语义结论仍归人工。

| 规则 | 触发（确定性） | 分类 | 旧/新 |
|---|---|---|---|
| `REFERENCE_MISSING` / `REFERENCE_PLACEHOLDER` / `POSSIBLE_ANSWER_LEAK` | 现行为不变 | review_required（旧schema允许缺失→advisory带理由） | 旧 |
| `DUPLICATE_VARIANT` | 变体归一化后与目标或其他变体重复 | deterministic_error | 旧（分类收紧） |
| `ROLE_POS_CONFLICT_REVIEW` / `FRAGMENT_*` / `WORD_GLOSS_SENSE_REVIEW` / `AUTHOR_PHONETIC_REVIEW` | 现行为不变 | review_required | 旧 |
| `BLUEPRINT_REFERENCE_MISSING` | 蓝图引用不存在的题目/教学块 | deterministic_error | 旧（分类收紧） |
| `UNMAPPED_EXERCISE` | 蓝图存在时，题目未被任何objective引用 | review_required | 新 |
| `MISSING_MAIN_SECTION` | 小节全为 supplement/折叠，无 role=main 主干 | review_required（可解性候选，非语义判定） | 新 |
| `VARIANT_STRUCTURE_CANDIDATE` | 变体与目标仅大小写/标点差异，或token数不同 | review_required（等义候选，不做语义判定） | 新 |
| `ENGLISH_PROMPT_LANGUAGE_REVIEW` | 英语题中文prompt为空或与目标同语 | review_required | 新 |
| `NEAR_TEMPLATE_CANDIDATE` | 与 `--related` 同阶段同token数且共享≥60%token | review_required（同模板追查候选） | 新 |
| `TEACHING_CHAIN_LIST` | 输出每课 MAIN 链的阶段序列与逐项阶段（清单，非判定） | 结构化输出 | 新 |

`blocked` 语义：出现任一 `deterministic_error` 时 `blocked=true`（建议修正后再发布）；仅 review_required/advisory 不阻塞但 `manual_review_required` 列明未闭环项。机器不因零告宣称"内容合格"。

## 5. 报告schema（`studyflow.authoring-quality/2`）

在 v1 字段（metrics、advisories、english_structure_review、unchecked_scope 等）基础上：

| 新字段 | 内容 |
|---|---|
| `conclusion_summary` | 五类各自计数与规则名集合 |
| `capability_config` | `{"rule_version","options":{"long_section_chars":N}}`——报告可复现条件 |
| `semantic_ids` | `{"package_id", "lesson_ids", "exercise_ids"}` |
| `target_hashes` | 每英语题 `{"exercise_id","target_sha256","variants_sha256"}`（目标+全部变体排序序列化后hash） |
| `checked_scope` / `unchecked_scope` | 显式列出（吸收现有散置说明） |
| `publication_gate` | 四槽位：`protocol`（来自validation-receipt绑定结论）、`content`（本报告hash自引用）、`rendering`（来自rendering-receipt，未提供则 `not_provided`）、`writeback`（`readback-check` 的回执，见§6） |

旧报告失效规则：任何回执的 `package_sha256` ≠ 当前包hash → 该槽位 `unbound_receipt`，不得当作通过（沿用现行绑定语义，扩展到全部槽位）。

## 6. 发布回读 `readback-check`

输出：

```json
{"course_id":"…","learning_mode":"…","latest_revision":N,
 "active_round":{"study_session_id":"…","revision":M,"content_hash":"…","abandoned":false}|null,
 "current_capture_hash":"…","readback":"current"|"stale"|"no_active_round",
 "next_action":"…"}
```

- `current`：活动轮冻结hash == 现时capture hash（用户读到的就是最新材料）。
- `stale`：活动轮hash落后（材料更新但轮次未重开——按现行W2语义不应出现于正常流，出现即提示需重新打开课程）。
- `no_active_round`：无活动学习轮（课程待学习，下次打开即最新材料）。
- 纯显示变化与相同内容更新不产生材料hash差异，天然不触发stale（与W2"无变化不重置"一致）。

## 7. 兼容与迁移

- 报告 v2 为超集：v1 消费方读 `advisories[].rule/path/evidence` 不受影响；`classification` 新增字段不破坏旧解析。
- 规则迁移判据：每条旧规则在新实现上对同一输入产出相同 rule/path/evidence（逐条对照回归，差异即迁移缺陷）。
- Skill `authoring_quality.py` 代理化后，[呈现规则](../../skills/studyflow-agent/references/authoring-presentation.md) 调用示例同步为CLI；未安装CLI的环境得到明确错误说明，不再静默降级到内置副本。
- 不改 `validate-package`/`import-package`/`update preview/apply` 现有契约；发布关口只是组合既有回执与新报告，不新增写入路径。

## 8. 验收判据

1. 故意违规fixture：缺参考答案、重复变体、蓝图引用缺失、全supplement小节、中文prompt缺失英语题、近似模板复用——分别命中对应规则与分类；`deterministic_error` 使 `blocked=true`。
2. 合法样本零误杀：现测试所用合成包不产生新告警（除既有已知advisory）。
3. 迁移逐条对照：旧脚本与新实现输出逐字段一致（迁移期双跑对比）。
4. 回执绑定：改包内任一字节后，`protocol_validation`/rendering槽位转 `unbound_receipt`。
5. `readback-check` 三态各自可构造并验证（配合W2测试的封存/新建轮次）。
6. 只读性：quality-check 在无工作区/无库目录下可运行；readback-check 不产生租约、不写任何文件。
