# StudyFlow UI 标准化与主题契约 v2

## 1. 目标

StudyFlow 的主题应改变阅读氛围与视觉表达，而不应改变学习业务的页面骨架。所有官方主题和受控自定义主题都遵守同一套功能区域、滚动边界、键盘焦点和数据生命周期约束。

## 2. 固定页面骨架

桌面学习工作区固定为：

```text
窗口标题栏
└── 固定左侧导航 / 课程大纲
└── 中央阅读区
└── 可选右侧学习工具
    ├── 练习
    └── 笔记
```

- 左侧导航不跟随正文滚动。
- 中央阅读区拥有正文滚动责任。
- 右侧工具栏打开时压缩中央阅读区，不改变左侧栏职责。
- 课程大纲、当前知识点大纲和计划进度不属于右侧工具标签。
- 工具窗口与主窗口共享同一 Core 数据和学习轮次。

## 3. 主题可变与不可变边界

### 3.1 可变内容

- 语义颜色、字体、字重、字号标度；
- 间距密度、圆角、边框和阴影；
- 文档组件的视觉配方；
- 动效强度、操作音色和本地装饰素材；
- 同一组件内部的视觉布局，例如信息先后、留白、强调方式。

### 3.2 不可变内容

- 功能区域数量和语义；
- 练习、笔记、课程大纲的归属；
- scroll owner 与失败恢复路径；
- CLI/API/Engine 契约；
- 学习轮次、答案、批改、修正和复测状态；
- 键盘焦点、ARIA 角色和可操作性。

主题 JSON 不允许包含可执行 CSS、脚本、网络资源或任意模板。展示配置只能取受控枚举和有限数值范围。

## 4. 练习界面契约

后端保留完整的提交生命周期；学习端不在每道题上重复渲染生命周期时间线。题目卡只显示：题号、题型、题干、作答要求、答案输入区、保存状态和导航动作。工具栏顶部显示当前知识点的题量与作答汇总。详细批改、修正和复测记录进入反馈页面或当前题目的可展开反馈区。

## 5. 笔记界面契约

计划笔记仍然是连续的计划级文档，可以关联课程、知识点和正文摘录。右侧工具栏提供紧凑编辑模式；独立工具窗口提供目录、正文和来源信息的宽屏模式。保存、冲突、恢复和导出属于文档级状态，不在每个笔记块上制造重复状态条。

## 6. 主题验收

每个主题必须通过：

1. 固定左栏和中央独立滚动检查；
2. 1440×900、1920×1080 与窄窗口检查；
3. 练习和笔记标签集合检查；
4. 颜色对比度、键盘焦点和 reduced-motion 检查；
5. 无未作用域化主题 CSS 检查；
6. 主题切换不触发 Core 写入、不丢失输入、答案、笔记或阅读位置。

自动化通过只表示工程验证通过，不代替用户的最终视觉验收。
