# 桌面主题设计方向卡 · T01—T10 · v3

- 编制日期：2026-10-05
- 适用波次：`visual-v5`
- 状态：设计方向草案，需由主题主代理按“设计意图表 → 确定性 HTML/CSS → 原型评测”逐方向落实
- 目的：替代 visual-v4 及更早候选的视觉基准，不复用旧候选的布局、颜色或组件结构

## 一、共同设计原则

StudyFlow 是本地个人学习工作台。主题首先要改善以下连续任务：

```text
计划选择 → 课程路径 → 多知识点阅读 → 同轮作答 → 保存/提交 → 反馈 → 修正/复测 → 笔记与退出
```

本卡只定义产品设计方向，不定义具体工程实现。使用它的 Agent 仍需读取目标项目文档、现有 UI 和两个通用 Skill，自行写出设计意图表和实施映射。

所有方向必须：

- 形成至少三项可观察的非颜色差异，其中至少一项是布局、容器或教学组织；
- 先做确定性 HTML/CSS 设计稿，再使用图转代码生成单文件技术原型；
- 正文、题目、笔记和反馈使用正常中文排版；
- 不做营销落地页、巨大仪表盘、重复卡片墙、无意义积分、监控大屏或纯换色皮肤；
- 允许合理合并、拆分、停靠和重排容器，但不能隐藏项目已有核心交互；
- 设计稿文字只用于结构与密度参考，正式文案必须由项目真实数据提供；
- 图片、插图和动效可选，必须有无图、减少动态和失败回退；
- 720×600 或 800×600 至少有一种可用的窄窗口退化方案；
- 设计稿与真实工程的差异、自动验证、人工视觉验收分开记录。

## 二、十个重新制定的主题方向

### T01 · 章节索引

- **核心任务**：长课程中快速定位知识点，并保持连续阅读。
- **结构签名**：侧向章节索引轨 + 连续阅读主面 + 可展开辅助信息列；不是网页侧边栏卡片。
- **教学组织**：定义、对照、步骤、案例和小结形成连续阅读段，知识点编号作为定位锚点。
- **设计意图必须回答**：索引轨如何显示当前点、已学点和待处理点；工具区打开后阅读宽度如何保持可读。
- **禁止偏航**：出版物仿真、杂志首屏、只加书签图标不改变结构。

### T02 · 精密索引

- **核心任务**：低噪声阅读、快速扫描状态和明确下一步。
- **结构签名**：精密顶栏 + 内容分割面 + 紧凑索引条；减少卡片，依靠基线、分割线和密度层次组织内容。
- **教学组织**：表格、步骤和提示使用不同密度的实体表面，不用颜色堆层。
- **设计意图必须回答**：如何让用户同时看到课程位置、当前知识点、草稿状态和可执行动作。
- **禁止偏航**：空白大页面、SaaS 卡片墙、数字仪表盘。

### T03 · 暗域静读

- **核心任务**：低疲劳夜间阅读和专注作答。
- **结构签名**：哑光深色阅读主面 + 低亮导航轨 + 按需进入的作答/笔记抽屉。
- **教学组织**：正文、题目、反馈使用明度和边界层次区分，错误不能只靠红色。
- **设计意图必须回答**：减少动态和高对比时如何保留状态可读性，窄窗时如何转为工作面。
- **禁止偏航**：霓虹 HUD、玻璃拟态、代码雨、整页纯黑。

### T04 · 模块折叠

- **核心任务**：在阅读、作答、笔记和反馈之间切换，同时减少容器冗余。
- **结构签名**：不对称模块布局 + 可折叠工作面；不同任务使用不同的停靠关系，而不是四列固定栅格。
- **教学组织**：当前教学块保持主位，辅助内容进入折叠模块，不把正文切碎。
- **设计意图必须回答**：哪些模块默认显示、哪些按需展开，以及展开后如何保持焦点和滚动位置。
- **禁止偏航**：无意义嵌套容器、终端读数墙、为了不对称而不对称。

### T05 · 海盐层叠

- **核心任务**：清晰区分阅读层、题目层和反馈层，长时间使用不疲劳。
- **结构签名**：浅色实体底 + 少量层叠面 + 横向连续内容组织；层叠用于语义，不用于装饰。
- **教学组织**：知识点标题、正文、例题和总结通过层级与间距组成路径。
- **设计意图必须回答**：层叠面如何不遮挡正文、不造成滚动嵌套，也不依赖透明度表达状态。
- **禁止偏航**：全页玻璃、透明卡片、冷色调色盘式换肤。

### T06 · 边注工坊

- **核心任务**：把易错点、个人笔记和来源提示放在阅读边缘，保持正文连续。
- **结构签名**：正文主列 + 窄边注列 + 按需工具区；边注不是第二篇正文。
- **教学组织**：定义和推导留在正文，提醒、易错点和个人摘录进入边注。
- **设计意图必须回答**：边注如何与滚动定位、当前知识点和笔记来源关联；窄窗如何降级。
- **禁止偏航**：自然风景网页、满屏插图、边注承载全部内容。

### T07 · 修订阶梯

- **核心任务**：让“原答案—问题—修正—复测”成为清晰的连续工作面。
- **结构签名**：反馈/修正优先的阶梯式容器；原答案、批改解释、修正入口和复测入口有明确顺序。
- **教学组织**：错误位置、原因、修正提示和新的题目不能混成一张结果卡。
- **设计意图必须回答**：如何区分原始提交与独立复测，且错误状态不用红绿颜色单独表达。
- **禁止偏航**：整页棕色、警报式错误、复古海报、用积分替代反馈。

### T08 · 推导轨道

- **核心任务**：理解复杂概念的条件、过程、结论和依据。
- **结构签名**：步骤轨道/依据索引 + 中央推导面 + 右侧练习工作面。
- **教学组织**：条件—处理—结论、输入—输出、对照表和步骤块可定位。
- **设计意图必须回答**：步骤导航如何与知识点导航共存，且不伪造知识图谱或新增业务字段。
- **禁止偏航**：赛博连线、监控大屏、满屏网格、假数据流。

### T09 · 双面工程

- **核心任务**：同时阅读中文解释、代码、表格和参数。
- **结构签名**：代码/数据面与解释面成对布局；工具区与解释面共享工作关系。
- **教学组织**：代码—解释、条件—运行结果、参数—含义成对出现；无代码课程自然退化。
- **设计意图必须回答**：中文正文如何保持正常排版，代码如何局部等宽，长表如何滚动而不挤压页面。
- **禁止偏航**：全文等宽、代码雨、黑客霓虹、把代码块做成主角。

### T10 · 键盘焦点

- **核心任务**：键盘优先完成阅读、跳转、作答、笔记、反馈和退出。
- **结构签名**：稳定工作区 + 明确焦点轨 + 低嵌套容器；状态由边界、标签和图标共同表达。
- **教学组织**：七类教学块按职责和层次区分，不依赖色相。
- **设计意图必须回答**：Tab 顺序、焦点可见性、减少动态模式和错误/退出确认如何保持可理解。
- **禁止偏航**：刺眼纯黑白、粗黑框包裹全部内容、极小文字、高密度牺牲可读性。

## 三、每个方向必须先交的设计意图表

每个方向在调用图转代码前必须落盘：

```text
<private-workspace>/visual-v5/design-intent/Txx/design-intent.json
<private-workspace>/visual-v5/design-intent/Txx/design-draft.html
<private-workspace>/visual-v5/design-intent/Txx/design-draft.png
<private-workspace>/visual-v5/design-intent/Txx/设计意图审查报告
```

`设计意图审查报告` 必须回答：

1. 这不是简单换色的三项差异是什么；
2. 哪一项布局/容器/教学组织发生了改变；
3. 哪个具体学习任务因此得到改善；
4. 哪些元素来自项目真实数据，哪些只是视觉占位；
5. 使用生图时哪些内容只作为氛围/插图，不作为几何依据；
6. 设计稿如何在窄窗、无图、减少动态和错误态下退化。

## 四、派发判定

- 设计意图表未通过：不得调用图转代码；
- HTML/CSS 设计稿与意图表几何不一致：不得进入原型生成；
- 图转代码只有改色或产生网页式布局：标记 `rejected-color-only` 或 `rejected-visual-drift`；
- 原型评测通过但没有真实工程映射：只能标记 `prototype-only`；
- 工程适配通过但没有独立验证：只能标记 `adapted-unverified`；
- 用户未查看前不得写 `accepted`、`default` 或“十主题完成”。
