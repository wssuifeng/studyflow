# StudyFlow 模块化结构重构设计

直接上游：[系统架构设计](系统架构设计.md)、[需求规格](../20_需求分析/需求规格说明.md)。

2026-10-01：用户确认“模块化单体 + 整体目录整理”，本设计是已确认方案的实施约束，不新增产品需求。

## 1. 目标与不变量

按业务领域组织 Python Core，按功能组织唯一 Vue UI；保留 Tauri 薄壳、CLI/Engine 共用 Core 的路线。

- app 1.3.0、Engine 协议 1.2、Skill 1.5.0 的外部契约保持兼容。
- 17张表、字段、0001—0005历史迁移及真实用户数据不变。
- 整课作答保持单事务、幂等、逐题父子版本链；不得把一次保存拆成各模块分别提交。
- CLI命令、JSON响应、已有Python入口和已安装桌面软件行为不变。
- 不改真实数据工作区、安装目录、系统环境变量或仓库权限，不自动提交/推送。

## 2. 目录与职责

- `../../apps/desktop/`：唯一Vue前端、Tauri壳、桌面构建与烟测脚本。
- `../../packages/core/`：Python发行包；`../../packages/core/src/studyflow/`采用src布局，只读迁移/兼容Web资源/合成示例归入`../../packages/core/src/studyflow/resources/`并随wheel和冻结Engine发行；测试在`../../packages/core/tests/`。
- `../../skills/`、`./`、`../../scripts/`、`../../.github/`继续各自负责操作知识、工程治理、维护工具与CI。
- 生成依赖和构建缓存不属于业务源码，保持Git忽略；pip临时目录使用系统临时目录。

## 3. Core模块归属

| 业务模块 | 模型归属 | 业务职责 |
|---|---|---|
| planning | PlanLine、Stage、Task、TimeBlock、PlanCourseItem、CourseScheduleItem | 计划、任务、课程顺序和日程 |
| courses | Course、Lesson、Exercise | 课程导入、知识点与练习定义 |
| learning | Submission、LearningProgress、SubmissionWriteReceipt、CourseWriteReceipt | 草稿、提交、修正/复测、阅读、幂等 |
| reviews | ReviewFeedback | 批改、反馈和待处理队列 |
| documents | Document | 文档校验、索引、读取 |
| workspace | ContextSnapshot | 工作区备份恢复与上下文 |

EventLog由共享持久化基础设施管理。模型按模块定义，但共享同一个Base和metadata；启动时显式注册全部模型，字符串关系和外键名不变。

模块内部仅建立实际需要的models/service/repository等文件，不机械复制Java的controller/mapper/impl层。服务通过明确的运行上下文和同一Session合作；禁止模块导入应用Facade。

## 4. 应用与适配器

- application：组合业务服务与跨模块只读视图；AppService作为兼容Facade，只委派，不保留业务SQL。
- interfaces/cli：按命令组拆分Typer注册；共用CLI运行时和统一错误输出。
- interfaces/engine：协议、请求分发、诊断和stdio入口；共用AppService。
- interfaces/web_compat：保留现有FastAPI/Jinja2开发兼容入口，不变成第二套正式UI。
- infrastructure/shared：数据库连接与事务、迁移、事件、诊断、公共错误与标识。

旧`studyflow.services/models/cli/engine/config/db`等导入通过薄兼容入口保留，真实实现只有一份。

## 5. 前端与桌面壳

Vue按app（布局导航）、features（console/plans/courses/learning/reviews/workspace）、shared（API契约与传输、基础反馈、公共样式）组织。组件、相关类型和样式有明确归属，不改变页面行为或引入第二套前端/新路由框架。

Tauri按Engine客户端、工作区/启动发现、invoke命令拆分，lib只做注册与装配。开发发现同步适配新Core路径；打包仍使用同一个Engine资源。

## 6. 迁移与验收

先建立现有行为基线，再拆Core、入口、前端，最后整体迁移路径。同步pyproject、构建脚本、CI、发布白名单、文档与Skill。实际移动使用校验范围后的PowerShell LiteralPath操作；不移动真实数据库。旧虚拟环境不盲目搬迁为新开发环境。

验收：原测试不回退；新增架构/模型注册/入口测试；Vue构建、Engine烟测、Rust检查、文档审计、公开边界检查通过。所有未执行项明确记录，不由工具成功推导用户验收或阶段完成。

## 4. 兼容与资源约束

- `studyflow.cli:app`、`python -m studyflow`、`studyflow.engine`、models/services/db/config 等既有 Python 入口保留，只转到单一实现。
- Base 与 EventLog 属于持久化基础设施；registry 显式注册全部业务模型，不依赖任意导入顺序碰巧建表。
- Wheel 和冻结包包含五个历史迁移及只读 UI 资源；不得把安装包目录、site-packages 或冻结解压目录当作学习数据工作区。
- 兼容 Web 读取包内资源，同时保留工作区模板覆盖入口。显式演示初始化才复制合成 Markdown，已有用户笔记不覆盖。
- 旧 `studyflow_app` 中未迁移的本地环境/运行目录仅为被忽略的私人残留，不是第二份源码，也不自动转换真实数据。
