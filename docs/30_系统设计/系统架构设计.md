# StudyFlow 系统架构设计 · v1.11

直接上游：[需求规格](../20_需求分析/需求规格说明.md)。

```text
学习者 → Vue单一UI → Tauri invoke → Rust薄桥 → Python Engine（UTF-8 JSONL stdio）
外部Agent / 人工 / 脚本 → Typer CLI ──────────────────────→ Python Core
Python Core → SQLAlchemy事务 → SQLite默认 / MySQL可选
            → 工作区Markdown、文档索引、事件和上下文
```

| 边界 | 位置 | 职责 |
|---|---|---|
| 唯一学习UI | apps/desktop/src | 计划、课程、知识点、整课答卷、队列、工作区 |
| 桌面桥 | apps/desktop/src-tauri/src | 窗口、Engine启停、请求关联，不复制业务规则 |
| Core/CLI/Engine | packages/core/src/studyflow | 模型、事务、状态、幂等、路径安全、工作区 |
| 迁移与测试 | packages/core/src/studyflow/resources/migrations、packages/core/tests | schema演进与合成验证 |
| Agent知识 | skills/studyflow-agent | 操作知识、安全约束；不是内置AI运行时 |

Engine协议1.2，标准输出只发协议消息，错误日志使用脱敏diagnostic_id。正式桌面默认SQLite自动管理。

源码、安装目录、数据工作区分离；Agent先核对返回的绝对工作区。合法app-data工作区不要求有软件治理文档，不为此初始化用户数据。

FastAPI/Jinja2只保留开发兼容层；正式路线只有一套Vue前端。

## 模块化实现（2026-10-01）

直接约束：[模块化结构重构设计](模块化结构重构设计.md)，实施证据见[重构实施计划](../40_开发实施/模块化结构重构实施计划.md)。这次改变源码组织，不增加产品边界。

- 六个业务模块拥有 ORM 模型、业务服务及必要的 DTO/查询辅助；不为追求整齐创建空层级。
- `application/facade.py` 保留 AppService 入口，只装配与委派。只读跨模块聚合在 `application/queries.py`，不会进入传输适配器。
- `infrastructure/runtime.py` 提供统一 Session/事务及事件写入；跨模块操作传入同一个 Session，不各自提交。
- CLI 命令组、Engine 协议/分发/stdio、兼容 Web 分离，仍共用一个 Core；旧 Python 导入仅为薄兼容入口。
- Vue 的 app/features/shared 分别负责装配、业务界面和跨功能契约；全局 CSS 按原顺序组合，避免目录重排引起层叠变化。
- Tauri `lib.rs` 只装配；`engine.rs` 管进程，`workspace.rs` 定位源码和运行工作区，`commands.rs` 暴露 invoke。
- 只读资源随 Python 包发行；可写学习工作区、安装目录和源码不是同一个目录。


## 连续学习流程

按[学习与作答一体化设计](学习与作答一体化设计.md)调整唯一Vue课程工作区：正文、对应练习与反馈同屏，知识点导航先保存草稿，最后统一提交。`learning/study_sessions.py`持有固定上下文与本轮状态；`useCourseAnswers.ts`管理整课答案、恢复和串行写入。控制台与计划页按学习提交推进，不把待批改课程作为唯一下一步。


## 学习工具与窗口（2026-10-02增量）

`learning/notes.py`承载私人知识点草稿；`useStudyNotes.ts`与`useSafeStudyExit.ts`分别管理持久化恢复和安全离开。CourseReader保持唯一学习页，CourseToolsSidebar提供练习/草稿/大纲。Tauri的`open_study_window`只创建同应用路线，复用AppHandle中的EngineState；置顶、拖动、缩放和关闭属于原生壳，不复制业务服务。

## 计划笔记与可停靠工具增量（2026-10-02，用户确认）

- 默认学习笔记属于计划，跨课程连续查看；课程/知识点只是块关联和筛选。旧随手草稿原文保留，用户显式复制，不静默迁移或删除。
- 正文选文可以记入计划笔记，摘录保存课程、知识点、冻结轮次、标题与内容hash；正文只做临时视觉标记，不改原材料和冻结快照。
- 练习、笔记、大纲使用同一组Vue工具组件。标签可关闭/重开、重排、拖宽、展开、最多双窗格；不足宽度拒绝分屏，窄屏降级覆盖，收起零占宽。
- 标签拆出是真正Tauri OS窗口，不复制完整CourseReader。每种工具最多一个独立窗；默认跟随主窗所选课程，但可独立浏览该课全部知识点。
- 独立窗不调用study-open，不产生新轮次。练习共享主窗冻结study_id和答案；主窗整课提交前请求所有工具保存并暂停编辑，完成后刷新/释放。拆出时主侧栏只显示放回/聚焦入口，避免两个编辑器双写。
- 主窗退出汇合工具保存；失败/超时提供返回、重试、导出和明确不保存退出。主窗关闭级联关闭工具，失焦和主窗最小化不主动关闭工具。原生层级、拖动、多显示器和安装体验仍需用户复验。
- 无新框架、无第二套前端、无内置AI API。布局/窗口几何只保存视图信息，不保存真实答案。

## 1.7.0增量（SF-01—12）

唯一Vue/Tauri薄桥/Python Core/CLI边界不变。Engine与CLI以同一冻结发行文件的两个名称交付；Agent调用新方法经过Schema再委派业务模块，不在Tauri/CLI/Engine复制SQL规则。reviews拥有RetestTask、courses拥有CourseRevision、learning拥有答案链/笔记、planning拥有计划编辑；application做跨模块只读聚合。

运行时共享工作区租约与单事务，维护独占租约。Engine读/写线程和RPC截止时间隔离挂起/晚响应，停止不可信传输；不能把超时直接解释为事务失败。UI变更token有界刷新，不自动重载有输入的编辑器。原生工具窗仍共享同轮/计划笔记，不新建轮次。

课程材料通过受控组件渲染，旧Markdown只为兼容；反馈旧轮次、笔记来源均只读冻结快照。完整契约见[接口](接口与CLI契约.md)与[数据](数据模型与持久化设计.md)，实现证据见[交付记录](../40_开发实施/2026-10-03-SF-01-12实施交付记录.md)。

## 主题专项增量（2026-10-03，共享运行基础已实现）

按[主题与交互契约](前端主题与交互契约.md)在唯一Vue前端加入受控配置/语义tokens/展示预设及应用级外观同步。主题不拥有课程/答案/笔记/轮次，不复制业务renderer、不增加后端服务或Redis；原CLI课程包与CSP边界保持。THEME-BASE已经在`shared/themes/`实现配置校验、三个内置主题、语义颜色、设置页本地导入/导出及偏好/跨窗适配；纯controller不依赖Vue/Core。主题故障降级会话外观，不改变课程/答案/笔记。主代理复用当前底座做10×3候选与后续验收，原生主题专项/安装包不在本轮工程完成结论中。


## 主题布局视觉增量（2026-10-03，设计已修订，代码未开始）

按用户最新决定，唯一Vue工程允许多种纯展示容器/template/CSS/静态资产，统一业务状态所有者不变。不再用“同一前端”禁止布局调整；可信构建期主题registry可选展示view/asset，JSON导入仍是数据。Core/API/学习事务与恢复/窗口协调均锁定，纯展示组件只消费props/slots/已有事件。

新共享呈现接口将独立于编辑器/课程状态生命周期，主题几何变更维护IME/焦点/阅读锚点；必要的纯展示拆分由主代理串行实施。新schema兼容v1和旧40色板；新波次overlay只映射审核展示区域，不任意覆盖业务源码。图片由外部工具生成后本地打包，软件不内置在线生成服务。

详细规格见[布局视觉设计](主题布局与视觉扩展设计.md)；B01—B05尚未实施，不以主题文档改版宣称实际UI已改变。
