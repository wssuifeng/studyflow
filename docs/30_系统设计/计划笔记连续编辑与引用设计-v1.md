## 1. 设计目标与本次变更

### 1.1 目标

个人本地学习笔记：有合理大小的段落卡片，卡内像普通文档一样连续输入；能按实际课程和知识点快速选择；全计划时层级清楚；引用自由编辑、来源按需查看。一个计划仍是一份笔记，范围只决定显示和新增位置，不产生多个笔记本。

普通课程工具只保留练习/笔记，英语只保留笔记。本稿仅调整笔记，序光/白紫、普通/英语、计划笔记页与独立笔记窗共用功能、数据和保存链。

### 1.2 对前一版的明确替换

| 项目 | 前版取舍 | 本版要求 |
|---|---|---|
| 学习中首次打开 | 默认全计划 | **默认当前课程的当前知识点**；缺少知识点上下文才退为当前课程 |
| 位置说明 | 可能用独立文档标题/副标题表达 | **由紧凑选择器表达**；不在正文重复插入“表示与存储 / 第1课·数据表示” |
| 选择范围 | 全计划/本课/本知识点泛化标签 | **全计划或实际课程选择 + 该课程的知识点小列表** |
| 范围内编辑 | 筛选只读，回全文才能编辑 | **知识点、课程、全计划均可直接编辑**；按记录ID提交变更，保护不可见内容 |
| 全计划显示 | 无明显容器分级的连续文档 | **课程 → 知识点 → 段落卡片**，用标题和轻渐变形成层次 |
| 段落外观 | 不再显示卡片 | **保留舒适、自动增高的记录卡片**，不是每一行一个小框 |

用户已经明确了上述方向；下文快捷键、具体几何、数据/接口及选型是为实现方向补齐的设计规则，已随本完整稿获得用户采纳；精细视觉、实现与验收仍需独立证据。前序精修图的轻量工具窗体方向保留，不表示旧编辑原型已满足这些新要求。

### 1.3 不做的内容

完整Word、分页打印、表格/附件/图片笔记、自由字体配色、云协作、AI自动总结、独立笔记库、积分或排行。本轮不操作真实笔记，不同步公共Skill，不打包或发布。

## 2. 术语与数据身份

- **计划笔记（PlanNotebook）**：一个计划的一份长期笔记和版本边界。
- **知识点（Lesson）**：本项目现有课程子单元，不是笔记里的每个自然段。
- **笔记记录/段落卡片（NotebookEntry，拟新增）**：有稳定ID和唯一主要归属的记录单元，可包含多个自然段、列表及多个出处；卡片是显示载体。
- **自然段**：卡内富文本段落，Enter生成；不是一张新卡，也不需要新的管理栏。
- **主要归属**：计划级、某课程级、某知识点级三者之一，决定该记录显示在哪个组；来源是另一种关系。
- **不可变出处（NotebookSource，拟新增）**：经Core核验的冻结定位与原始摘录。
- **引用出现实例**：同一出处在笔记某个文字区域的一次使用，可改写、复制或移动。

同一记录在全计划只出现一次。多个来源不导致同一笔记复制到多个课程/知识点组；引用其他课程的原文也不自动改变这张卡的主要归属。

## 3. 窗体与选择器

### 3.1 共享外壳

复用宿主真实工具标签，子页仅提供安静编辑工具条与紧凑范围选择。子页导航与宿主标签页同宽，不在外层增加框架padding/圆角小窗；内容区单独滚动，顶部选择器始终可达。计划名在需要时以小上下文显示一次，不再占一块大介绍容器。

普通学习侧栏的笔记示意：

```text
笔记                              弹出 · 更多 · 收起
[ 数据表示  ▾ ]   [ 表示与存储  ▾ ]          保存状态
────────────────────────────────────────────
┌ 舒适大小的笔记记录 ──────────────────────┐
│ 自己的理解与轻样式引用……                  │
│ 回车继续写自然段                          │
│ 内容变多后卡片自动长高                    │
└─────────────────────────────────────────┘
```

此处的课程/知识点名字是选择器值，不再在下面插入一个同名大标题、课程副标题或Markdown `##` 段落。作者自己写的小标题可以存在，但不用于自动重复说明当前上下文。

### 3.2 一级：全计划/实际课程

- 一级小列表在当前计划内提供“全计划”和计划下实际课程，按计划课程顺序排列，显示真实课程标题。
- 不继续仅显示抽象的“本课”；当前学习课程可在下拉项中用一个小标记提示，不常驻额外说明行。
- 长列表可搜索课程名，列表在窗口内有最大高度和自身滚动；不是打开另一个页面。
- 当前选择“全计划”时二级知识点列表收起，不让课程和知识点选择互相矛盾。
- 选择某课程后显示二级列表，默认该课程整体；若是首次从学习上下文打开，则直接定位当前知识点。

### 3.3 二级：课程整体/具体知识点

- 二级列表提供“整门课程”和该课程全部实际知识点，按课程顺序排列；不能只列已经有笔记的知识点，否则无法为新知识点开始记录。
- 选择“整门课程”显示本课程随记以及该课程知识点的记录；选择具体知识点只显示该知识点记录。
- 知识点暂时没有笔记也能选择，给出一个可直接输入的空记录位，不生成空知识点文件或假数据。
- 切换一级课程时清除旧课程的知识点选择，不把原知识点ID带到新课程；并明确“整门课程”与知识点的归属校验。
- 支持键盘选择/搜索与焦点返回；按Esc可关闭列表，长标题截断但悬浮/焦点可读全称。
- 极窄窗允许选择器折成两行或一个等价层级弹层，但功能必须一致，不能横向溢出或藏掉知识点选择。

### 3.4 首次打开、跟随与手动浏览

| 入口 | 默认范围 |
|---|---|
| 普通课中打开笔记 | 当前计划 → 当前课程 → 当前知识点 |
| 英语学习中打开笔记 | 有现有Lesson上下文则定位它；无则课程整体，不为每个单词/句子造知识点身份 |
| 从计划笔记页进入 | 没有学习上下文时默认全计划 |
| 从已打开侧栏弹出独立窗 | **保留当前选择、记录、光标与滚动**，不重置范围 |
| 独立窗首次直接打开 | 使用传入学习上下文；缺少时回退课程/全计划 |

首次打开优先当前上下文，不让上一次浏览其他课程的偏好覆盖用户要求的默认行为。打开期间：未手动切范围时，可随同计划的当前知识点变化；手动选择历史课程/全计划后保持选择，不突然切走正在写的内容。此时提供小型“回到当前知识点”动作，不另做说明仪表盘。

同计划知识点变化前结束IME合成/固化当前缓冲，之后再更新投影；不能因为跟随重建编辑面而丢输入。跨计划/工作区切换沿用安全保存与退出协调。主窗和独立窗共享同一笔记身份及编辑权，选择范围不是第二份保存状态。

## 4. 三种范围的内容布局

### 4.1 当前知识点

默认仍定位当前知识点的笔记，内容区也保留课程 → 知识点 → 记录卡片的三级壳，不再退成脱离上下文的扁平卡片。课程与知识点使用紧凑可折叠分组标题，属于导航壳而非用户正文，不插入Markdown大标题或课程路径副标题。初次空态一张可输入记录位，已有笔记按该知识点内顺序显示；不因分组导航扩大默认数据范围。

### 4.2 课程整体

- 使用与当前知识点/全计划相同的课程分组壳；不在正文重复当前课程大标题。
- 课程级笔记显示于“课程随记”组；其后按知识点排列分组。
- 每个知识点标题显示一次，下面是该知识点的记录卡片；不是每张卡片都带同一知识点标题。
- 默认只显示有内容的组；当前知识点可保留空输入位。选择二级列表可进入任一未记录知识点。

### 4.3 全计划

结构固定为：

```text
计划随记（有内容时）
  记录卡片

数据表示                         ← 课程组标题
  课程随记（有内容时）
    记录卡片
  表示与存储                     ← 知识点组标题
    记录卡片
    记录卡片
  编码与校验
    记录卡片

下一门实际课程
  对应知识点
    记录卡片
```

课程/知识点标题属于**分组导航壳**，不是用户正文，不计入复制正文或自动写入笔记；用户选择“复制含分组/导出”才显式输出结构标题。不能通过全选删除把分组标题和课程本身删掉。

### 4.4 层次与渐变

- **课程层**：最外层轻量分组容器，标题较明显；淡渐变或浅色表面形成章节区域，不使用厚边框、大阴影。
- **知识点层**：课程内轻分组，小标题、短分隔或细层级线；尽量不再叠一层完整大卡片。缩进少量，不浪费侧栏宽度。
- **记录层**：可编辑卡片是主要实物表面，比外围层更明确；活动卡只轻强调边界，不突然大幅抬升阴影。
- 引用为卡内文字样式，是更细一级，不再包一张“摘录卡”。
- 渐变用于区分深浅层次，不为每个课程分配不同饱和颜色。序光/白紫共用几何及功能，分别映射课程表面、知识点表面、记录表面、活动边界和引用样式的语义变量。
- 全计划初次展开有内容的组；用户可折叠课程/知识点并记住展开状态。折叠只改变视图，绝不代表删除、不参加保存或丢弃缓冲。搜索可临时展开匹配组，清除后恢复原状态。

## 5. 段落卡片与连续编辑规则

### 5.1 卡片尺寸和滚动

- 卡片初始提供约4—5行舒适输入空间。几何建议：侧栏初始最小高度112px，较宽独立窗128px；这是待视觉验证的起点，可随字体/缩放调整，不是固定长度上限。
- 采用最小高度而非固定高度，输入超出时自然增高；不在1200px处截断，不在卡片内部再套滚动条，也不让字号/DPI增大后遮挡最后一行。
- 只有笔记工作面滚动，工具头/选择器固定。光标进入新一行时只滚动必要距离，不把其他阅读页面一起拉走。
- 已有空白记录和只读记录可以按实际内容收敛，但编辑中的初始空间不得退化成一行小框。不能用巨大placeholder撑高所有卡片。
- 卡片没有常驻编号、逐段保存状态、来源footer或一排管理按钮。更多操作在悬浮/键盘聚焦后的小菜单，移动设备与键盘有等价入口。

### 5.2 卡片与自然段不同

**一张卡片是一段完整记录，可以容纳多个自然段。** 这样既保留用户要求的合理容器，也避免每按一次回车就生成一排小框。

| 操作 | 行为 |
|---|---|
| 点击空笔记/卡内 | 直接输入，不先点添加 |
| Enter | 卡内新自然段；列表中为下一条，空条目再次Enter退出列表 |
| Shift+Enter | 自然段内换行 |
| Ctrl+Enter | 在当前光标处分为下一张同归属记录卡；光标后的内容/引用随新卡移动，末尾则准备空卡 |
| 卡内段首Backspace/段尾Delete | 合并兼容自然段，保留文字/格式/来源 |
| 卡片开头Backspace | 前卡同归属且可兼容时合并两卡，撤销可恢复；不同归属不隐式合并 |
| 跨卡选择、复制/剪切/删除 | 作为同一个文档工作面操作，不要求逐卡点击输入框 |
| Ctrl+Z/Y及Ctrl+Shift+Z | 撤销/重做文字、分卡、合卡、移动和来源操作 |
| 同计划移到另一个课程/知识点 | 明确选择目标，原子改变主要归属/顺序；引用原出处不变 |

仍可在更多菜单提供“新记录/拆分/合并”，但不是必经流程。若编辑器无法稳定实现跨卡选择，不能退回多textarea并宣称连续编辑完成。

自动生成的未填写空卡只是本机占位，不写大量空条目；用户确实编辑或明确保留空记录时才有持久化身份。新记录/拆分/复制生成新ID，合并保留首卡ID并记录被合并内容以供撤销。

### 5.3 轻量排版与输入反馈

首批支持自然段、两级自写小标题、加粗、斜体、行内代码、有序/无序列表及引用标记。格式条按选区出现，常用快捷键和键盘菜单可用，不常驻字体/字号/颜色工具面板。

IME composition期间不重建编辑器、不触发Ctrl+Enter等结构快捷键、不保存半个词；compositionend后补齐缓冲。范围切换/折叠涉及活动输入时，等合成结束再应用。保存回执、浮层和新摘录不抢焦点、不重置选择或滚动。

输入/自动保存不逐键发声；显式操作沿用现有可调音量/静音/Reduced Motion反馈。自动识别外链、任意HTML/图片嵌入不在首批。

## 6. 引用展示、改写与来源

### 6.1 展示

短引用可嵌在自己的句子中，长引用可跨自然段。用细下划线/浅底色等安静样式标识，不常驻来源说明，引用不再强制一个独立blockquote大容器。

悬停约350ms或来源指示键盘聚焦后显示浮层，点击小指示可固定；点击文字本身仅放置光标。浮层可移入操作，Esc关闭并返回焦点。触屏有可点击入口，不能仅靠hover/颜色表达。

浮层简要列出出处课程/知识点、冻结版本简写、原文/片段/已改写、查看原始摘录。完整文字和UID按需展开；查看冻结正文不启动新学习轮次，不把当前卡片主要归属误当引用出处。

### 6.2 不可变出处与可变文字

- 原始摘录和冻结定位由Core核验后保存；不可通过普通编辑改写。
- 当前引用文字是卡内可编辑文档内容，不另外重复存一份current_text。
- 出现实例将文字区间与出处相连，同一出处可使用多次，副本独立编辑。

来源浮层状态由Core依内容派生：与完整摘录相同为“原文”；可明确定位的连续原文子串为“原文片段”；其他编辑/重排为“已改写”，语义是据此整理而非原文原句。只规范Unicode NFC和换行，不忽略标点/大小写来伪装原文。此比较不声称证明思想来源或学术引用真实性。

### 6.3 引用操作

| 动作 | 行为 |
|---|---|
| 引用内部改字/删部分 | 自由编辑，保留出处，重算状态；不因不再匹配原文而保存失败 |
| 引用边界继续写 | 默认自写文字，标记不吞相邻理解 |
| 跨自然段/分卡 | 来源覆盖相应文字；实例跨记录时分配新ID，出处不变 |
| 全删引用 | 正常删除，不留空卡；撤销恢复文字和出处 |
| 合并不同来源文字 | 各区间来源保留，不把全部文字拼成一个假出处 |
| 转为普通笔记 | 去标记，不去文字，可撤销 |
| 恢复原文 | 仅对一个完整引用实例开放；不影响其他文字，可撤销 |

同一文本区间首批只挂一个出处；替换来源需要明确动作。跨自写/多个出处的大范围替换默认普通笔记，不能随意选择第一个出处。一个实例覆盖一个连续区域；编辑切成不连续区域时拆成新实例，比较跨段内容时用段落换行拼接，撤销恢复边界和ID。

### 6.4 从课程正文摘录的目标

“记入笔记”默认归入**来源所在的当前学习知识点**。同归属活动卡有有效光标时插入该处，否则添加该知识点的新卡。跨出处编辑允许，但如果用户正在浏览另一知识点的笔记，不把新摘录悄悄写进那个旧知识点；提供“插入正在编辑的记录”作为明确选择。

侧栏关闭时打开当前知识点；已经手动浏览其他范围时保留它，轻提示并提供“查看新摘录”。独立窗是编辑者时转交同一事件，不让主窗同时再写一次。新摘录可撤销，也不抢走正在输入的焦点。

## 7. 剪切、复制、移动和粘贴

| 场景 | 规则 |
|---|---|
| 同卡/同归属跨卡剪切移动 | 保留受控格式、引用、顺序；不必先另建小输入框 |
| 不同归属间剪切片段 | 插入目标卡，片段来源保留；目标主要归属不变；原卡剩余仍归原处 |
| 完整卡移动到另一知识点/课程 | 显式“移动到”操作，原子更新归属/顺序；若当前筛选不可见，提示目标及撤销，不假装内容丢失 |
| 复制完整/部分引用 | 实际选区复制；新出现实例，共享不可变出处，按内容派生片段/改写 |
| 混合自写与多个引用 | 各自保留标记，不扩大为一整段引用 |
| 同工作区另一计划复制 | Core校验来源后保留出处；目标记录新ID，新主要归属使用明确目标 |
| 跨工作区/无法核验 | 文字保留，退为普通文本并一次提示；不保留假的可信来源 |
| 复制到Word/TXT | 默认正文及基础格式，不强塞footer；另有“复制含来源/含分组” |
| 外部网页/Word粘贴 | 清洗为允许的语义格式；不信任data-*，不加载远程图/执行脚本 |
| Ctrl+Shift+V | 只粘文字，移除来源/格式 |

整卡复制生成新卡ID；同文档有效移动可保留原ID，但重复粘贴不能产生重复ID。剪贴板“cut”标记不是可信移动凭据，只有当前会话有效的移动令牌和匹配片段可确认移动，重复使用退为复制。

应用内结构化剪贴板只带所选片段、必要出处及工作区标识，不带数据库路径/凭据或整篇未选正文。Core仍核验出处，不能靠私有MIME宣称可信。WebView2不支持自定义MIME时必须先保文字；可评估有界会话剪贴板缓存和内容指纹，外部改动/超时/跨工作区不可误认。格式或来源降级需一次轻提示，应用内“移动到”提供不依赖系统剪贴板的可靠入口。

**跨计划首批承诺复制，不承诺跨计划原子剪切。** 目标写入失败不能先删除原笔记；后续真正跨计划移动需同一Core事务、两份CAS与一个幂等键。普通同计划剪切移动不受此限制。

## 8. 所有范围可编辑，保存不覆盖隐藏记录

### 8.1 数据源与投影

统一笔记Controller维护已加载记录、版本基线、本机改动和未确认请求。可见卡片是按范围/展开状态生成的投影，不是完整持久化文档。**切换课程/知识点不创建笔记、不丢本机缓冲、不强制重新读库替换输入。**

一份范围内使用一个结构化编辑面，卡片作为非原子内容节点；分组标题是非正文导航壳。跨卡选区/编辑事务映射回稳定记录ID。课程/知识点分组按归属派生，不把标题存进每个记录的正文或依赖标题文字判断归属。

更换投影不清空计划级撤销历史；撤销涉及不可见记录时仍更新正确记录，并给“查看恢复位置”，不悄悄作用于当前卡。搜索默认查找/定位真实卡，编辑回定位卡而非编辑一个没有ID的复制摘要。

### 8.2 增量命令

拟采用按记录ID的插入、内容替换、删除、移动/重新归属命令；每批带笔记 `expected_version` 和稳定 `idempotency_key`，同事务校验并保存。删除只能删除列明的ID；绝不因为它不在本次可见数组里就删除。

例如在“表示与存储”新增/修改两卡，只提交这两卡的变更；同计划“编码与校验”等隐藏记录、折叠组和未加载分页不参加覆盖。移动验证目标课程/知识点属于当前计划，锚点位于目标组；失败整批回滚。

整份导入是单独受控入口，需完整性标识与版本；不能拿搜索/分页/筛选结果当全文导入。前端、Engine和CLI共用这些规则，不能只在Vue保护隐藏数据。

### 8.3 顺序、关联与空态

每卡一个主要归属，组内有稳定顺序；全计划按计划课程顺序及课程知识点顺序展示。重排/移动用目标记录ID作为顺序锚点，由Core规范化顺序；失效锚点返回冲突，不猜测一个新位置。普通拖动重排不是首批必要项，首批菜单“上移/下移/移动到”与键盘即可，不能重新排序出两个主题不同业务。

全计划新建：有活动卡时继承它的归属；在某组内创建则归该组；无目标时归“计划随记”。课程整体新建默认“课程随记”，进入知识点组/选具体知识点则归它。空全计划/课程只给一个可输入位，不为每个组预造空卡。

卡内自然段分裂不改变主要归属；跨归属合卡必须明确选目标，不自动把一张卡复制挂多个组。课程删除、知识点修订/移除导致原归属失效时，保留记录及冻结标题于“历史课程/知识点笔记”区域，不隐藏、不直接删除，也不擅自重挂到新节点。

## 9. 数据、兼容、CLI与模块

### 9.1 v2模型提案

保持 `PlanNotebook` 的一计划一份身份、版本与回执。持久化建议在现有表新增 `format_version` 与v2规范正文 `document_json`；保留旧 `blocks_json` 作为迁移前兼容资产，迁移后不再允许它成为另一写入源。

`document_json`保存记录集合及规范顺序，`NotebookEntry`是聚合内值对象，**首批不为每卡增加一套独立SQL表、版本和回执**。每记录包含稳定ID、主要归属（PLAN/COURSE/LESSON + 必要ID）、组内顺序、卡内受控文档JSON，以及Core生成的归属标题快照用于历史节点显示。前端可构造单个范围编辑树，但分组投影不是第二套数据库正文。

原始来源用同一持久化Base下的 `PlanNotebookSource` 表，归属笔记主键，来源ID在记录mark中使用；它是来源实体而非第二份笔记。来源记录在一次保存中核验/创建，正文CAS成功后一起提交，回执同时涵盖该批操作。客户端不能写一份新的标题快照来伪造课程归属。

`NotebookSource` 保存经核验的原课程/知识点/冻结轮次、content hash、可选块锚点、原始摘录与冻结标题；引用mark只有出处ID及出现实例ID。当前文字仅存于记录内容，来源状态派生。新出处请求随笔记变更同事务校验创建，已有出处不得由客户端任意改写；跨计划复制显式校验。

已经核验保存的出处不应在每次编辑时依赖仍存活的学习轮次。冻结全文不可用时保留原始摘录、版本及“全文不可用”提示，个人笔记仍可编辑。清理课程前明确物化/保留快照，不能默默制造悬空来源。

### 9.2 旧笔记迁移

v1每个有序NotebookBlock转为一张记录：旧quote转卡内引用，旧text紧随其后，保留文字/顺序/关联/出处，避免把一句原文和理解变成两张不相关卡。必要时依据v1 ID和顺序保留映射，来源不可核验则明确待核验，不假称可信。

迁移前正规备份，隔离验证无损；无法转换则保留旧格式只读/导出，不写残缺v2。旧接口只允许兼容读取；旧blocks全量写不能覆盖v2笔记，应明确拒绝并提示需要新版能力。未知格式不能当空笔记，Markdown/纯文本输出是有损阅读副本而非无损回写来源。

本轮未修改数据库，不复制活动SQLite、不直接SQL。应用版本及迁移编号在实施阶段实际编排，不在设计稿假造已发布版本。

### 9.3 Agent/CLI

沿用现有notebook-get/save/search/export命令路由思路，具体新参数在批准后冻结；不宣称新命令已存在。能力发现给格式与操作支持；读取可按计划/课程/知识点/记录ID分页，返回共同笔记版本、主要归属及来源概要。原始摘录按需展开，不能一次返回无限长期笔记。

写入为上述有界记录命令，严格CAS/原键/原子批次；修改用户笔记需明确授权，不因Agent能写课程而自动整理笔记。参数不完整或来源无效时明确失败，不静默剥离出处。Skill讲清课程层级和笔记归属不同，禁止用自动生成的课程/知识点正文标题代替范围标识；仓库源更新、公共/安装同步要分别举证/授权。

### 9.4 实现路线与模块边界

| 路线 | 取舍 |
|---|---|
| 多textarea卡片 + 临时字符串引用 | 最少依赖，但跨卡选区、撤销、格式及来源容易再次割裂，不推荐 |
| 自行维护contenteditable/DOM | 可做到外观，但IME/选区/粘贴/撤销和引用同步维护成本高，不推荐 |
| **结构化编辑核心 + 可编辑记录节点 + 受控引用mark** | **推荐**；保留卡片视觉，仍有一个范围内连续编辑面，需要明确投影映射与迁移 |

候选为Tiptap Vue 3/ProseMirror的开源核心及必要扩展，不接付费云或协作服务。官方有Vue、自定义节点/mark与JSON能力，见末节；具体依赖版本、非原子记录节点、跨卡选区及WebView2兼容必须实际原型验证，不能把普通NodeView演示当本业务通过。

前端 `features/notes` 按 editor/components/composables/styles 分职责；选择器和分组壳复用，不每种入口自写业务。Core仍属于learning笔记，可在notebook二级职责包内分document/schema、sources、commands、queries/recovery；既有导入入口仅兼容委派，不复制第二套模型/Service。AppService/CLI/Engine装配适配，Tauri只处理窗口和必要剪贴板桥接。

## 10. 保存、恢复与多窗

- 输入停顿850ms后安排自动保存；Ctrl+S请求立即保存。持续输入至少每5秒固化本机恢复快照，IME期间延后至合成结束。卡片不各自显示状态栏，顶部只有一个真实保存状态。
- 请求发送时固定命令负载/版本/键。在途后续输入形成另一份缓冲，旧回执不覆盖新文字、光标、归属或投影；结果未知只重试原键原负载。
- 同计划范围切换无需每次强制保存成功才能看另一知识点；先固化缓冲，后台维持原请求队列。缓存失败时提示导出且不能声称“已保留”，但也不能陷入循环保存或剥夺“不保存退出”。
- 每计划单编辑权；拆窗/回归先处理未确认请求再交接记录、范围、光标/滚动。其他入口只读同步；同一笔记不同筛选也不能同时各自写入。
- Agent等造成CAS冲突时以基线/本机/工作区按记录ID比较。独立改动可合并；同卡编辑/删除冲突、移动/顺序冲突需用户比较选择，不无条件追加近似整篇文档。
- 本机恢复包含卡片内容/归属/顺序、来源描述、基线和未确认请求，不能只存纯文本。恢复先查原请求结果，再补后续缓冲；格式未知/不可读需可导出原始恢复件。
- 不保存退出、导出、重试、继续编辑始终是明确可达的路径；退出不代表撤销已提交事务。已保存成功与本机缓存成功分开，缓存失败不推翻数据库回执。
- 撤销/重做是同计划会话内历史，显式拆分、去来源、移动、恢复原文独立为一次操作；无需承诺跨重启完整撤销历史。
- JSON导出保留结构/来源；Markdown和纯文本可选分组标题/来源说明，必须标明有损格式，导出可包含尚未保存缓冲。

## 11. 状态、性能与验收

### 11.1 必要状态

空知识点直接输入；空课程/全计划只一个起始位；范围正在读取不显示假的空数据；保存失败/结果未知不丢缓冲；记录移动后不在当前范围时明确目标；来源全文不可用仍可看摘录；历史归属失效有保留区；独立窗编辑时本窗只读；窄窗、放大/DPI、静音/减少动画均有可达入口。

### 11.2 安全与性能

只允许受控语义节点/mark，Core验证所有内容、归属、锚点、剪贴板来源及ID，不信任任意HTML/URL/data-*；不加载外部图片或执行脚本。

保持现有总长度100万字符预算，定义明确JSON字节/节点/卡片/出处上限后压力验证；超限保留本机缓冲并明确拒绝，不截断。全计划分页按课程/知识点组加载，已有输入卡不能被虚拟化卸载丢光标；全选/搜索/复制的范围要明确：只覆盖当前已加载编辑内容，整份复制/导出走受控全量读取，不能把“已加载部分”说成“完整计划”。

性能初步目标（待审、未测）：在记录硬件的10万字符合成笔记中，按键可见更新P95≤50ms、粘贴1万字符≤500ms、打开目标知识点可编辑≤1s；100万字符全计划分页、来源多/卡片长和原生DPI另列压力结果。不每键重渲染全计划、不每键全量查出处；如果跨卡编辑/分页不能同时可靠，先调整技术方案，不悄悄缩回多小输入框。
