# StudyFlow 数据模型与持久化设计

直接上游：[需求规格](../20_需求分析/需求规格说明.md)。模型和schema以Core模型与0001—0008迁移为准。

| 聚合 | 模型 | 用途 |
|---|---|---|
| 计划和日程 | PlanLine、Stage、Task、TimeBlock | 计划、阶段任务、时间和证据关联 |
| 顺序课程 | Course、PlanCourseItem、CourseScheduleItem | 课程顺序与当天安排独立 |
| 知识与练习 | Lesson、Exercise | Course一对多Lesson，Lesson一对多Exercise |
| 作答和反馈 | Submission、ReviewFeedback | 原答案、修正/复测、父子版本和反馈 |
| 阅读与幂等 | LearningProgress、SubmissionWriteReceipt、CourseWriteReceipt | 阅读位置、稳定响应回执 |
| 索引与上下文 | Document、ContextSnapshot、EventLog | 相对路径、上下文、变更来源 |

整课写入在一个事务内校验归属、叶子状态、版本和完整性；任何题失败整批回滚。相同幂等键和载荷返回稳定原响应；同键改载荷返回冲突。

草稿 → 待批改 → 通过/待修正/待复测。修正和复测生成新Submission，不覆盖原答案。通过一题不等于整课通过或自动证明掌握。

默认SQLite数据在`.studyflow`，Markdown可读。MySQL从环境变量配置，无完整多租户治理承诺。不复制运行中的SQLite，迁移走一致性快照与清单校验。


## 核心学习链增量（2026-10-01）

0006_course_study新增CourseStudySession（总计18张业务表），冻结本轮知识点正文和题目集合，并保存本轮阅读位置/版本号。Submission增加可空study_session_id和batch_id；CourseWriteReceipt增加可空study_session_id，复用其ID标识提交批次。旧记录关联字段保持NULL，不伪造历史题面快照。

已识别的文件型SQLite旧库首次启动会先做一致性备份再增量升级；新库自动初始化。0001—0005内容不变。MySQL保持可选，升级应显式运行Alembic并备份；本轮未连接或验证真实MySQL。

没有另建多租户、内容发布、审批或积分模型。状态按当前学习轮次的逐题叶子结果汇总，不由滚动阅读百分比证明掌握。


## 学习工具与可靠写入增量（2026-10-02）

0007_learning_tools增加StudyNote与StudyNoteReceipt（总计20张业务表），分别保存冻结学习轮次中的知识点个人草稿及稳定幂等回执。唯一业务键为study_session_id + lesson_id；更新携带expected_version，首次为0。笔记不创建Submission、不进入批改队列、不替代正式答案，清空文本是明确更新。

EventLog是append-only事件记录。移除旧uq_event_signature全局唯一约束，不按source/object/action/summary去重；同一道题或同一笔记可多次记录相同语义的保存事件。业务幂等由各写入回执承担，解除错误的日志去重不解除答案/笔记版本和幂等约束。

SQLite受控升级先备份再迁移，保留旧事件、答案及回执。合成0006旧库升级测试已验证数据保留；没有手工SQL修改正式工作区，也未连接真实MySQL。

## 连续计划笔记增量（0008，2026-10-02）

新增PlanNotebook、PlanNotebookReceipt（总计22张业务表）。PlanNotebook以plan_line_id唯一，保存有序blocks_json和乐观version；读取空计划笔记不创建数据。每块归属计划，可关联课程或知识点；摘录由冻结CourseStudySession验证并保留来源。

整份笔记更新为单事务，expected_version首次0；稳定幂等凭据绑定完整块列表/版本/计划，重复请求返回原响应，冲突不覆盖。笔记不生成Submission、不进入批改队列，不证明学习完成。旧StudyNote/StudyNoteReceipt、原答案、事件和冻结快照完全保留。受控SQLite升级自动做一致性备份；本轮没有运行正式学习库升级，MySQL仅保留兼容契约，未实测。

## 结构化课程内容增量（1.6.0，2026-10-03，无新迁移）

仍使用Course、Lesson、Exercise、Document及CourseStudySession，不新增表或第二套内容库。

1. 课程包按package_id与规范化内容哈希发布到工作区 `content/course-packages/<package_id>/<content_hash>/`。生成文件不可变，Front Matter保存结构块，正文保留线性回退；原始作者包不自动放入公开源码。
2. 全包校验通过后，同一事务登记全部知识点/题目/文档和计划课程关联。发布锁跨进程有效，进程退出释放；登记失败回滚数据库，崩溃可能残留未登记不可变文件，不覆盖既有课程。
3. 同包重放关联原课程；同ID变更或同名旧课拒绝，不能把新包导入解释为通用安全更新。
4. CourseStudySession捕获 `content_blocks` 和题目引用，旧轮次保持原样；旧快照缺块时使用原有Markdown。
5. PlanNotebook摘录块增加可选 `source_block_id` 元数据，通过冻结源验证；连续笔记仍属于计划，答案、笔记、内容发布各自生命周期不混用。


## 完整优化契约（2026-10-03，SF-01—12实施基线）

- 作答仍只使用 Submission。新增后续版本必须对当前父记录做事务内版本CAS；新增唯一父链接用于并发竞争。历史分叉全部保留，标记冲突并禁止继续写入，显式选择有效分支产生审计记录；不自动删除或伪造结果。
- 单题写回执保存请求hash和响应快照。旧回执缺hash时返回 IDEMPOTENCY_UNVERIFIABLE，要求回读，不能假造hash。课程包和整课提交统一最多500题。
- RetestTask归reviews拥有，冻结父答案、学习会话、题面、约束与学习目标；学习答案仍归Submission并绑定任务。评分参考仅在Agent上下文中返回，学习UI不返回。
- CourseRevision归courses拥有；修订保持Course和计划序号，已开启的学习快照不变；显式预检差异和旧版本hash后发布。旧题模型保留，不级联删除答案。
- 队列摘要分页、角色和状态明确，不含答案正文；批改上下文按批按需读取并对学习材料去重。变更revision检查不得自动卸载有输入的编辑器。
- 恢复切换前必须独占工作区维护租约并排斥活动Core请求；同目录恢复由Engine协调，运行中的外部CLI必须遵守租约。备份使用SQLite一致性API。
- Engine请求有截止时间并检查响应ID；超时/断线的写请求是结果未确认，保留原幂等键且不自动重发。

以上为本次获准实施的细化设计，工程完成和用户体验验收分开记录。
