## 1. 结论先行

**保留当前技术栈和模块化单体，不再重写框架。下一阶段重点不是加更多页面，而是让发布、学习、批改、修正、复测、回顾和备份共享一致规则。**

目前已具备可用主干：唯一Vue界面、Tauri原生工具窗、Python Core、CLI、SQLite、冻结学习轮次、整课事务、计划笔记、结构化课程。主要欠账是：新旧写入入口规则不一致、复测缺独立题面生命周期、Agent读取上下文过重、安装端CLI未交付，以及恢复/计划管理/笔记回顾缺可操作界面。

不建议转微服务、改MySQL为强制依赖、再做一套前端、加入在线AI或积分排行榜；这些不能解决当前已复现问题。

### 用户验收更新

用户于本轮明确反馈：**覆盖安装成功，课程成功保留**。这是实际升级与课程可见性证据；不是全部答案/笔记/恢复/多屏/长期学习体验的验收。不再将“未安装”当作当前状态，但保留之前构建时尚未安装的历史记录。

## 3. 当前架构：哪些保留，哪些要收口

```text
外部Agent ─ CLI ─┐
                 ├─ Python Core（业务/状态/幂等/事务）─ SQLite + 内容文件
学习者 ─ Vue ─ Tauri桥 ─ Engine ─┘
                      └─ 原生窗口/进程生命周期
```

| 层/模块 | 当前职责与判断 | 改进方向 |
|---|---|---|
| planning | 计划、顺序关联、排期与任务；关系基本完整 | 补调整顺序/暂停/归档的受控操作与下一步投影，非重建计划模型 |
| courses | 课程/知识点/题目、包校验/导入；已有事务和不可变文件 | 用课程修订替代“新标题新增一课”作为正式更新方案 |
| learning | 学习轮次、整课答案、进度与笔记 | 单一写入规则；所有入口同一当前叶子、同一恢复约定 |
| reviews | 反馈及队列 | 结构化批改问题与复测任务；轻量队列和按需上下文 |
| documents / workspace | 内容索引、快照、备份恢复 | 保留备份引擎；补桌面管理、工作区维护锁与可读错误 |
| application | Facade委派、跨模块查询 | 保持业务规则不回流Facade；拆分重型投影，避免每次导航加载全部材料 |
| Vue app/features/shared | 一套UI，课程控制器/拆窗可复用 | 清理遗留编辑器，统一安全离开和状态组件，不全量换框架 |
| Tauri/Engine | 原生窗口、进程、stdio | 保持薄桥；补超时、代际隔离、可恢复重启与响应关联验证 |
| CLI / Skill | 已可被外部Agent操作 | 真正随安装分发CLI；契约一致、能力可发现、上下文可裁剪 |

`Runtime.session()`统一提交/回滚、Facade无查询的架构测试都是应保留的优点。文件长或有委派本身不是缺陷；只针对重复业务规则、长耦合和薄弱契约做有证据的拆分。

## 5. 已复现缺陷（先修这些）

### F-01 · P1 · 独立反馈页未提交修正版会丢失；缓存故障会卡忙态

- 证据：[SubmissionFeedback.vue](../../apps/desktop/src/features/reviews/components/SubmissionFeedback.vue#L9)，9—13、28—45及58行。输入只存在ref；点击提交时才写localStorage，没有接入课程页的导航保护。第38—39行先设busy再在try外写缓存。
- 复现：打开一份待修正答案 → 写修正版 → 点“作答与反馈”返回 → 再进入，文本变成空字符串，无确认提示。隔离注入QuotaExceededError后按钮持续禁用显示“提交中”，Console记录错误。
- 影响：正常离开可能损失输入，存储异常缺恢复；不应因为整课页安全就忽略这个入口。
- 处理：历史页改为只读时间线＋“在课程内修正/复测”；旧深链仍能恢复既有临时请求。共享恢复控制器，错误在finally释放忙态。
- 去向：SF-01。

### F-02 · P1 · 同一父答案允许两条并行修正，队列与课程结果不一致

- 证据：[learning/service.py](../../packages/core/src/studyflow/modules/learning/service.py#L99)99—131；[study_sessions.py](../../packages/core/src/studyflow/modules/learning/study_sessions.py#L214)214—232；[reviews/repository.py](../../packages/core/src/studyflow/modules/reviews/repository.py#L11)11—22。
- 复现：对同一NEEDS_REVISION父记录用两个不同幂等键依次提交，生成两个attempt_number相同的子答案；队列列出两个待批改叶子，课程答卷只选其中一个最新答案。不需要并发即可发生。
- 处理：服务端统一“当前有效叶子”校验与并发保护；历史分叉保留，不静默删除，不仅靠禁用按钮。旧链存在分叉时明确提示并受控确认当前有效分支。
- 去向：SF-01，SF-04复测模型沿用这一不变量。

### F-03 · P2 · 单题兼容入口幂等只核对ID，不校验完整载荷

- 证据：[learning/service.py](../../packages/core/src/studyflow/modules/learning/service.py#L139)139—149、157—246；Engine dispatcher仍暴露单题保存/提交。旧submit_answer还允许不同题目同键返回原答案，该入口主要被兼容Web使用，不能说它就是当前整课CLI。
- 复现：save_submission_draft同键从A改为B，返回A；submit_submission同键不同答案亦返回A，不报冲突。整课write_answers已有payload_hash，不能把本缺陷泛化为全部写入。
- 处理：兼容入口委派同一规范化命令与载荷哈希；同键同载荷重放，同键改内容明确冲突。补原有依赖旧行为的测试，不为保绿继续维持不一致。
- 去向：SF-02。

### F-04 · P2 · 导入容量与整课提交容量不一致

- 证据：[content.py](../../packages/core/src/studyflow/modules/courses/content.py#L43)单知识点≤100题、整课≤50知识点但无总题数约束；[course_answers.py](../../packages/core/src/studyflow/modules/learning/course_answers.py#L58)单次答案≤500。
- 复现：501题整课JSON校验、导入、开课均成功；提交501题返回INVALID_ARGUMENT。不能通过拆多次SUBMIT绕过“整课原子提交”。
- 处理：先统一最大500题及一致的错误位置；验证500通过、501导入前拒绝，不留下半课。超大课支持另行决策，不盲目提高所有上限。
- 去向：SF-02。

### F-05 · P2 · Agent队列对每道题重复完整冻结上下文

- 证据：[reviews/service.py](../../packages/core/src/studyflow/modules/reviews/service.py#L20)20—67；[study_sessions.py](../../packages/core/src/studyflow/modules/learning/study_sessions.py#L201)201—210；[App.vue](../../apps/desktop/src/app/App.vue#L49)49—64每次载入请求完整assignment.queue。
- 实测：一个知识点、20道合成待批改题，单份上下文约51,625 bytes，完整队列2,117,455 bytes；相同项同时存在items和waiting_review，既重复正文，又重复数组。
- 影响：Agent上下文浪费，UI队列也加载不需要的正文。这里只测到体积，不宣称已测得启动延迟或卡顿。
- 处理：摘要队列分页，contexts去重/按需获取，保留明确的旧兼容模式；UI和Agent使用面向任务的轻量读接口。
- 去向：SF-05。

### F-06 · P2 · workspace导出成功响应缺少统一ok字段

- 证据：[CLI workspace.py](../../packages/core/src/studyflow/interfaces/cli/commands/workspace.py#L11)11—32直接输出repository返回值；[workspace/repository.py](../../packages/core/src/studyflow/modules/workspace/repository.py#L184)184—195及283处。
- 隔离export确实成功，返回archive_path等信息但没有ok；Skill的统一成功判定要求ok=true。不能误写成备份本身失败。
- 处理：CLI适配层统一成功封装，保留已有字段，明确退出码与错误码；import同查。
- 去向：SF-02。

## 7. 前端交互审核与优化原则

### 不推翻的部分

保留左导航、正文优先、默认收起的应用级右工具区、知识点横向导航和单工具拆窗；不再新增“仪表盘＋今日任务＋主推进”重复容器。现有表格、概念块、案例等继续使用受控组件。

### 值得改的部分

1. **控制台只有一个主要动作。** 每个计划展示当前课程＋当前下一动作；今日安排仅为日期维度，不复制一份课程。按钮按状态叫“开始学习”“继续第N知识点”“修正2题”“查看新反馈”，而不是全部叫继续学习。
2. **反馈以可行动性排序。** 需要我处理的修正/复测优先，等待Agent放次要；历史通过记录单独筛选。进入时定位具体题，不只打开课程第一屏。
3. **历史只读，编辑回课程。** 在原答案、错误原句、原因、正确方向、我的修正版之间建立清晰层次，避免另一页又有一套输入框。
4. **统一视觉令牌。** 实际截图仍有旧紫色课程边框/编号与新青绿主按钮并存；base/theme/workbench和业务CSS重复定义。统一品牌和语义状态色，不是再做一轮全站皮肤重写。
5. **紧凑页面引导。** 控制台/计划/反馈/工作区都有较大的宣传式标题和英文eyebrow；压缩常用页引导，将空间给课程/反馈本身。保留空白，但不以空白取代必要信息。
6. **每种保存状态说真话。** 区分“正在编辑”“仅本机保留”“已写工作区”“待确认”“冲突待处理”；错误要有重试、导出和明确不保存退出，音效仅作可选补充。
7. **学习阅读偏好。** 增加有限字号/行距/阅读宽度设置和一键恢复；这是建议，不是本轮已实现。减少动态效果、键盘焦点和文字状态优先于新动画。
8. **计划笔记既能写也能读。** 编辑和阅读可切换，搜索定位段落，引用跳转冻结版本；仍是一份计划笔记，不另建知识库平台。

本轮浏览器四页1440px检查无整页横向溢出；不是所有尺寸/多屏/系统缩放均已通过。最终学习舒适度由用户体验确认。

## 8. 推荐路线与取舍

| 路线 | 结果 | 选择 |
|---|---|---|
| 只做视觉补丁 | 改善第一眼，但修正丢失、复测和Agent发布仍割裂 | 不单独采用 |
| 保留架构，按完整业务片段收口 | 可逐批验收、保护现有能力，优先解决真实缺陷 | 推荐 |
| 重建前后端/微服务/通用低代码课程平台 | 成本和迁移风险高，偏离本地个人软件目标 | 不采用 |

建议顺序：可靠性 → 批改复测与Agent读写契约 → 独立CLI/安全课程修订 → 备份和计划管理 → 笔记回顾与统一交互 → 回归交付。视觉令牌可较早统一，但不能掩盖未完成的业务链。

## 9. 官方参考入口（本轮未联网核验）

- [Tauri外部二进制](https://v2.tauri.app/develop/sidecar/)：支持把Python等程序随应用交付，不要求学习者安装解释器；采用何种共用发行目录需本项目验证，不直接照抄新依赖。
- [SQLite Online Backup API](https://www.sqlite.org/backup.html)：支持在线一致性数据库快照；不据此宣称目录替换恢复可在已有连接存活时安全执行。
- [W3C状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)与[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)：用可识别文字状态、辅助技术提示和可见焦点验证操作反馈，不以音效/颜色单独表达。
