## 2. 四项优先工作的已采纳设计（原建议保留）

### LC-01：受控折叠详解，不折叠必要知识

推荐独立 `details` 块，不直接开放作者 HTML、不自动折叠全部 concept。供审核的输入为 `id`、`type=details`、`title`、`summary`、`body`：ID 沿用稳定 ID 规则，标题最多 200 字符、简述最多 3,000 字符、详解最多 20,000 字符；均非空。只有一层，不接受嵌套 blocks、脚本、CSS 或自定义组件。

- 标题与简述常显，详解默认收起；先修 concept 策略，再让折叠用于补充推导/解释/案例。核心定义、必要条件、题目要求不得藏在详解里。
- 明确采用新课程包 `/3` 的建议，不静默扩展 `/1`、`/2` 的严格白名单；`/3` 在 `course.learning_mode` 支持既有 `general` / `english`，仍复用同一课程模型。旧包、旧快照不自动改写。CLI capabilities / system.schema 显式公布版本和块类型；旧客户端拒绝不支持的包，不虚称已兼容导入。
- `summary_html`、`body_html` 由 Core 共用消毒链生成；Vue 使用固定组件。可使用语义化 disclosure，但不扩大作者富文本 HTML 白名单。
- 兼容 Markdown / 导出包含简述与完整详解；折叠是显示行为，不是丢弃内容。冻结快照记录结构和版本，当前轮次不自动更新。
- 展开偏好按工作区/冻结内容哈希/块 ID 隔离，仅本地展示偏好；不写学习完成状态，不加数据库展开状态。
- 块和标题锚点可追溯；大纲/来源跳转先展开再定位。开合不丢阅读位置；键盘、可见焦点、ARIA、减少动态效果和两主题共同验证。

用户已采纳契约，实施与证据见 CONTENT-05—09 和末尾记录；仓库 Skill 的功能说明更新不等于 LC-05 的整体制课经验优化。公共/安装副本同步与发布单独授权。

### LC-02：正文默认线性；不凭类型猜作者的教学关系

比较过：①继续自动配对并要求作者规避（否决）；②为每个块引入任意布局参数（首版过重）；③默认单列、保留已有 comparison 的显式对照展示（推荐）。

- `teachingGroups()` 不再将相邻 concept 自动两两组合；顺序、数量、稳定 ID 和来源保持。
- 默认单列适用于旧课程与新课程，两主题及英语讲解入口共用。comparison 等语义组件保留其内部布局，窄窗按共享策略响应。
- 首版不为概念并排新造 schema 字段；确有需求时再单独设计显式分组。不能把“所有内容拼成一大块”写成制课要求来绕过展示缺陷。
- 修改配对相关断言，验证 1/2/3 个连续 concept、不同长度正文、窄窗/两主题/右栏展开，无重排、缺块和横向溢出。

实施落点：[展示分组](../../apps/desktop/src/features/courses/teachingPresentation.ts)、[教学组件](../../apps/desktop/src/features/courses/components/TeachingContent.vue)及教学/主题测试；不顺带执行 LC-06 侧栏重设计。

### LC-03：保留历史的安全重新开始

推荐“**用最新版重新开始（保留历史）**”，不是清理课程/覆盖原轮次，也不是达到某个百分比便自动放弃。仅针对普通课程首版开放；英语训练事件/检查保护未做完前不能借此绕过英语生命周期。

1. 入口提供只读预检查，列出当前轮次、冻结版本、最新版是否可读，以及允许/阻止原因。不依赖 UI 猜测进度。
2. 服务端核验没有题目草稿/提交/批改/修正/复测及关联业务写入；空文本但存在答案记录也不能默认当作无作答。存在英语检查或未知业务关联时保守拒绝。阅读进度和已保存笔记可以存在，重开后仍保留在历史轮次。
3. 主窗口及独立工具窗先走现有 prepare/flush 协调：有未保存输入必须明确保存或放弃；失败/未知写入未回读确认时不得继续，用户取消不改变轮次。软件不能声称能从数据库知道其他窗口尚未提交的输入。
4. 确认页明确旧阅读位置不自动迁移、笔记/来源/历史保留，新轮次读取最新冻结内容。仅一次明确确认，不增加积分或冗余状态栏。
5. 写入采用旧轮次版本 CAS + 最新内容哈希 + 稳定幂等键；在共享事务中记录旧轮次已放弃并建立新冻结轮次。内容捕获/事务失败时旧轮次仍有效，不留下“已结束但新轮次没建好”的半状态。重复确认返回同一新轮次。
6. 旧轮次不可再作答/写进度；迟到写入返回明确关闭/冲突错误。旧答案/笔记不删不迁，历史可读并清楚标示。保存回执、队列、学习统计与恢复查询不能把放弃视为通过。

拟增量需要下一条追加迁移（当前 head 为 0013，不改写旧迁移）、Core 服务/查询、CLI/Engine 路由与 Vue 入口共同评审。预检查/提交的方法名和字段已同步到接口契约；调用前仍须核对运行中 CLI 的 capabilities，旧安装版不自动获得能力。

主要落点：[轮次服务](../../packages/core/src/studyflow/modules/learning/study_sessions.py)、[模型](../../packages/core/src/studyflow/modules/learning/models.py)、application 跨模块事务、迁移/接口、[课程阅读器](../../apps/desktop/src/features/courses/components/CourseReader.vue)。适配器只委派，不在 CLI/Engine 堆业务 SQL。

### LC-04：区分工程文档引用与实际 Agent 接入

**LC-04a 的确认根因：** 审计器将总控和 2026-10-09 记录中的安装/用户路径当作仓库相对产物。将外部位置明确写作 `<install-root>` / `<user-home>` 模板，仓库源改用正确 Markdown 链接；不改审计器，不加忽略。保留当日 Skill 2.0.0 / 12 文件核验历史。

**LC-04b 的受控改进建议：**

- `system.installation` 返回运行时确认的绝对 CLI/Skill/工作区信息及可用标识，由 Engine 负责发现，不让前端猜安装目录。源码态返回真实源码 CLI 调用方式与仓库 Skill 路径，不把“开发模式”当作可执行文件；无需读取 Skill 内容、凭据或改 PATH。
- 设置页加载中/失败/路径不可用时禁用复制，显示可解释原因与重试；就绪后生成分行、便于 Agent 读取的文本，不拼空值、`undefined` 或未经确认的 `~` 路径。
- 工作区以 `system.installation.workspace` 与 `doctor.workspace.root` 核对；仅一方已到达时按返回的实际绝对路径展示，两方不同或切换未完成时拒绝复制旧接入信息。

- 覆盖路径含空格/中文/`.`、安装/开发模式、异步未就绪、doctor 失败、路径缺失、工作区不一致。既有 `local.studyflow.desktop` 和 `studyflow.exe` 不得被拆成额外目录。

- 教学顺序、例题与练习对齐、反馈与复测；
- 标题/段落/对比/强调与信息密度；
- 前端组件布局、版本冻结与操作流程。

抽样覆盖概念、计算、代码、综合案例；保留原稿与修订证据，先试少量代表课，不一口气重写全部课程。软件渲染缺陷由软件修，不能强迫作者改知识结构来规避。

**可借鉴的本地 Skill 类型（只借思路，不机械复制文本）：** 文档 Skill 的标题层级/语义样式/表格列表，PDF 类的渲染验收，mockup-to-page 的真实工程适配与状态验证，skill-creator 的精简入口和渐进披露。Word/PDF 的版面规则要转译成当前 Vue 教学组件，不能引入第二套学习文档界面。

**资产职责：** 仓库 studyflow-agent 的制课入口 + 普通/英语模式专用 references 维护教学规则、好坏对照和质量检查；软件内置提示词保持简洁并指向同一规则源，避免多处拷贝后漂移。CLI 暴露 schema/能力/校验/回执，不充当整套教学经验库。课程专属教材事实和编排写到课程计划，不塞进全局 Skill。
