# W2 · 课程内容更新成功后直接重置学习状态 · 实施与验收记录

日期：2026-10-16。性质：独立克隆工作区W2单元的分项验收报告。工作区：`D:\Test\studyflow`，分支 `codex/quality-theme-unification`，相对本地baseline `56a23d2` 的增量。全部开发与测试使用隔离合成工作区（pytest tmp_path / VM合成引擎），未接触真实课程、真实工作区或安装应用。

## 1. 需求依据与设计差异

- 依据：用户2026-10-16派发更正（《课程更新后重置学习状态》，主工作区 `docs/40_开发实施/2026-10-16-派发更正-课程更新后重置学习状态.md`，非本仓库文件，不设链接）与主设计v1.1 §6（主工作区副本）。**本仓库快照内主设计仍为v1**，其§6的题级影响分类/局部进度复用/答案映射方案按用户决定取消，改为：内容更新成功 → 封存目标课程活动学习轮次 → 下次打开从最新材料重新开始。
- 保留的最小安全边界（与更正一致）：只影响目标课程；笔记保留；更新失败不重置；相同内容更新不重置；幂等重试不重复重置；迟到的旧保存/检查请求不得写入新状态；旧窗口停止旧会话保存并重读课程；移除“请先完成并提交本轮训练（先学完旧材料）”常驻条幅。
- 本轮不实现（取消范围）：题级影响清单、局部进度复用、答案映射、材料热合并、版本切换UI。纯CSS/主题变化不走课程修订发布路径，天然不触发重置。

## 2. Core实现（相对baseline的源码增量）

| 文件 | 变更 |
|---|---|
| `modules/courses/revisions.py` | `apply()` 在同一发布事务内：按学习可见字段（课程标题/摘要/科目/难度 + 全部lessons结构）判定材料是否实际变化；变化时封存该课程全部未封存轮次（`abandoned_at`+版本自增，SQL原子更新），事件与结果字段记录 `learning_state_reset`/`reset_study_sessions`；幂等replay路径在封存前返回，天然不重复重置 |
| `modules/learning/study_sessions.py` | ①`require_study(active)` 拆分封存/被替代两种情况为新错误码 `STUDY_ROUND_SUPERSEDED`（原为通用`VERSION_CONFLICT`）；②`open_study` 复用路径只复用未封存轮次；封存轮跳过轮次政策与“材料未变”拦截直接新建轮次；③新增 `_superseded_round_target`：重放旧 `study-open` 回执（阅读器持久的localStorage键）遇到已封存轮次时，重定向到当前活动轮或按派生键一次性新建重置轮，重试收敛到同一会话 |
| `modules/learning/round_policy.py` | 已封存轮次视为“无进行中学习”，允许开始下一轮（否则课程概览会给出旧的“请先完成本轮”阻断文案） |

未新增数据库迁移：复用既有 `abandoned_at`（0014引入）、`CourseRevision`、`CourseWriteReceipt` 与CAS/幂等机制。历史答案、检查尝试、批改与错题记录继续挂在已封存轮次上，可查询、不计入新轮（现有按 `study_session_id` 归属的机制）。
