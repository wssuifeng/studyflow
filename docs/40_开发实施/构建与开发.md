# 构建与开发

StudyFlow 的 Windows 桌面以 Tauri 承载 Vue，标准输入输出调用本次构建的 Rust Engine。桌面与原生 `studyflow.exe` 共用 Rust Core 和 SQLite，数据根由工作区配置确定。

## 前置条件

Windows x64，Node.js 22、npm、支持当前 Cargo 锁文件的 stable Rust、Visual Studio C++ Build Tools 和 WebView2。Tauri 生成 Windows MSI 时使用 WiX。Python 3 仅用于可选的工程边界检查、WebView2 冒烟驱动及 MSI 载荷核验。

## 调试与合成工作区

以下从仓库根运行。准备测试环境时，在同一 PowerShell 中选择新的工作区并清理继承的数据库路径覆盖。

```powershell
Remove-Item Env:STUDYFLOW_DATABASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:STUDYFLOW_DATABASE_PATH -ErrorAction SilentlyContinue
$env:STUDYFLOW_WORKSPACE = Join-Path $env:TEMP ('studyflow-demo-' + [guid]::NewGuid())
npm --prefix apps/desktop ci
& ./apps/desktop/scripts/build-engine.ps1 -Profile debug -BuildOnly
$cargo = cargo metadata --locked --format-version 1 --no-deps | ConvertFrom-Json
$cli = Join-Path $cargo.target_directory 'debug/studyflow.exe'
& $cli init
& $cli doctor --format json
npm --prefix apps/desktop run tauri -- dev
```

环境变量 `STUDYFLOW_ENGINE_PATH` 仅是调试进程定位选项。生产桌面按当前应用资源定位和校验 Engine。对 CLI 和桌面使用同一工作区配置；SQL 操作经命令和共享工作区租约执行。

## 测试

```powershell
cargo fmt --all -- --check
cargo test --locked -p studyflow-core -p studyflow-runtime
npm --prefix apps/desktop run theme:lint
npm --prefix apps/desktop run test:learning
npm --prefix apps/desktop run test:themes
npm --prefix apps/desktop run test:english
npm --prefix apps/desktop run build
python -X utf8 scripts/check_publish_boundary.py --worktree
```

桌面原生测试使用实际 WebView2。测试机可以安装 `playwright`、`psutil`，并使用显式合成目录。现行驱动见 [verify-rust-desktop.ps1](../../apps/desktop/scripts/verify-rust-desktop.ps1)。

```powershell
npm --prefix apps/desktop run tauri -- build --no-bundle
cargo test --locked -p studyflow-desktop --release --lib
$cargo = cargo metadata --locked --format-version 1 --no-deps | ConvertFrom-Json
$desktop = Join-Path $cargo.target_directory 'release/studyflow-desktop.exe'
$fixture = Join-Path $env:TEMP ('studyflow-native-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $fixture | Out-Null
& ./apps/desktop/scripts/verify-rust-desktop.ps1 -Mode BuildTree -DesktopPath $desktop -WorkspacePath $fixture -ExerciseBusinessFlows
```

测试版首次启动、课程闭环、原生窗口与真正安装升级各有单独回执。偏好/截图/合成状态保存在忽略的测试或临时目录。

## Windows MSI 候选

```powershell
npm --prefix apps/desktop run tauri -- build --bundles msi --no-sign
$cargo = cargo metadata --locked --format-version 1 --no-deps | ConvertFrom-Json
Get-ChildItem -LiteralPath (Join-Path $cargo.target_directory 'release/bundle/msi') -Filter '*.msi'
```

`beforeBuildCommand` 调用 `build-engine.ps1`，从 Cargo 回执准备 CLI、Engine 和仓库 Skill，核对资源哈希后替换生成目录。核验 MSI 时从同一次 Cargo 构建读取 release EXE，解包比对载荷，记录签名、版本、SHA-256、ProductCode 和 UpgradeCode。`verify-rust-desktop.ps1 -Mode Installed` 还要求实际注册的 `-ProductCode`，应在独立 VM 用安装的快捷方式目标复跑。步骤与验收边界见 [Rust 迁移计划](2026-11-21-全Rust后端替换实施计划.md)。

旧 Python 后端的恢复文件和退役映射见 [历史索引](../archive/python-runtime-20261121/INDEX.md)。
