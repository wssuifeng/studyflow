# StudyFlow 构建与开发

直接上游：[架构](../30_系统设计/系统架构设计.md)。推荐Windows开发与桌面打包。Python3.12+、Node22、Rust stable，以及MSVC C++构建工具、Windows SDK、WebView2；前置条件以Tauri官方为准。

```powershell
# 仓库根
py -3 -m venv packages/core/.venv
$python = Join-Path $PWD 'packages/core/.venv/Scripts/python.exe'
& $python -m pip install -e './packages/core[dev]' 'pyinstaller>=6.10,<7'
npm --prefix apps/desktop ci
& $python -m pytest packages/core/tests
npm --prefix apps/desktop run build
& $python scripts/check_publish_boundary.py --tracked
& ./apps/desktop/scripts/build-engine.ps1
npm --prefix apps/desktop run tauri -- dev
# 正式打包，先完成Engine构建
npm --prefix apps/desktop run tauri -- build
```

新工作树或目录迁移尚未暂存时用`--worktree`（包含非忽略新文件并排除已删除路径）；新导出使用`--all`；提交暂存后与CI用`--tracked`。三者均保留精确子项目白名单，不能代替人工diff检查。

Engine在venv中打包成Tauri资源，exe不进Git。Tauri自动启停Engine，开发模式自动启动Vite。可运行smoke-engine.py检查冻结Engine，其数据仅在忽略的test-results。

1.7.0安装资源包含独立CLI与Skill；外部Agent使用绝对CLI路径，不要求Python/Core开发环境，不修改系统PATH；Windows源码venv解释器若带遗留Low标签，按[运行时诊断](../../skills/studyflow-agent/references/windows-cli-runtime.md)在现有授权内处理，不绕活动沙箱。Skill源在skills/studyflow-agent，复制到Agent公共目录时保留完整结构；修改后更新仓库源及构建生成资源；公共Agent目录需独立授权同步，不自动覆盖。

旧兼容Web仅在需要时从`packages/core`运行`python -m studyflow serve`；不是第二套正式UI。兼容模板与静态样式从包内读取，不要求学习数据工作区复制软件源码。

依赖见pyproject.toml、package-lock.json、Cargo.lock。Tauri官方前置条件：

```text
https://v2.tauri.app/start/prerequisites/
```

## 模块化布局的开发注意事项

- Python 采用 `src` 布局：先 editable 安装，再运行 CLI/测试；不能依赖工作目录碰巧导入源文件。
- CLI 入口仍是 `studyflow.cli:app`，Engine 入口仍是 `studyflow.engine`；普通安装用户不需要修改路径或手动开后端。
- 迁移/模板/样式/合成示例在 `../../packages/core/src/studyflow/resources/`，package-data 随wheel发行；Engine构建显式包含资源文件和业务模块，不打包 bytecode/cache。
- Windows `.venv` 不作可搬迁文件夹使用。创建新环境重新安装；旧本地数据和安装目录不随源码整理移动。
- 当前源码App/Core为1.8.18、Engine协议1.2、仓库Skill与MSI资源为2.9.13；未签名1.8.18 MSI已构建并完成Installer/载荷核验，但未安装或复制维护区。公共Skill为2.9.11；安装目录状态待用户安装后实测。当前构建证据见[1.8.18构建记录](2026-11-01-1.8.18-Agent会话启动指令安装包构建记录.md)，下方版本段落仅作历史参考。
