## 2. 已确认的问题

### P1 · 关闭窗口失败后存在重复释放工具保持请求

文件：`apps/desktop/src/app/App.vue`，窗口关闭处理。

当 `prepareTools('shutdown')` 返回 `ok=false` 时，代码先显式调用 `releaseTools(held.requestId)`；如果用户随后选择取消关闭，`finally` 又会根据仍保留的 `shutdownRequest` 再次释放同一个请求 ID。当前子窗口释放处理具有幂等保护，因此暂未证明会造成数据损坏，但这是不必要的重复生命周期操作，后续若释放协议扩展为计数保持，可能导致状态不一致。

建议：只有在 `held.ok` 时写入 `shutdownRequest`，失败分支释放后立即清空，或统一由 `finally` 负责释放。

### P1 · 普通页面路由切换没有明确重置主内容滚动位置

文件：`apps/desktop/src/app/App.vue`，`readRoute()`。

现在路由切换只更新 `route` 并调用 `load()`，没有把 `.main-content.scrollTop` 重置为 0。用户在计划列表、设置或反馈队列滚动到底部后进入另一个普通页面，可能继承旧滚动位置，表现为“页面打开后不在顶部”。这属于统一工作区滚动标准的功能缺口，尚未通过真实浏览器复测。

建议：仅对普通页面路由切换重置主内容滚动，不触碰课程内部的 `study-material-body` 阅读位置，也不要在主题切换时重置。

### P1 · 队列初始读取上限与侧栏总数存在暂时性不一致

文件：`apps/desktop/src/app/App.vue` 的 `compactQueue()`。

初始状态固定请求 `assignment.summary` 的 `limit:100`，侧栏数量来自全量 `study.today` 的 `queue_counts`。`QueueView` 能通过“加载更多”继续读取，因此不是永久丢失数据；但在首次进入 `/queue` 时，列表只显示前 100 项，数量徽标可能大于当前列表，且分页责任分散在 App 与 QueueView 两层。

建议：让队列页自己拥有分页读取，App 只提供摘要/计数；或者明确把首屏上限、分页游标和“当前已加载数量”作为统一契约。

## 3. 已确认的标准化/维护风险

### P2 · 普通壳层虽然已统一，旧布局规则仍分散存在

当前同时存在：

- `apps/desktop/src/app/styles/shell.css` 的 `sticky` 基础侧栏；
- `apps/desktop/src/app/styles/desktop.css` 的固定宽度和标题栏覆盖；
- `apps/desktop/src/app/styles/workspace.css` 的 `workspace-shell`/`learning-shell` 几何；
- `apps/desktop/src/shared/themes/runtime.css` 的 v2 契约；
- `features/courses/styles/sequence-light.css` 与 `white-violet.css` 的课程侧栏和正文滚动覆盖。

当前加载顺序和选择器优先级使正式主题大部分情况下表现正确，但这不是单一来源标准。后续新增主题或修改 import 顺序，很容易重新出现“普通页面固定、课程页不固定”或正文落入第一列的问题。

建议：将壳层几何集中到 `workspace.css`/`runtime.css`，主题文件只保留颜色、背景、组件视觉和必要的阅读密度，不再各自声明侧栏 position、主窗口 height、主内容 overflow。

### P2 · 序光与白紫课程壳层的滚动实现仍不完全一致

- 序光在课程壳中使用 `main-content: overflow:hidden`，由正文内部滚动；
- 白紫主要依赖课程主内容/正文容器的另一套规则；
- 两套主题对课程侧栏的 `position` 也存在 `relative` 与 `fixed` 的实现差异。

视觉上可以保持侧栏不随正文移动，但行为契约并不统一，后续独立窗口、DPI 或窄窗口调整可能只修到其中一个主题。

建议：明确“主窗口固定壳 + 课程正文唯一滚动容器 + 工具区独立滚动”的标准，再让两个主题只调整外观。

### P2 · 普通页面导航/课程导航缺少真实浏览器回归矩阵

现有静态测试和构建已通过，但当前环境缺少 Playwright 的 `chrome-headless-shell`，本轮无法重新执行真实 DOM 计算。仍需在安装包/WebView2 中验证：

- 1440×900、1920×1080、窄窗口；
- 白紫与序光；
- `/today`、`/plans`、计划详情、`/queue`、`/settings`；
- 页面滚动、主题切换、从列表进入详情后的滚动位置；
- 独立工具窗口和主窗口之间的导航/关闭。

## 4. 低风险但应清理的问题

### P3 · 状态提示存在不可达的重复选择器

`apps/desktop/src/shared/styles/notices.css` 中的 `.focus-shell .main-content:has(.native-tool-window) > .status-banner` 与当前 DOM 不匹配。实际生效的是 `workspace.css` 中针对壳层直接子节点的规则。应删除重复规则，避免后续维护者误判。

### P3 · 白紫样式文件顶部有未主题作用域化的插图默认规则

`white-violet.css` 中 `.theme-reading-artwork`、`.theme-reading-artwork img` 和 `.study-unit-heading:has(.theme-reading-artwork)` 没有白紫选择器前缀。当前 `CourseReader` 只在非序光时挂载插图，所以暂未形成已证实的序光泄漏，但规则边界不严谨。

### P3 · 连接状态和标题栏焦点反馈使用了错误的语义 Token

OCR 指出的几处样式问题经源码核对成立：

- 连接成功点使用 `surface-raised`，不如 `status-success` 清晰；
- 断开点使用 `status-warning-soft`，在浅色背景上对比不足；
- 标题栏聚焦/失焦使用相同的 muted 色，失焦状态不可区分；
- 窗口标记使用 muted 前景叠加品牌底色；
- 关闭按钮 hover 使用 danger-soft 背景但仍使用 muted 前景；
- 工具保存错误指示点使用 danger-soft，而错误文字使用 danger。

这些不会阻断页面功能，但会削弱用户对连接、焦点、保存失败和关闭操作的即时识别。

### P3 · `workspace.css` 重复声明了运行时主题 Token

`workspace.css` 顶部重新声明了 `--sf-*` 和基础语义变量，而 `runtime.css` 在后面又重新声明同名变量。当前以后加载的运行时样式为准，但重复定义会制造“修改了却不生效”的维护错觉，应收敛到一个 Token 来源。
