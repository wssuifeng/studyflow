## 一、本轮做了什么

### B01 · 共享展示契约 v2 + v1 兼容

- 新增 `apps/desktop/src/shared/themes/display.ts`：定义展示包 schema `studyflow.theme-display/1`，包含
  `layout`（rail/tabs/docked/page）、`navigation_width`、`reading_width`、`tools_width`、`reading_shell`、
  `teaching_style`、`note_style`、`type_scale`、`heading_family`、`body_family`、`surface_treatment`、
  `radius`、`elevation`、`outline`、`assets`。
- 解析是**严格**的：未知字段、缺失必填字段、越界数值、超过 4 个素材、非法素材标识、非法比例、
  安全区越界、非法回退色、回退色与画布过近（对比 <1.05，缺图时不可见）一律拒绝。
- `contract.ts` 的 `Theme` 增加 `display`，并对 v1（9 字段）与 v2（10 字段）双兼容：
  旧主题 JSON 不写 `display` 时由 `presentation` 推导默认值，仍然可用。
- 用户导入的 JSON 仍是**纯数据**：它只能说「我要某个标识的素材、什么用途、什么比例」，
  永远不能携带路径、URL 或可执行内容。

### B02 · 可变容器 + 稳定学习状态宿主

- `AppShell.vue`、`CourseReader.vue` 改为通过展示槽位渲染，保留原有 props、插槽与 ref/测量逻辑。
- 学习状态所有者不变：`useCourseAnswers`/`usePlanNotebook`、保存/提交/批改/复测/退出保护与轮次全部冻结未动。
- 新增 `display-loader.ts`：把展示包落到根元素 dataset 与派生 CSS 变量

  `--theme-line-height`/`--theme-heading-font`/`--theme-body-font`/`--theme-body-size`/`--theme-reading-max`）。

在私有候选区（不进公开仓库）：

- `scripts/build-overlay.mjs`：复制当前工作树前端源码到隔离构建树 → 生成**多候选**展示注册表 →
  Vite 真实编译。产出 5 个产物（index.html、1 JS、1 CSS、2 个本地素材）。
  依赖复用 `apps/desktop/node_modules`，不安装、不复制、不做符号链接。
- 构建器逐条拒绝：网络地址、路径逃逸、`@import`、`expression(`、缺 `[data-overlay-name]` 锚点、
  缺 `:focus-visible`、越界/未知槽位、触及冻结文件（`shared/api/`、主题核心、`composables/`）、
  声明素材缺文件、候选主题 ID 与内置主题冲突；并校验候选主题确实出现在构建产物中。
- `scripts/serve-preview.mjs`：独立 loopback origin 服务构建产物，并把 `/api/engine` 代理到
  `preview.py --engine-only`（真实 Core + 纯合成数据）。每个候选集合一个 origin/runtime。
- `scripts/verify_preview.py`：主代理独立验证器（Playwright 真实 Chromium），不采用候选自报结论。
- `scripts/repro-build-proof.py`：两次独立干净构建的产物比对。

## 三、实施中发现并修复的真实缺陷（均为我自己引入或被日志证实）

1. **主题校验器回归**：`check-theme.cjs` 把 `contract.ts` 单独跑在 VM 沙箱里，而 B01 给契约新增了
   `./display` 依赖，导致它直接报 `require is not defined`——所有主题校验失效。
   修复：注入只解析同目录契约模块的最小 `require` 外壳，不暴露 Node 模块系统。
   修复后它立刻抓出三个候选主题的真实对比度问题（`text.muted` 对 `surface.active` 不足 4.5:1），
   以及纸面主题纹理回退色与画布过近。
2. **预览路由 origin 不一致**：`/__preview/info` 把引擎内部路由原样透出，调用方会把页面开到
   引擎端口上，得到**空白页却不报错**。修复：路由统一改写为浏览器可达的预览 origin。
3. **共享构建目录互相覆盖**：多个候选并发构建同一个 `--out` 时，后者会清空并替换前者的产物，
   共享预览莫名只剩一个候选。修复：构建器默认**拒绝**写共享预览目录（需显式 `--allow-shared`），
   并在每次构建前清空自己的输出目录。
4. **残留产物掩盖失败**：Vite 只清自己的 outDir，多次构建后 `dist/assets/` 混入 5 份 JS/CSS，
   使「构建产物里到底有没有这个候选」不可信。修复：输出目录改为**内容寻址**（每次构建写新目录，
   预览自动选最新），共享预览目录由主代理独占、构建器默认拒绝子代理写入。
5. **新基线一度把守卫放宽**（自我修正）：首版新快照的冻结范围只覆盖 `apps/desktop/src` 与
   `packages/core/src` 等，漏掉 Tauri 宿主工程、Core 配置与两份关键文档，等于在这些文件上
   **看不见漂移**。已按旧守卫口径修正为整个 `apps/desktop` 与 `packages/core` 受控范围，
   并把全部公开文件镜像进快照以保持完整性；同时同步 `01-contract` 契约镜像，
   且坚持**把冻结值写进 `input_hashes`**，不把当前 hash 冒充冻结值（旧基线曾在此犯错并已留痕）。
   修正后 `workspace_tools.py verify` 通过、0 错误、0 漂移。
