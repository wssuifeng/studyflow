## 2. 课程覆盖与当前状态重置

### 正常覆盖

`course update-preview` / `course update-apply`以及原有`call --method course.update.*`使用同一Core。保留课程ID、计划绑定与笔记；材料实际改变并成功发布时，同事务封存旧轮次、清理当前进度投影。下次打开读取最新材料；草稿、已提交和待批改不再阻止获授权覆盖。

失败、无变化、纯CSS或同幂等请求重放不重复重置。无变化发布不增加内容revision，避免制造假stale。无轮次的旧作答先建立旧材料边界快照，再重置，不能渗入新学习。

### 升级前存量阻断

新增`course reset-learning`及Engine方法`course.learning.reset.preview/apply`：

```powershell
studyflow course reset-learning --id <course-id> --dry-run --format json
studyflow course reset-learning --id <course-id> --confirm `
  --state-hash <preview.state_hash> --content-hash <preview.content_hash> `
  --idempotency-key <stable-key> --format json
```

预览只读、不取写租约；执行必须明确确认并检查材料/学习状态指纹。预览后若发生新写入，拒绝旧预览并要求重新核对。幂等回放返回原结果，不再次重置。普通和英语桌面的重开入口亦通过显式`reset_current_state`进入同一维护操作，不要求先完成旧材料。

旧答案、训练和笔记不物理抹除：旧轮次作为历史保留，但不回填新一轮答案、不再进入当前批改/修正/复测队列。迟到的旧窗口写入安全拒绝，不污染新状态。原无flag的历史`course.study.restart`守卫仅作兼容，不代表新维护能力仍受“有答案禁止”的限制。

### 彻底删除的兜底

既有`workspace purge-courses`增加可重复`--id`，支持单课/明确课程集合；仍需盘点、验证备份及显式确认。仅明确省略ID才进入全库模式，不为常规修订要求删库重导。**本轮没有调用真实工作区的覆盖、重置或删除。**
