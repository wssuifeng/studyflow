# 主题布局与视觉扩展实施计划 · THEME-VISUAL-B

> 执行代理：按B01—B05依赖顺序实施；主代理可分配明确独立的展示候选，最多5活动子代理，不递归派生。任务使用复选框；**B01/B02尚未实施，B03/B04已有私有部分产物但未完整验收；本文件不宣称正式源码能力已完成**。遵守现行治理，不自动Git提交、推送或安装。计划用精准自然语言和少量接口约定，编码细节由执行代理落实。

**Goal：** 在不改变学习业务接口/状态与真实保存结果的前提下，让主题能够实际改变布局、容器、排版、教学表现和本地背景，而不是十套色板。

**Architecture：** 唯一Vue工程，共享业务与编辑状态。可信源码展示包按构建期registry注册CSS/纯展示Vue/本地资产，运行期只用受控manifest选择；保留v1 JSON兼容。候选在同一新冻结基线的独立overlay预览编写，不碰共享学习实现。

**Tech Stack：** 既有Vue/TypeScript/Vite、Tauri薄桥、Python Core/CLI；不换框架，不加后台/Redis/主题插件商店。

上游：[展示扩展设计](../30_系统设计/主题布局与视觉扩展设计.md)、[主代理提示词](前端主题样式专项-主代理提示词.md)。

- 不动Core/CLI/Engine、shared/api、学习composable的业务语义、真实学习数据、权限/服务、公共Skill、模型配置。
- 先前抽查T01/s02、T04/s03、T09/s04；本轮按报告校准T11—T13与B01—B05，未重审全部源码。40项submitted/构建通过不是视觉验收。
- 既有40色板、原manifest与回执保留；新波次另建visual-v2产物/调度和基线引用，不重写旧完成声明。
- 独立origin/runtime/profile防止跨候选同步；生成图片只含抽象设计提示词，不上传私人课程/答案。
- 阶段仍为开发实施；用户视觉确认、原生/系统DPI、安装发布均单列，不由脚本成功推定。

**Consumes：** 现行v1 JSON、三个基础主题、现有custom偏好与revision同步、用户阅读设置。

**Produces：** 准确v2 schema/规范化适配、受审查CSS/view/asset注册接口、展示数值/推荐值与用户explicit偏好优先级。字段与实际代码同步到主题契约；不将设计示意当已实现API。

- [ ] 先写失败测试：原40色板无需增加字段可解析；自定义主题选择/限额/损坏回退仍成立；非法路径/远程asset/未知view拒绝或明确安全回退；旧阅读值保守保留，不误判默认为用户自愿更改。
- [ ] 实现v1→新规范化对象兼容和v2的数值范围/默认值；色彩语义与已有对比度检查保持。布局参数范围体现最小720×600响应式约束，不能机械认为某字段单独合法就整页可用。
- [ ] 对CSS/view/assets采用构建期registry，不在JSON执行任意CSS/JS，不在主进程动态读取任意资产路径；资源不存在时纯色/基础view可用，学习写入不受影响。
- [ ] 维护同一应用快照与跨窗revision；有输入/IME/未确认保存时切换只影响展示，不能产生Core请求或重key编辑器。

- [ ] 运行test:themes、test:learning和build；增加主题schema/本地资产/兼容测试真实输出。v1旧候选格式记录不冒称新布局通过。
