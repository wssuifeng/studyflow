# 2026-10-07 · 普通工作区壳层统一修复记录

## 1. 用户问题

上一轮修复主要覆盖课程阅读/文档详情页。进入详情页之前的 `/today`、`/plans`、`/plan/:id`、`/queue`、`/settings` 仍可能使用旧的 `sticky` 导航和整页文档滚动，导致普通页面与课程页的固定侧栏、滚动主体和主题切换行为不一致。

## 2. 根因

`AppShell.vue` 只有标题为“课程工作区”时才挂载 `learning-shell`。上一轮固定侧栏和固定视口规则主要以 `learning-shell` 为选择器，普通页面回落到基础 `.app-shell` / `.sidebar { position: sticky }`，主内容也没有独立滚动容器。

## 3. 本轮修改

- `AppShell.vue`：所有非专注主窗口统一增加 `workspace-shell`，课程页继续额外挂载 `learning-shell`。独立工具窗口不增加该类，保留 `focus-shell` 单列行为。
- `workspace.css`：为 `workspace-shell` 增加固定导航、标题栏避让、主内容区独立滚动和 Grid 第 2 列归属。
- `runtime.css`：将主题壳契约 v2 扩展到普通工作区；主题只改变视觉与受控宽度，不得把普通导航恢复为随文档滚动。普通页面侧栏宽度与主题网格列保持一致，课程页继续使用课程工具布局宽度。
- `test-themes.cjs`：回归断言覆盖课程页和普通页的壳层契约。
- `smoke-native-tools.py`：设置页回归改为验证主内容滚动、文档高度不继续撑大、侧栏为 fixed。

## 4. 验证

- `npm --prefix apps/desktop run test:learning`：67/67 通过。
- `npm --prefix apps/desktop run test:themes`：43/43 通过。
- `npm --prefix apps/desktop run build`：通过。
- 本轮未重新安装或提交安装包；Playwright 原生浏览器复测因当前环境缺少 `chrome-headless-shell` 可执行文件未执行，不能把自动化通过写成用户视觉验收。

## 5. 验收边界

工程层已将普通页面与课程页统一到同一主窗口壳层。仍需用户在安装包中手动检查两个正式主题下的 `/today`、`/plans`、计划详情、`/queue`、`/settings`：左栏是否固定、滚动条是否只出现在中间内容区、切换序光/白紫后是否无空白或跳位。
