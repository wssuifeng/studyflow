# StudyFlow 前端主题专项 · visual-v5 主代理提示词

- 编制日期：2026-10-05
- 状态：`prepared-not-dispatched`
- 设计方向：[桌面主题设计方向卡-v3](../30_系统设计/桌面主题设计方向卡-v3.md)
- 前置清理清单：由私有候选区 `archive/2026-10-05-visual-v4-reset/cleanup-manifest.json` 提供
- 通用视觉工具：`screenshot-to-code`、`mockup-to-page`；可选 `imagegen`、`gpt-image-2-style-library`

> 这是 StudyFlow 的项目专属执行提示词。它可以规定 StudyFlow 的业务冻结、候选写域、并发和验收；通用 Skill 本身不承担这些项目约束。

## 1. 确认旧波次清理完成，从零建立 visual-v5
旧 visual-v4、visual-v3 及更早候选和过时指令文档已经按用户授权物理删除，清理记录位于私有候选区的 reset 目录。主代理接手后必须先：

1. 读取 StudyFlow `AGENTS.md`、`docs/00_总控.md`、`docs/40_开发实施/_中控.md`；
2. 读取通用 `screenshot-to-code` 与 `mockup-to-page` Skill，并自行决定本轮具体技术栈与验证方法；
3. 读取私有 `archive/2026-10-05-visual-v4-reset/cleanup-manifest.json` 和清理完成记录，确认状态为用户授权删除完成；
4. 核对 `workspace.json` 与 `task-matrix-visual-v5-prepared.json`，确认 visual-v5 仍是 `prepared-not-dispatched`；
5. 从当前 StudyFlow 正式源码工作树建立全新的 visual-v5 baseline 和真实 `task-matrix-visual-v5.json`，不得复用已删除波次的 baseline、候选、截图或矩阵。

旧主题不再作为新主题输入，也不应尝试恢复。仅可阅读保留的经验/治理文档，提取失败原因和不变量，不复制旧 CSS、布局、插图或组件结构。
旧 T01—T13、s01—s04、visual-v3/v4 候选都不允许作为新主题基座直接换色或微调。它们只能用于历史反例审计。

## 2. visual-v5 的核心工作流

本轮不再采用“子代理直接看图写页面”的方式。每个方向严格按以下链路：

```text
方向卡 v3
  → 主代理设计意图表
  → 主代理确定性 HTML/CSS 设计稿
  → 渲染 PNG 视觉基准
  → 主代理串行调用 screenshot-to-code
  → 变体定量评测与人工筛选
  → 候选子代理使用 mockup-to-page 做工程适配
  → 独立构建、真实 Chromium 和业务回归
```

### 阶段 A：设计源生成

主代理为 T01—T10 分别生成：

```text
visual-v5/design-intent/Txx/design-intent.json
visual-v5/design-intent/Txx/design-draft.html
visual-v5/design-intent/Txx/design-draft.png
visual-v5/design-intent/Txx/intent-review.md
```

### 2.1 主题名称锁定

本轮主题名称采用以下固定名称，不再追加“台”等统一后缀，也不要在执行中自行改名：

| 编号 | 固定名称 |
|---|---|
| T01 | 章节索引 |
| T02 | 精密索引 |
| T03 | 暗域静读 |
| T04 | 模块折叠 |
| T05 | 海盐层叠 |
| T06 | 边注工坊 |
| T07 | 修订阶梯 |
| T08 | 推导轨道 |
| T09 | 双面工程 |
| T10 | 键盘焦点 |

名称只用于方向识别、任务标题、manifest、候选目录说明和用户比较，不代表必须采用固定布局。实际布局仍以对应方向卡的结构签名和本提示词的业务冻结条件为准。
每个方向必须证明：

- 至少三项非颜色差异；
- 至少一项布局、容器或教学组织差异；
- 设计稿几何与设计意图表逐项一致；
- 窄窗、工具展开、错误/保存状态和无图回退已经考虑；
- 设计稿来自 Txx 自己的方向卡，不得凭空编三栏页面。

### 阶段 B：图转代码原型

主代理逐方向调用 `screenshot-to-code`。原始结果只能写入：

```text
visual-v5/scratch/screenshot-to-code/<run-id>/
```

不得直接写入 `candidates/`。

默认优先使用 `html_css`，除非主代理根据具体工程适配需求决定尝试其他真实可用 Stack。单文件 Vue/React CDN 产物只能作为原型，不能直接视为正式工程代码。

每次运行必须有真实 `run-manifest.json`，记录设计图 hash、prompt hash、Stack、变体数、模型、渠道、状态、失败原因和选定变体。

### 阶段 C：主代理筛选

主代理必须同时检查：

- 设计结构是否保留；
- 是否只是换色、换阴影或换圆角；
- 是否偏网页英雄区、营销页或卡片墙；
- 关键区域、正文宽度、工具关系和窄窗是否可用；
- 是否有假按钮、假进度、AI 自编正文或远程依赖；
- 是否满足绝对可读性和核心操作下限。

失败状态使用：

```text
rejected-color-only
rejected-visual-drift
rejected-web-layout
rejected-fake-interaction
rejected-safety
prototype-only
```

### 阶段 D：候选工程适配

只有主代理选定某个原型后，才进入对应候选写域。子代理必须读取 `mockup-to-page` Skill，并先建立：

```text
设计稿区域 → 原型区域 → StudyFlow 真实组件/slot → 真实数据来源 → 适配方式
```

必须保护：

- Core/CLI/Engine/API 与 IPC 契约；
- 答案、草稿、计划级笔记和学习状态所有者；
- 保存、整课提交、批改、修正、独立复测；
- 失败保存后的“不保存并退出”；
- 输入法、焦点、滚动锚点、窗口协调和主题切换。

子代理不得把原型中的中文正文、假状态或业务逻辑复制进产品。

### 阶段 E：独立验证

主代理或独立验证 Agent 统一执行：

- 公开边界与候选写域检查；
- `vue-tsc` / 构建；
- 真实 Chromium 首屏、中段、工具展开、错误态、窄窗；
- 设计稿与实际渲染的区域裁剪对比；
- page errors、failed requests、横向溢出；
- 真实保存、提交、批改、修正、复测和不保存退出；
- 主题切换、无图、静音、减少动态；
- CSS 具体度、宽度来源和容器命中。

“可装载”“工程通过”“接近设计稿”“用户验收”分别记录。

## 3. 共享 Sub2API 并发规则

Sub2API 全局最多 5 个并发，候选子代理和图转代码/生图请求共用该资源池。不得把二者当成两套并发。

### 3.1 资源租约

- 普通候选子代理：按 1 个 worker slot 计；
- screenshot-to-code：按当前后端真实创建的全部变体计；如果未确认，按独占生成租约处理；
- imagegen：按当前渠道真实并发计；无法确认时按独占生成租约处理；
- 任何时刻总租约不得超过 5；
- 不允许 5 个子代理同时各自调用 screenshot-to-code；
- 设计源生成与图转代码阶段，主代理独占生成队列，子代理暂停；
- 原型锁定后，才能派发最多 5 个子代理进行候选适配，适配阶段不得再调用图转代码/生图；
- `--wait-first` 不是后端取消机制，不能用于绕过并发限制；
- 所有派发、生成、重试和关闭都要写入并发账本。

推荐阶段切换：

```text
阶段 A/B：0 个子代理 + 主代理串行生成
阶段 C：0 个子代理 + 主代理筛选
阶段 D：最多 5 个子代理并行适配，禁止生成请求
阶段 E：主代理统一复核
```

- StudyFlow 正式共享展示源码；
- Core、CLI、Engine、API、数据库和业务 composable。

共享展示接口确有缺口时，由主代理串行提出最小变更并记录，不允许子代理越界修改。

## 5. 使用的 Skill

主代理必须实际读取并根据项目请求决定如何组合：

- `screenshot-to-code`：确定性设计稿到单文件视觉原型；
- `mockup-to-page`：原型到 StudyFlow 真实展示层适配；
- `imagegen`：局部插图、纹理或背景；
- `gpt-image-2-style-library`：生图提示词与风格选择知识库。

没有实际调用的 Skill 不得写入已使用清单。图片和设计知识库不能替代设计意图表和确定性 HTML/CSS 设计稿。

## 6. 状态、收口和用户验收

- 旧波次清理完成：`cleaned-user-authorized`；
- 新 baseline 已建立但未派发：`prepared`；
- 设计意图/设计稿阶段：`design-source-ready`；
- 图转代码原型阶段：`prototype-ready` / `prototype-partial`；
- 候选已适配但未独立验证：`adapted-unverified`；
- 已交用户查看：`submitted-for-user-review`；
- 未经用户明确认可，不得写 `accepted`、`default` 或“十主题完成”。

主代理必须更新：

- `task-matrix-visual-v5.json`；
- `workspace.json`；
- 每个方向的设计意图、原型 run manifest、mapping、preserved-behavior 和 verification；
- StudyFlow `docs/00_总控.md`、`docs/40_开发实施/_中控.md`、决策日志和验证记录。

禁止在本轮自动提交、推送、安装、发布或同步公共 Skill，除非另有明确授权。
