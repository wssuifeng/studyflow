## 3. 人工核对后的问题与校准

> 下列内容是补审阶段的候选问题。修复阶段已重新核对当前完整源码；`assignment.summary` 已确认通过 extensions 路由注册，属于假阳性，其余真实问题见[审计修复记录](2026-10-07-前端壳层审计修复记录.md)。

### 已校准为假阳性 · 队列调用 `assignment.summary`

文件：

- `apps/desktop/src/app/App.vue`
- `apps/desktop/src/features/reviews/components/QueueView.vue`
- `packages/core/src/studyflow/interfaces/engine/dispatcher.py`

前端调用的 `assignment.summary` 在 `dispatcher._dispatch()` 中由 `extensions.METHODS` 接管，并委派到 `queue_queries.summary`；安装版烟测也使用该方法。本项由隔离快照缺少 `extensions.py` 造成，已增加 Engine 回归，不修改方法名。

### P1 · 工具窗口“放回侧栏”没有先 flush 当前会话

文件：`apps/desktop/src/features/courses/components/ToolWindow.vue`。

`putBack()` 在确认关闭后直接发送 docking 事件并 `getCurrentWindow().destroy()`，没有调用 `session.flush()`。如果练习答案或笔记存在未提交输入，窗口可能在缓存/异步写入完成前被销毁。应先执行与关闭窗口一致的保存保护/确认流程，成功后再 docking 和销毁。

### P1 · 计划操作的编辑锁取得过晚

文件：`apps/desktop/src/features/plans/components/PlanDetail.vue`。

`mutate()` 在 `await notebook.save()` 之后才设置 `editing.value = true`。两个快速点击会同时通过前置判断，并发发出两个 `plan.edit`，导致重复操作或版本冲突。编辑锁应在第一次同步入口立即取得，预保存失败时再释放。

### P1 · 切换到恢复工作区时，`prepareTools()` 在 try 外部

文件：`apps/desktop/src/features/workspace/components/WorkspaceSettings.vue`。

`switchTo()` 先 await `prepareTools('shutdown')`，然后才进入 `try`。如果准备阶段抛异常，`busy` 不会复位，`releaseTools()` 也不会执行，界面可能永久处于忙状态。应将准备调用纳入统一 try/finally，并只在成功获得有效 request id 后释放。

### P1 · dock 操作存在非 Tauri 异常和并发失败传播

文件：`apps/desktop/src/features/courses/dock/toolWindows.ts`。

- `addDetachedNote()` 与 `openToolWindow()` 没有像 `releaseTools()` 一样先判断 `isTauri()`，且 `listen()` 位于 try 外；浏览器预览或 Tauri API 不可用时可能直接 reject。
- `suspendTools()` 使用裸 `Promise.all`，任意已关闭子窗或单次 `emitTo` 失败都会中断整个 suspend 流程；应采用可明确汇总结果的 `allSettled` 或逐窗处理。

### P1 · dock 自拖放会破坏工具顺序

文件：`apps/desktop/src/features/courses/dock/state.ts`。

`reorderTools(from, to)` 没有处理 `from === to`。先过滤掉 `from` 后再对 `order.indexOf(to)` 使用 `splice(-1, ...)`，会静默改变顺序。需要把同项拖放定义为 no-op。

## 4. 人工核对后保留的 P2/P3 问题

- `apps/desktop/src/features/plans/components/PlanList.vue`：筛选结果为空时仍以原始 `plans.length` 判断空状态，用户会看到无解释的空白；查询未 trim/不区分大小写。
- `apps/desktop/src/features/courses/components/ToolSession.vue`：读取工具索引使用 `detail.study.id`，写入使用 `props.context.studyId`，应统一存储键来源。
- `apps/desktop/src/features/courses/components/ToolWindow.vue`：`subscribe()` 用 `void handler(...)` 丢弃异步 rejection，建议统一报告异常，避免事件处理失败静默发生。
- `apps/desktop/src/features/learning/composables/useSafeStudyExit.ts`：模块级 timer 与并发导航保护需要确认是否可能相互清理；建议将 in-flight promise 与 timer 局部化。
- `apps/desktop/src/features/learning/composables/useStudyNotes.ts`：恢复缓存的 JSON 解析失败会进入统一 failed 状态，建议坏缓存按条隔离并允许用户继续保存。
- `apps/desktop/src/shared/api/engine.ts`：浏览器 fetch 的超时清理点需要覆盖 response body 解析；Tauri `invoke` 路径也应有明确的超时边界。
- `apps/desktop/src/shared/styles/states.css`：empty/loading 使用 danger 色语义不准确；应改为中性 surface/text。
- `apps/desktop/src/shared/ui/interaction.ts`：缺失音量值经 `Number(null)` 变成 0，可能把默认音量错误地初始化为静音；需要先判断存储键是否为 null。
- `apps/desktop/src/shared/ui/navigation.ts`：独立工具窗口写入的 last-route 使用窗口级 key，而恢复读取路径需确认是否使用同一 key。
