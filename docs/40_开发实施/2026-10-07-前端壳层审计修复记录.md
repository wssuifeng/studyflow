## 2. 审计结论校准

### 2.1 `assignment.summary` 不是当前真实缺陷

补审记录将 `assignment.summary` 判断为 Core dispatcher 未注册，但当前分发链为：

1. `dispatcher._dispatch()` 先把 `assignment.summary` 命中 `extensions.METHODS`；
2. `extensions.dispatch()` 委派到 `studyflow.modules.reviews.queue_queries.summary`；
3. `protocol.CAPABILITIES`、安装版烟测和前端调用均使用该方法。

因此本项属于隔离上下文不完整造成的假阳性，不修改前端调用名，也不增加重复的 dispatcher 分支。本轮在 `packages/core/tests/test_engine.py` 增加真实 Engine 调用回归，确认 `assignment.summary` 返回队列数据。

### 2.2 其余 P1/P2 风险已按最小范围修复

- 工具窗口放回侧栏：确认离开后再次检查当前 `ToolSession.flush()`；保存未确认时不发送 docking、不销毁窗口。
- 计划编辑：进入 `mutate()` 即同步取得 `editing` 锁，笔记预保存、Engine 写入和刷新均处于同一 `try/finally`，避免快速重复点击并发 `plan.edit`。
- 工作区切换：`prepareTools('shutdown')` 纳入保护性 `try/finally`；只在取得 request id 后释放，异常不会永久卡住 `busy`。
- 工具桥：`openToolWindow()`、`addDetachedNote()` 增加非 Tauri 降级与监听异常保护；`suspendTools()` 改为 `Promise.allSettled`，单个已关闭子窗不会阻塞其他工具。
- dock 排序：`from === to` 和目标不存在均为 no-op，不再触发 `splice(-1, ...)`。
- 工具索引：读取与写入统一使用冻结上下文的 `props.context.studyId`。
- 工具事件：异步 handler 的 rejection 统一报告，不再使用静默 `void handler(...)`。
- 计划列表：搜索 trim、大小写归一化；筛选无结果显示明确空态和清除筛选入口。
- Engine 浏览器请求：超时控制覆盖 `response.json()` 响应体解析阶段。
- 音效偏好：没有历史音量键时使用默认音量 72，不会因 `Number(null) === 0` 把新用户初始化为静音。
- 空态/加载态：使用中性 surface 语义；错误态保留 danger 语义，避免普通空态显示为错误。

## 5. 后续核心功能链建议入口

在继续扩展功能前，建议把核心链收敛为：

`发现计划 → 打开冻结课程轮次 → 阅读/记录笔记 → 按知识点保存草稿 → 整课提交 → assignment.summary 生成待办 → Agent 获取 assignment.context → 批改/指出问题 → 用户修正与复测 → 回写并回读状态 → 计划进度聚合`。

后续重点不是再增加仪表盘，而是为这条链补一套跨窗口一致的状态投影、幂等请求回读和用户可见的下一动作。
