## CLI 音频持久化与课程复用

2026-11-20 使用 MSI 解包所得的 `studyflow.exe` 1.8.22 运行隔离制课。模拟 Audio Speech 服务收到 1 次合成 POST，退出合成 CLI 后由另一次 `speech.job.get` 读到 `ready`。关闭模拟服务、清除测试 Key 后，重放原任务和重复采用返回原结果。两份独立 `/7` 课程包引用同一个 WAV，工作区只有 1 个已采用音频实体。两次作者预览、四次正式课程音频读取都校验了原始音频字节。两课均在隔离工作区完成填空与整课提交。回执在 `apps/desktop/test-results/cli-audio-reuse/verification.json`。真实阶跃单句合成见本记录前文。

制课时先用 `studyflow capabilities --format json` 检查 `engine_capabilities`，再用 `studyflow call --method speech.profile.list` 获取已配置的 `profile_id` 与 `version`。合成、采用与导入可在同一工作区由 CLI 完成。

1. `studyflow call --method speech.job.start --file job.json`。请求含固定 UUID 格式的 `job_id`、`profile_id`、`expected_profile_version` 和 `text` 或 `segments`。单段通常一次合成请求，多段可逐段请求。恢复已有任务时沿用原 UUID 和参数。
2. `studyflow call --method speech.job.get --file job-id.json`。状态到 `ready` 后，用相同的 `job-id.json` 调用 `speech.asset.adopt`。这个文件只需要 `job_id` 字段。采用会将成品持久化到 `content/audio-assets/`，并返回含 `sha256` 和 `format` 的 `audio` 对象。
3. 将该对象填入 `/7` 课程包中 `LISTENING_GROUP` 的 `listening.audio`，执行 `studyflow course import-package --file course.json --format json`。后续课程直接填写原对象，导入、预览和播放从工作区读取同一个文件。跨工作区迁移时，使用包含音频资产的工作区备份。新建合成任务使用新 UUID 时仍会发起合成请求。
