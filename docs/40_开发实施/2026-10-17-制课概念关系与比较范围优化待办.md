## 1. 问题与已查证根因

- 通用制课规则已有目标对齐、概念完整性和不凑容器，但“按依赖展开”尚缺少可操作的知识结构设计环节；填好目标/题号/组件不证明能形成可理解的知识体系。
- 专项旧固定模板及旧 UI 规避要求与通用规则存在冲突，需在后续迁移中清退，不继续叠补丁。
- 此前纠错提示词将系统性编排收窄成表格修补；删行、改名或增加范围提示可能仍留下整体关系和先修缺口。
- 仓库与公共副本三份主要制课入口当轮哈希一致，不能把此次问题简单归因为同步遗漏；不据此声称所有副本一致。

这属于生成方法和教学语义，不是单纯主题/CSS问题。截图、schema合法或CLI成功都不能证明教学组织合理。

## 2. 推荐改造范围（待确认实施）

- [ ] **目标与范围**：根据资料、学习者基础和后续依赖确定必教内容，再设计检验证据；不从现有几道题倒裁目标。
- [ ] **区分两类关系**：梳理学科对象的组成/分类/功能/协作等关系，以及学习者理解所需的先修关系；不把组成树直接当教学顺序，不开发新知识图谱系统。
- [ ] **知识点边界**：以完整认知问题和解释/操作闭环拆合知识点，不按术语、字数或容器数拆分。
- [ ] **正文前教学骨架**：复用并扩展已有作者对齐工件，写清核心问题、必要起点、关键关系、小节依赖与检验；不把作者表格强制展示给学习者。
- [ ] **内容先行**：普通课先形成连续解释链，再选展示组件；英语按自然目标表达逆向设计可独立成立的递进序列，不强套理论课正文流程。
- [ ] **整条主线复核**：按学习者起点审整个知识点及衔接，发现结构问题回到骨架重排，不以局部删行代替修复。
- [ ] **表格与关系子项**：标题/对象范围/共同维度对应；组成、分类、协作、对比分清；必要定义与关系常显，合法跨类别辨析不误杀。
- [ ] **清退冲突入口**：重构通用主流程与必要提示词，而非重复附加禁令；专项迁移保留事实和边界，撤销固定六件套和过时 UI 规避硬要求。
- [ ] **工具协同与行为验证**：确定性工具只覆盖其实际能力；语义按证据复核。加入非已知反馈题目的代表任务，不能用格式/截图/关键词扫描认证教学正确。
