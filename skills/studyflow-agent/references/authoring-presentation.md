# 将教学骨架映射为可读课程

先按[制课入口](course-authoring.md)形成解释链。本页负责使用现有组件和验证显示，不决定学科关系，也不定义新前端协议。

## 1. 实际能力与内容分层

发现实际CLI支持的包版本/块型。/3的独立details是summary常显、body折叠；/5的concept可用body或最多两层sections，main常显、supplement简述常显/详解折叠，稳定小节ID供大纲与出处。见[契约](course-experience-v5.md)。正文默认单列；comparison是语义对照，不是布局指令。

必要定义、关系、推导条件、作答数据与理解桥梁保持常显，补充证明/额外例子可折叠；折叠后重读主线。不要为避旧配对合并无关概念，也不把所有正文藏进一个详解。未知能力时使用合法线性内容，不写任意HTML、CSS、JS或假字段。

## 2. 按理解任务展开概念

长篇概念解析或“读起来累”的反馈必须检查本节。先读连续正文，定位读者此刻要完成的理解任务：当前在认识对象、建立对应、辨析维度、跟踪变化，还是推算结果？从文字中才能自己重建的结构，优先就近呈现；每处保留使关系成立的必要解释。连续阅读不等于通篇散文，块型交替也不等于编排清楚。

| 阅读困难/实际任务 | 适合的改写 | 需要保留或避免 |
|---|---|---|
| 对象、角色及对应关系混在段落里 | 先用读者可懂的短文建立对象，再用紧凑的角色/对应表或合法文字关系直呈联系 | 表要有真实共同维度；不能只把术语定义搬进大单元格，不编造图示字段 |
| 多个方案各讲一长段，读者需来回找相同属性 | 将已建立含义的对象按关键维度对照，在差异处补原因 | 依赖的定义先于结论密集的总表；开头可用熟悉维度定向，未知名词不能靠总表猜 |
| 对象随过程改变，文字只有一串动作 | 显示输入、关键中间状态、输出或合法文字流向；需要逐步教学才用steps | 每步有动作与理由；并列机制不能拼一条流程，少量连续动作也不必拆成一串大卡片 |
| 字母、位段或公式占据段落，读者难以对应量 | 先用自然语言说明在讨论什么量、各符号代表什么，再把关系和计算过程就近写清并说明理由 | 不让公式代替解释；检查实际宿主是否支持该写法；建立最小结构后即可局部演示，不必等整章定义讲完 |
| 小标题下面同时堆定义、分类、性质、例外、公式 | 围绕当前问题拆解，分别选择短文、关系表达、必要演示；在问题转折处承接 | 不按字数拆碎；只改为更多标题/sections仍可能是同一堵文字墙 |
| 简单定义、完整因果解释或连贯叙述本身就易读 | 保留短文；必要处用清楚的指代与段落承接 | 不为增加视觉种类强行转表格、steps、example或callout |

### 2.1 自然语言优先，术语先解释

正文先回答学习者眼前的问题，再引入压缩表达它的术语。遇到不确定读者是否熟悉的名词，先说明对象或现象是什么、在当前情境中做什么，随后给正式名称；缩写和符号也先说明所指，再用于推理。准确术语不要删掉，但不要让一个新名词靠另一个未解释的新名词来定义。解释到足以完成当前理解即可，不建立脱离正文的术语墙，也不强制每个句子只含一个知识点。

数学表达要能直接读懂，而不只是看起来像公式：逐个说明符号含义、运算关系和使用条件；推导中把关键变化说成自然语言，并保留必要的等价步骤。能用短句表达时，不为显得正式而改成符号串。若使用记号，给出可朗读的文字解释，例如`2³`并写“2的3次方”；Unicode上标可辅助视觉辨认，不能代替解释。变量指数等不适合简写的式子可写成“2的e次方”，先说明`e`表示什么。

当前StudyFlow源码的Markdown链路不含数学排版扩展：`2^3`与`$2^3$`会作为原文字样显示，`<sup>`标签会被清理；不得假设LaTeX、HTML上标或其他公式语法会生效。除非在实际目标版本/宿主中验证过，否则优先采用自然语言，必要时辅以可直接显示的Unicode字符。若目标内容必须使用当前不支持的复杂公式排版，应报告呈现限制并另行评估软件支持，不要把不可读语法写进课程正文。

冷读时检查：学习者第一次碰到正式名词/符号时，是否已经知道它指什么；能否按实际显示读出公式并解释每个量。标题、术语表或后文补充不能替代正文首次依赖前的解释。

浮点数中“有效数/指数/规格化/前导1”先释后用的裁定示例见[术语先释例](authoring-review-examples.md#8-先解释名词再依赖公式)。它是一次具体裁定，不是通用的案例开场顺序。

根据内容作用选择实际支持的载体。concept适合解释，sections表达真实的父子问题；有真实对照才用comparison，有输入/推演/核验才用example。callout服务一处明确的误区、限制或提示，不承担整章主讲；tone按实际语义选，不把普通定义/概览改成“警告”求显眼。实际标签、图标和颜色属于产品呈现，不能为了“绿色卡片/左边框”误用类型，也不编造callout.sections等未知字段。

选择能把关系说清且阅读成本合适的表达：短对应可以直接写成一行合法文字关系，简短应用可以留在解释附近；不把每次两三步操作都升级为占满一屏的example/steps。采用表格或完整演示时，也要检查它的标题、空白和步骤间距是否让读者反而难以连续跟踪。页面更高不自动失败，但增加滚动要有明确理解收益，不能以“块型更丰富”解释所有增量。

一个concept若承担多个独立问题，应重新判断块/小节边界；相邻几个concept也可能因表达都停留在定义段落而累。把它们合成一个带小标题的concept不会自动改善，强拆成更多同级标题也不会。标题层级只反映问题关系；现有宿主无法表达期望层级时，使用合法内容组织并报告限制，不借改标签、字符宽度或任意CSS伪造层级。对组成、分类、功能、协作分别说清关系，不能让一张改名表替代缺失解释。

以一段完整理解路径复核：读者知道当前问题，获得刚好够用的结构/含义，随后看得见关系或变化，能够解释关键理由并进入下一问题。它是读者能否跟上的判据，不是固定“概念→表格→步骤→例子→误区”的序列；无需每处设置口号、回顾或提问。必要结构先于协作过程，但可在结构建立后即接局部示意，不让读者连续记完多组术语才接触应用。

按[主流程§5](course-authoring.md#5-先完成解释链再映射组件)裁定复用：把一处密文改成更清楚的对照/过程时，要同时处理其原先重复载体，不追加一份表格或callout再抄同样内容。表格以短、可横向对照的内容为主；长段解释放在对应差异附近，避免把文字墙搬进单元格。主线中必要定义、因果、状态、条件和核验仍常显。

强调只突出当前决定性关系/限制；大量加粗、徽章和色块会抹平重点。工时、作者命令、资料定位留作者工件。段长、连续同型块和滚动距离是检查线索，不是配额；没有固定“每屏一图/每几百字一例/禁止相邻concept”。疑难改写见[长概念裁定例](authoring-review-examples.md#7-连续概念段落要改的是读者如何看懂)。

## 3. 内容复核先于显示结论

整链审核按主入口执行；逐题检查求解条件、可见答案泄漏、参考完整及允许的等价解法。区分跟做、无提示回忆和新情景迁移；相同数值/相同问题换题号不算迁移。

按实际页面顺序检查主流程§7：首次使用前的必要解释是否常显，跨组件/远距离的同程复述是否已处理，移动后的前后指向及引用目标是否仍成立。开头概览不能用尚未解释的术语/公式堆出结论；并列机制不能靠编号伪装成同一顺序。反查标题、表格范围、步骤和折叠与已确定关系是否一致；把summary换成details仍需通过内容职责复核。关系/顺序缺陷回到骨架调整，不以多截图、改徽章或清空表格代替教学修复。

## 4. 真实呈现按风险验证

新模板、首次采用新组件组合或已有显示问题时，在明确授权的隔离数据中检查真实Vue。长概念/阅读疲劳修订要选一条完整解释链，先检查其连续阅读效果，再看具体组件；不能只截新增表格、末尾彩框或首屏好看的位置。复用同一正式Vue与相关主题，在可比的窗口/缩放/侧栏条件下核对基线与候选，选实际有风险的长文、表格、公式及窄窗。

沿**实际滚动容器**检查开头、中部转折和末尾。待布局稳定后，在截图前后核对容器scrollTop与可见标题确有变化；浏览器窗口可能不承担滚动，重复的首屏截图不能计为中末段通过。长截图用于总览，还需正常视口看正文、标题、表格是否可读；未读到的区域写未验。截图/DOM尺寸提供位置证据，不能自动认证教学可读。

每条受影响链至少说明一个实际内容变化及作用，例如从多段属性中提取可对照的维度、将状态变化与原因就近呈现、把局部示意放回使用处；同时复核必要解释/覆盖仍在、是否制造新的重复、表格是否变成长段堆积。若变化只有字体、竖线、色块、块数或组件序列，解释展开与阅读负荷仍未证明改善。正确的普通段落允许原样保留。

稳定模板内纯内容小改可复用明确记录的显示基线，补验受影响内容，不要求每课重跑全部主题截图。已有获授权的正式Vue+Engine隔离环境时直接复用实际入口；作者工作区没有源码不构成自建前端的理由。未拿到入口时先完成内容草稿并报告呈现未验，不用手写HTML截图冒充。发现纯显示缺陷时记录宿主/主题/视口与实际几何，按已有授权修复或交维护方；不要用错语义类型绕过样式。

渲染记录必须绑定被检查的精确候选：记录实际renderer（StudyFlow桌面端或运行中的StudyFlow Vue页面）、App/构建版本、课程ID与content revision或候选包SHA-256、数据/隔离根、主题、视口/缩放、滚动到的内容范围、截图文件及SHA-256、问题和结论。截图要由实际渲染进程产生并能复查；静态HTML、手工拼图、组件故事页或只验证DOM/包结构都不能证明课程实际显示正确。当前安装CLI若没有渲染/截图能力，直接使用已授权的真实桌面/浏览器渲染入口；没有入口则保留“未验”，不得伪造回执。

内容修订先在隔离环境检查，再按已有授权/用户设定关口发布；验证对象应是准备发布的候选，并绑定其内容版本/hash。若已发布才发现缺陷，如实报告并正常修订，不把“现在发布再看看”当长概念样本的默认验证流程，也不自行增加逐课审批。body转sections或正文变更走preview/apply；成功更新会重置当前学习，笔记/历史保留。纯CSS不会替换内容；历史作答仍引用其原材料。

## 5. 只读质量工具

使用已确认CLI绝对路径执行`course quality-check --file <package.json> --format json`。可加`--blueprint`、`--sources`、重复`--related`、`--validation-receipt`、`--rendering-receipt`，只读指定JSON；不读真实工作区、不重写课程。源Skill的`authoring_quality.py`只是CLI薄代理，其PATH定位不能替代已确认的安装路径。

蓝图若供工具使用，`objectives[].teaching_ids/exercise_ids`指实际内容ID；工具核对引用与覆盖。其他关系/先修说明是作者工件，工具不会验证其意义。`teaching_chain_list`仅列英语progression，不是普通课语义分析。

`course quality-check`只读取包和指定回执，不启动UI、不截图，也不产生渲染证据。本机预检未发现CLI渲染/截图能力时，第三关必须先由上述真实renderer完成。回执按当前CLI实际接受的JSON契约绑定`package_sha256`和实际结果；调用前先核对帮助/schema，不猜测字段。只有验证器实际读取了该回执且哈希与检查对象一致，才能报告“有绑定的渲染回执”；quality-check本身不会补做渲染。过时/无绑定不记通过。长段、疑似泄漏、角色/POS或近似模板等命中逐条裁定，不自动删除/换词。报告`semantic_acceptance=not_evaluated`保持其原义，不能将零告警写成事实/自然度通过。

## 6. 英语解析与词段显示

英语按[自然表达](english-course-authoring.md#41-自然表达与语境审核所有英语制课任务必过)与[划分复核](english-course-authoring.md#42-独立表达与成分划分复核)审全部项。工具`english_structure_review`仅投影作者词位和POS提示，不猜正确语法。

逐词音标、短义、词性由作者按实际语境核实；片段结构类别不等于完整句中的句法功能。检查缺音标时不留空整行、长短释义混合不撑歪、错误/快捷键解析与正确隐藏；CSS不能修错词义或错划分。代表显示检查不替代全部项内容核对，区分源材料、历史材料、Core投影和实际DOM。
