# 连续课文与内容审核

与[制课入口](course-authoring.md)配合。这里是作者如何使用现有组件，不是前端主题或尚未实现的新渲染协议。

## 1. 当前能力边界

先发现实际CLI的包版本/内容类型。`/3`增加独立details块：summary常显、body默认折叠；它不是任意块折叠，也不是concept内部任意小节折叠。发现/5时concept可使用body或最多两层sections：main常显，supplement简述常显/详解折叠。稳定小节ID支持大纲和笔记出处；详见[现行契约](course-experience-v5.md)。正文默认单列连续课文流；comparison是语义对照，不是并排容器布局指令。不要为绕过旧配对把所有定义塞成一个巨块。

没有可发现能力时保留合法线性内容和标注适配建议，不能在课文里写`<details>`、CSS/JS、假字段或假装`【考点】`已被自动解析成特殊组件。必要定义、例题假设、作答条件始终可见。

## 2. 从文档Skill借语义，不搬版面

- 用小标题表达关系和层级；不要每两句话一个标题、重复块标题，或为了字号伪造标题等级。
- 定义串适合术语加粗+简短解释；列表表示真实并列/顺序，表格只承载共同维度比较。
- 适量强调关键关系/限制；全段加粗、连续警告或每块重复“重点”徽章会抵消层次。
- 正文不带工时、AI任务边界、批量脚本指令和重复教材定位。查证信息放作者来源/课程概况，保证仍可追溯。
- 视觉上过密时先区分主干与补充，再考虑合法details；不能按字数截断定义或用删内容掩盖布局缺陷。

## 3. 选块示意，不是固定模板

| 知识任务 | 可能的组合 | 不应机械附加 |
|---|---|---|
| 一个概念的适用边界 | concept+具体练习；必要时callout | 没有比较维度的表格、虚构流程 |
| 一次计算 | 定义/公式+有理由example+独立变式 | 复制同一推导成steps、summary再讲三遍 |
| 一段代码的运行 | 代码/状态解释+边界反例+追踪练习 | 把整段代码变成没有解释的“范例” |
| 业务建模 | 情景约束+有根据的取舍+新情景 | 六种块型依次列完但没有贯通对象 |

例题答案属于教学；独立练习的具体答案不能预填。想让学习者使用例题方法可换条件，不能只改题目编号。

## 4. 发表前内容检查

**逐题：** prompt/requirements能否独立理解？是否缺必要数据？是否泄漏待求结论？参考答案是否与已教口径、实际约束和等价表达一致？示例是否诱导一字不差的唯一答案？

**逐知识点：** 新术语都已定义？公式/单位/假设完整？标题是真实逻辑？存在重复描述或长段？同一对象是否贯通？每个附加块能说出不可替代的教学作用？

**跨课：** 先修是否来自真实前课而非作者想象？一批是否照抄同一六件套？新词/新概念/题量是否只是配额？回顾和检验是否具有实际目的？来源有版本与定位吗？

可用脚本搜“参考答案/正确答案/评分要点”等明显标签、统计段落/重复块序列作为预警，但必须逐条复核。一般约束中出现“答案/写出/解释”并不必然泄漏；无关键词命中也不能证明安全。不要从字数或同块序列自动删除内容。

## 5. 真实渲染检验

内容、CLI数据与实际显示分别验。先试一个典型知识点和一个复杂知识点，在实际Vue里检查：

- 标题层级、段落行长/留白，长代码/公式/表格和窄窗口是否可读；
- 详解闭合时主干完整，展开后大纲锚点/引用原文定位仍有效；
- 题面只显示作答条件，知识点与题目归属准确；
- 内容的版本/状态、保存/退出没有因展示修订被重置。

软件缺陷登记给开发，不要求作者把课文改成巨块或伪造标题。课文流去卡片、块内折叠、路线图等未实施能力只能列建议。机器验证不代表学习者阅读舒适、学会或完成；真实课修订仍需本任务授权。
