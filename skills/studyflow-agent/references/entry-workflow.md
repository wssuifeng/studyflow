# 首次进入与会话恢复

每个新会话先恢复目标资料与协作状态，再用实际CLI确认StudyFlow数据根和当前能力，最后按用户已定义的目标与计划列出可执行事项。若用户已明确具体任务，直接进入相应流程，不再要求从菜单选择。

## 三类根目录

- **任务/参考资料根**：用户本次指定或当前项目明确承载材料的目录；只扫描该根的说明、索引和任务指针，不递归扫相邻磁盘。
- **Agent协作根**：长期保存目标、计划、参考资料、课程作者材料、会话记录、学习证据和批改回执。通过用户本次指定路径或`~/.studyflow-agent/workspace.json`定位。
- **StudyFlow数据根**：由CLI管理课程、练习、学习、提交、笔记和批改状态。只能经实际CLI访问。它与Agent协作根、安装目录、源码仓库互相独立。

`doctor.workspace.governance_root`不是Agent协作根。`governance_ready=false`不表示数据损坏，也不授权把协作文件放入AppData。

## 开场顺序

1. 读取当前实际加载的`SKILL.md`和本文件。用指定CLI绝对路径、显式数据根运行`version`、`capabilities`、`doctor`；检查退出码、JSON、`ok`及返回的绝对`workspace.root`。简要汇报版本、健康/可写和缺失能力，不打印完整清单。不要静默改根或用`setx`。
2. 定位目标资料根和协作根。目标路径不明确时只检查当前工作目录中用户提供的`AGENTS.md`/项目入口，不向上无限遍历；协作根优先用显式路径，其次读取固定用户级指针。不得递归扫描用户目录、AppData或整盘猜路径。
3. 若协作根不存在，在用户已指定的专用材料父目录下创建`StudyFlow-Agent-Workspace`；没有指定时使用`<user-home>/StudyFlow-Agent-Workspace`。父目录有混合用途内容时只创建专用子目录。按[工作区结构与记录规范](workspace-structure.md)初始化缺失文件，不覆盖已有文件，并更新用户级指针。绝不在StudyFlow数据根、安装目录或软件源码仓库初始化。
4. 每次会话必读协作根的`AGENTS.md`、`INDEX.md`、`state/current.md`、`state/goals.md`、`state/decisions.md`、当前活动计划，以及最近一条session记录和与任务相关的最近学习/批改记录。再读目标资料根的AGENTS/索引/当前任务文件。只打开当前任务相关的参考资料，不遍历历史归档。
5. 对会变化的版本、计划/课程状态、学习提交和批改队列，以本轮CLI为准。只读任务所需范围；不为查看课程而新开学习轮次。每次从软件读取到并用于规划/制课的学习事实，按[工作区结构](workspace-structure.md)写入最小化学习证据记录并更新相关计划/目标；真实答案和私人笔记不复制进协作区。
6. 若没有明确任务，使用目标/计划文件、工作区未完成项和CLI实际能力生成菜单。仅当需要确认菜单选项的当前队列或状态时，才做对应的最小CLI读取。菜单用简体中文、简短说明第一步，不默认假设用户要制课。

## 菜单

只列出CLI和工作区都能支持的事项；能力缺失要标注，不编造操作：

1. **继续计划课程编写/修订**：从活动计划定位下一课、对应目标与已登记参考，先做草稿和审核，再按授权发布。
2. **编写或调整学习计划**：依据用户目标、有限阶段、已存学习证据和参考资料更新计划；目标变化需用户定义/确认。
3. **查看学习进度或批改记录**：有对应能力时读取指定范围；处理批改必须针对真实提交并获得用户明确要求，不能代学习者作答。
4. **新增/调整学习目标**：记录目标原文、日期、可观察完成条件和依据；不把“学过/无错题”推断为掌握。
5. **登记或使用参考资料**：保存用户提供的原件或稳定来源信息，记录本次实际阅读范围和用途。

菜单末尾可询问：“这次想先做哪一项？是否有新的参考资料需要加入（可给文件或来源路径）？”用户已经指定任务时不再重复询问。

## 收尾与状态回写

有实质进展时更新`state/current.md`、`INDEX.md`和一条session记录；新建/更改目标、计划、参考使用、课程发布、学习读取或批改时，同时更新其专属登记/回执文件。状态摘要保持短，详细证据进入对应记录。只读咨询且没有新增事实或决定时不必造日报。

任务状态分别标注草稿、已结构校验、内容已审核、真实呈现已检查、CLI已发布、学习记录已回读、批改已回执、用户已验收。任一状态不得替代其他状态。细节见[工作区结构与记录规范](workspace-structure.md)。

## 按任务读取规则

- 计划、目标、反馈闭环或长期资料维护：读取[长期工作区治理](learning-workspace-governance.md)与[工作区结构](workspace-structure.md)。
- 新课、审核或修订：读取`course-authoring.md`和`authoring-prompts.md`。
- 长概念、阅读负荷或显示/公式问题：再读取`authoring-presentation.md`。
- 英语课程：再读取`english-course-authoring.md`。
- 批量、OCR或中断续行：再读取`authoring-workflows.md`。
- 学习、批改、笔记和备份：只读取该动作对应的契约。`system.schema`及完整请求结构只在具体调用需要时读取。
