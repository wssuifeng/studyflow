# 批量制课与中断续行

只在任务确实涉及批量/OCR/多阶段流程时读本页。宿主工具、资源预算和执行权限来自本次任务，不因为Skill提到流程就自行开子代理/调用新平台。单课可用简短检查清单，不建立重型工作流。

## 1. 先验证样例，才扩批

编写者会复制样例里的隐含约束。样例先过范围/关系/先修与整条解释链、可见字段无答案泄漏、数据与必要真实呈现和回读，再按实际授权分发。不同主题需有不同组织的样例，不能以一门“六件套”推导所有课。批量验证结构还需内容扫描、逐条命中复核与跨主题抽查。样例应含无效重讲的修正与有用复用的保留；长概念样例还需按展示审核，交完整解释链的实际关系/状态表达变化及连续视口对照，核对滚动确实抵达中末段。不能用彩色组件序列或“这一屏好看”推广整课；按主流程§7交付实际前后解释顺序，不能仅报告组件数或revision。抽查用于发现共性问题，不替代任务范围内逐课的内容复核；同类缺陷复现时检查本批适用的同链/同模板项，修正编排方法后再继续，避免带错扩批。用户已设样课确认关口时沿用；没有该要求不自行新增逐课审批。

## 2. 并发是统一资源预算

OCR耗内存，网络工具/子代理可能共用提供方并发；不能各自按上限加总。先用小批测资源占用，按本次宿主/提供方/用户上限取可用预算。工具参数类型错误与模型超时分别诊断，不通过无限重试或偷偷改配置解决。

不要把某次“5并发恢复正常”写成所有机器的固定最佳值，也不默认授权委派。若任务当前指定上限5，重型工具占用的槽位也计入这5个。

## 3. 静态重放输入与动态结果分离

对于要求确定性重放的宿主：以稳定任务ID/输入路径与哈希/阶段序号组织；会影响重放哈希的report调用输入及调用顺序保持静态。完成顺序、耗时、时间戳和模型自由文本放独立结果工件/宿主支持的动态日志，不塞回静态重放接口。

普通日志不需要全部变成固定句；只对受重放约束的接口采用该规则。不得把某宿主的AmendWorkflow等名字或错误当所有Agent通用命令。

## 4. 中断恢复，不重写已完成阶段

阶段工件记录输入哈希、规则版本、稳定课/知识点/练习ID和真实回执，并区分内容复核范围/未决项与已发布事实。恢复先读工件与CLI现状；只跑未完成、输入或适用规则有变化的阶段，复用仍成立的证据。规则更新只重审受影响内容；旧回执若只有清理、校验或发布，不推定已完成教学重编排，补做欠缺审查。缓存存在不等于成功，成功回执也不代替内容审查。

幂等键按明确操作固定：未知结果只以原负载/原键重试；负载改变必须新键。不得用新的时间戳键无限重放写入，也不能靠直接SQL或新建同名课程避冲突。

## 5. 健康检查与OCR证据

用实际支持的doctor/today/plan/course回读检查健康、归属/顺序/计数和revision；成功导入不证明学习完成。JSON用可靠序列化写UTF-8文件，不手工拼接shell字符串。参数形状从capabilities/system.schema/本机help发现，不凭另一平台的旗标名称猜。

OCR保留原PDF、页码和复核点；代码/公式/符号优先核对渲染原页。字母收支闭合、词表覆盖或OCR置信度都是局部指标，不证明语义零误差。编码故障先确认PowerShell版本/文件编码：Windows PowerShell5.1的中文脚本可用UTF-8 BOM，不把ASCII-only的某条管线习惯推广成系统硬要求。

动态回执/模型输出、私人教材和课程样本留获授权的私人/忽略区，公开Skill只留通用规则。停止条件是明确失败/资源预算/权限或数据结果未知；报告实际卡点，不自动扩权或清理学习数据。
