# 制课入口：目标、知识与评估对齐

用于计划蓝图、新课、修订或内容审核。这里规定教学判断，CLI/schema规定可写数据形状；两者不能替代。先读本页，再按任务读[展示与内容审核](authoring-presentation.md)、[可复用提示词](authoring-prompts.md)；英语另读[英语制课](english-course-authoring.md)，批量/中断恢复才读[批量流程](authoring-workflows.md)。

## 1. 明确任务和事实来源

最小输入：模式、学习目标、基础/先修、前后课程、授权资料、已有学习证据、目标计划/课程、是否允许实际写入。只读必要资料，不递归读取学习者答案/笔记或整个私人工作区。

区分：权威原始资料、OCR/提取稿、作者解释/推导、学习者实际证据和待核实假设。课程专属教材页码、考纲树、词表数字/稳定ID登记在作者材料；不塞进通用Skill。遇到扫描/OCR先抽核关键定义、公式、上下标、符号和题目条件；不能只凭提取比例/字符闭合宣称事实无误。

未知基础可以提出标明假设的蓝图，不把“生成过材料”当“学过”。既有课程优先保留稳定ID与计划顺序，不改名建副本绕过修订。

## 2. 先确定检验，再组织讲解

内部建立简短对齐表（作者工件，不强制显示成学习正文）：

| 知识点 | 可观察结果 | 前置/本课首次定义 | 教学活动或贯通例子 | 检验题 | 作者合格依据 |
|---|---|---|---|---|---|

用解释、比较、计算、追踪、建模、排查等动作，不只写“了解”。每个必答题所需概念应已教或是明确前置；迁移换场景时说明使用哪些旧知识。不能教识记却突然按未教的分析能力批错。

概念完整性重点：术语/符号先定义再使用；别名不等于定义；公式注明变量、单位、适用假设；例子中的新概念也要有入口。必要定义不可藏进默认折叠详解。

## 3. 一个知识点是一条学习主线，不是一套容器配额

- 开头给真实问题/用途或精炼核心关系，按主题选合适入口，不强制每课“结论先行”。
- 按依赖顺序展开内部小节；段落承担一个意思，长度服务于含义，不硬套“每段80字/两句”。
- 选一个对象贯穿说明、例子与尝试；块间说明真实关系，避免机械“上面我们学习了……”承接。
- 对比只在有共同维度时用comparison；流程只在步骤/分支确有教学意义时用steps；例题给过程和理由；callout只标真实易错/边界。
- 没有理由就不加辅助块；允许不同知识点有不同块数/序列。不要每节凑齐concept/comparison/steps/example/summary/practice。
- 多个相关知识点属于同一课程；不为一词/一卡拆课程，也不把无关主题塞成超长课。
- 展示选择按[展示审核](authoring-presentation.md)；支持的details只折补充，不写任意HTML/JS/CSS或未发现字段。

## 4. 各类主题用不同教学组织

| 主题 | 必须讲清 | 合适的检验 |
|---|---|---|
| 概念/辨析 | 定义、边界、正反例；近似术语差别 | 解释关系/判断新情景并给理由 |
| 计算/推导 | 变量、假设、单位/位宽、每步依据、结果核验 | 换输入独立推导，不能只背例题答案 |
| 代码/算法 | 环境、输入输出、状态变化、边界；不只贴代码 | 追踪/解释/实现，允许满足约束的等价方案 |
| 综合案例 | 已知业务规则、未明假设、约束和取舍 | 建模/诊断并解释决策，不凭作者默认补条件 |

示例与练习适当交替，保留无提示检索与新情景迁移；不把单一教学次序或固定题量宣称普遍最优。

## 5. 题面可见，作者参考分离

`prompt/requirements`属于作答前可见字段。requirements只写交付形式、过程、单位、明确约束；不要放结论、解题路径关键答案、评分答案清单或标准解法。必要数据应放题干，不能为“防泄漏”删掉求解条件。

- 好：写出计算过程，注明单位和采用的假设，结果保留两位小数。
- 坏：答案应包含命中率0.9、结果20ns；或“应指出某状态必定转为阻塞”。
- “列出几个项目/解释某概念”不自动算泄漏；检查是否把待检验的具体结论交给了学习者。

发现课程包/5能力后，将参考结果、解释、检验依据、可接受变体与出处放题目的`review_reference`，详见[现行契约](course-experience-v5.md)。题面与解析分用途显示，不是账号/权限。旧CLI不支持/5时保留获授权外置作者参考，不能塞进requirements或伪造字段；批改前按冻结题面读取对应参考。

使用外置作者参考时，最少记录课程/包定位、稳定知识点/练习ID、课程revision或未发布草稿版本、公开课程内容哈希与题面指纹、参考版本和来源定位。这些是获授权的作者工件，不是新的课程包字段；草稿标识不得冒充CLI已发布revision。课程revision指内容版本（content_revision），不是学习轮次序号；公开包哈希和冻结快照哈希也不能直接混用。批改时核对实际冻结题面，不按同一题ID自动读取最新参考；缺少版本绑定或题面不匹配时，暂停使用该参考，报告缺口并请求确认可用依据，不默默套用旧版/新版答案。

逐题核对题面可解、要求一致、非唯一答案标准清楚。复杂任务可分标准；不把示例解法当唯一答案，不给个人工具增加班级排名/统计平台。

## 6. 复习、错误与修订

实际能力支持时：指定计划 + general/english分域 → 摘要 → 有界重点列表 → 必要冻结题目/原作答/反馈。不要把两域错误堆成一个队列，也不能凭失败次数诊断长期缺口。原题修正、无提示原题复测和新情景迁移分别设计；没有证据不伪造个性化。

英语补充课另读[英语补充学习](english-remediation.md)；安装版是否支持以capabilities为准，不从仓库文档猜命令。

格式修订用preview/apply并回读；已开轮次仍读冻结版，不自动重开/清理。确有授权时按安全重开契约处理，而不是要求用户反复purge。作者资料和复测题的变更也应可追溯。

## 7. 四道交付关口

1. **事实/教学**：先修、概念、推导和目标—练习对齐；记录未核实项。
2. **内容**：逐题查可见字段泄漏、冗余/固定模板、连续性；扫描命中必须语义复核，零命中不等于正确。
3. **数据**：实际CLI validate；类型、ID、引用、计数、版本/变体合法。validate通过不等于教学质量通过。
4. **真实呈现/操作**：在授权的隔离工作区看正文/折叠/大纲/练习/双主题或相关模式；设计图、Word/PDF样式或JSON都不能替代实际Vue检查。

先少量代表样本，确认规则和显示后再扩展；授权写入才导入/修订，回读计划归属、顺序、知识点/题数及revision。只报告交付与真实回执，不代作答或宣称掌握。用[提示词](authoring-prompts.md)启动相应任务；资料/排程留作者计划，不挤入正文。


## 长期计划与维护

多轮制课/反馈复盘/学习资料目录维护先读[工作区治理](learning-workspace-governance.md)。目标拆为有限阶段，真实证据影响下一课，不把已生成/导入当掌握；当前来源小量恢复，不递归重读全部教材或课包。具体考试、真实路径和课量约束留任务。
