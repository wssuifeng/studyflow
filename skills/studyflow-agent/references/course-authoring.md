# 制课入口：先组织知识，再完成课程

用于计划蓝图、新课、修订和内容审核。教学设计由本页负责，字段和可写数据以实际CLI/schema为准。先读本页；选块/检查读[展示审核](authoring-presentation.md)，任务调用用[提示词](authoring-prompts.md)；英语另读[英语制课](english-course-authoring.md)，批量/OCR/续行才读[批量流程](authoring-workflows.md)。

## 1. 确定学习任务与应教范围

最小输入：目标、学习者基础/未知项、前后课程、授权资料、必要学习证据、目标计划/课程及允许操作。先判断这次要使学习者能够解释、辨析、计算或完成什么，再确定应教范围；已有几道题、教材标题或组件数量都不能代替范围设计。未知基础可以作标明假设的蓝图，不把“生成过/读过材料”当作会用。

从考纲/教材/已批准计划确定本课必须建立的理解、边界和后续承接，再设计检验；若现有题只覆盖局部，补全教学/检验或报告范围缺口，不倒裁课程来迁就题目。无关扩展留后课，确属理解必需的起点不能以“本题不考”跳过。

区分权威原始资料、OCR/提取稿、作者解释、学习证据与假设。扫描材料先抽核定义、公式、上下标、符号和题目条件；提取率不证明事实正确。教材页码、考试范围、真实路径等留作者材料，必要时有界查证，不递归重读全部私人工作区。

## 2. 建立两种结构：学科关系与理解依赖

先确认学习者是否已有相关结构。没有实际前课或学习证据时，不能默认其认识关键对象、层级或术语。对于系统组成和工作机制，先建立整体/边界、主要部件与职责，以及理解当前过程所需的关系，再让读者跟踪部件协作。结构与职责的首次解释有独立教学作用，不能因案例也会出现这些名词就删掉。

按实际阅读顺序，在机制、公式、步骤或求解案例首次使用某项知识前核对：读者能否辨认对象、关系、术语、给定条件，并完成此处依赖的基本操作？为每个必需项找到前文常显解释或可信先修依据；缺项先补。不把列出全称/别名当作解释，也不能到算例之后才教会其中反复使用的基本操作。案例可承担新机制的首次解释，但不能让读者靠过程猜它所依赖的结构。简单的问题或情境可用于引出学习动机，但应使用当下能理解的语言，不要求读者提前运用未建立的结构。此核对可在既有骨架完成，不新增逐项报表。

先画简短关系草图或写几行关系说明，不建立额外知识图谱系统，也不强制每课同一张表：

- **学科关系**：涉及哪些对象、概念、条件或机制？组成说明部分属于什么整体，分类说明某类有哪些类型，功能说明解决什么问题，协作/因果说明如何发生联系。只标本课需要的关系，不凑齐所有类别。
- **理解依赖**：从学习者当前起点，理解下一步必须先获得什么？把“已知→需补的桥梁→本课新理解”连起来。对象组成树不能自动充当教学次序；机制、推导和案例可从一个问题进入，再按需要引入部件。
- **范围与口径**：功能划分、物理组成和教材分类可能不是同一个视角。声明本课采用的视角，避免把重叠功能强画成互斥分区；简化模型必须保留影响结论的条件。

例如讲CPU，先建立足以理解当前任务的整机/内部部件关系；当前案例必需的寄存器，先说明保存什么和承担什么职责，再观察它们参与取指。其他寄存器可留在后续需要处，不把所有名词先讲一遍当作先修。计算主题则应先明确量的含义和成立条件，再从实际过程建立数学关系，没必要硬画组成树。例子用于说明方法，不是所有课的固定起手式。

开头的概览只建立当前问题和必要关系，不提前堆叠尚未解释的性质、公式与结论。术语/符号首次承担解释时给出可理解定义，别名不算定义；公式交代变量、单位、适用条件及读者需要的推理桥梁；例子引入的新概念同样要有入口。按理解需要补最小前置，既不突然用新名词，也不先堆一页脱离用途的定义。

## 3. 用完整认知问题确定知识点边界

每个知识点承担一个可说明的理解/操作问题。拆合时检查：

1. 学完后能解释什么关系、完成什么过程或判断什么新情景？
2. 独立阅读是否有起点、关键解释和检验？拆开后是否必须来回跳转才能理解同一件事？
3. 合并后是否同时承担几个不同问题，造成不必要的新负荷？相邻知识点的承接是什么？

不要按术语数、字数、教材小标题或卡片数机械拆分。多个知识点可以构成一课；一个术语不必一课，互不相干的主题也不应塞成超长课。既有课先判断结构问题发生在哪一层，再决定重排小节、拆合知识点还是只改一句；保留同一语义对象的稳定ID，换目标/换题时评估新ID和引用。

## 4. 写轻量教学骨架并设计检验

正文前，为每个知识点留下以下信息；可以用现有蓝图补充，不另造重复报表：

| 作者要回答的问题 | 最小内容 |
|---|---|
| 本节解决什么 | 完整认知问题、可观察结果与范围 |
| 从哪里开始 | 已有证据、基础假设、最小先修及首次解释位置 |
| 怎样形成理解 | 主问题、关键关系与展开路径；首次必要解释/完整演示各在哪里，后续再用新增什么；目录不直接复制覆盖清单 |
| 如何检验 | 贯穿例子、独立检验/迁移、完整参考与成立条件 |
| 内容落在哪里 | 目标→知识点/块/小节/题ID，必要常显内容与补充理由 |

先写有意义的骨架，再给实际内容定位。单课不为每句增加管理表；复杂问题才展开细节。目标—讲解—检验必须对应：不能只教识记却按未教的分析能力批错，同数值同任务跟做不能冒充独立迁移；换输入须重新核算。

不同任务选择不同骨架：概念重定义/边界/关系，机制重条件与状态变化，计算重两端含义/假设/推导/核验，代码算法重输入输出/过程/边界，综合案例重规则/约束/取舍。它们是判断方向，不是必须依次出现的栏目。

## 5. 先完成解释链，再映射组件

按骨架写连贯教学，先让读者知道当前要理解/解决什么，再提供足够进入问题的最小整体。术语在首次参与解释时说明用途；覆盖清单供作者查漏，不能逐项转成“名词标题＋定义”。同一问题可以连续展开几段，标题标记问题或推理阶段的转折，不按术语数切段。段落长度由意思决定，不硬套字数/句数。连续讲解强调理解相接，不表示把所有任务压进长concept或连续多个“名词标题＋定义段”。主线去卡片也不意味着只剩长正文；若一段同时让读者建立对象、记属性、比较差异、想象过程并计算，应按当前理解任务改写展开方式。

语言先让学习者听懂，再给准确名称。若某个名词、缩写或符号不是明确的已知先修，首次需要它时先用自然语言说清“它是什么/指什么、在当前问题里起什么作用”，再给正式术语或记号；后文才用短名称继续推理。不要先抛术语再用更多术语解释，也不要把覆盖清单写成一串“名词：定义”。正式术语应保留，不能为口语化而牺牲准确性；不要求反复解释学习者已经掌握的基础词，也不按固定术语数或句长机械拆文。解释应出现在读者第一次需要该概念的位置。

为首次解释、演示、辨析和回顾安排实际职责，按主题取舍而非固定栏目：

- 首次解释建立必要关系、条件和因果；案例先修已成立时，带理由的案例也可承担新机制的主讲。基本结构和职责不能靠学习者在过程里猜出。
- 演示把规则落到具体输入、关键中间状态或取舍，说明每步为什么成立，并核验结果。规则说明与带数演示可以并存；抽象方法、操作说明和案例各自应解决尚未解决的理解困难，不能各写一遍完整的同程推导。
- 辨析通过共同维度、反例或边界解决混淆。对比表、口诀、选用步骤、场景和误区若只是反复给同一选择结论，保留机制/理由与有区分作用的案例，合并其他复述；换成表格或警告框不会自动产生新用途。
- 回顾服务于新的组织线索、隔一段后的必要提醒或不看正文的主动检索。紧接正文复述全部结论可省。检索题的价值是让学习者提取或应用，不能因答案已教就删除；也不能把同题原样重算称为独立迁移。

初稿后按整条解释链检查“新增理解”，包括相隔较远的正文、表格、steps、example、误区及details；不只检查相邻块或summary。疑似重复处对照：**对象/问题、条件与输入、推理或操作路径、结论、读者此处要做的学习任务**。措辞或组件不同仍可能同程复述；公式/术语相同也可能分别承担定义、应用、条件辨析或检索。

若多处对同一情境走同一路径、得到同一结果，且后处没有新增理由、边界或学习任务，选定一处完整讲解，将其他处合并、改成短承接或删除重复载体。需要的抽象规则可简明保留；关键中间状态、因果、假设和核验不能为去重删掉。第二个完整例子应有实际用途，例如展示不同分支、修正误概念或安排必要练习；仅换数据可能用于练熟，但不能宣称已验证迁移。语言训练的渐进组合、变体练习和间隔再现按专项规则保留，不套“一种过程只能出现一次”。

用删除后的阅读结果复核处理：读者是否仍能理解为什么、在什么条件下成立，并完成目标任务？若只能背结论，恢复缺失桥梁。再做一次冷读：不借助作者心里知道的知识，读者在每个名词/缩写/符号第一次被用于推理前，能否从就近文字说出它指什么、为何出现？公式能否按其写法读出来，符号各自指什么是否清楚？若要靠猜、查词表或读到后文才补懂，回到首次使用处调整解释顺序。疑难处可参考[编排裁定例](authoring-review-examples.md)，只在既有骨架记“原位置→保留/前移/合并及理由”；不为每句话新增报表，不把字数/标题/组件减少当质量目标。

最后按[展示审核](authoring-presentation.md#2-按理解任务展开概念)选择现有表达。长概念讲解先找读者需要在脑中另画表、另排顺序或来回找定义的位置，把这部分关系/状态/计算就近呈现，再用必要短文解释为何成立；不能仅拆成更多同级标题、合并成sections或追加彩色框。结构含义建立后可马上接简短示意或应用，不把所有定义和性质堆完才集中举例。一个载体可以承接几段相关解释；多个不同问题也可拆成连续片段。同课不同知识点不必同序，不把示范课固定成模板。steps只能表达同一任务的真实顺序/分支；几种并列机制各有流程时，放到各自必要解释之后，不能拼成一条伪流程。

定义、关键关系、推理桥梁、必要假设和作答条件常显；可选证明/额外例子才折叠。折叠后从头读一次，确认主线仍完整。将summary改成details但保留同程复述，仍未解决阅读负荷。正文不带排程、作者命令、题号“不考”提示或批量管理话。展示能力以实际契约为准，不能写任意HTML/JS/CSS或假字段。

英语共用范围、先修、映射与审核方法，生成路径按专项规则从自然表达和有用途的句序展开，不强套理论课的连续正文。

## 6. 题面、参考与反馈

`prompt/requirements`作答前可见。题干保留求解数据，requirements只写交付形式、过程、单位与明确约束，不放待求结论、关键答案或评分答案清单。“解释/写出几项”不自动构成泄漏，应看是否直接交出了被检验内容。

CLI确认支持/5后，将完整答案、解释、合格依据、可接受变体及出处写入`review_reference`，见[契约](course-experience-v5.md)。这是本地用途分离，不是账号权限。参考必须实际解答问题，提纲和“补充推导”不是答案；复杂任务允许有依据的等价方案。

旧CLI不支持时使用已授权外置参考，绑定课程/包、知识点/题ID、材料revision或草稿版本、内容hash与题面指纹、参考版本/来源；不能伪造课程字段。批改历史作答按其实际题面匹配参考，不能凭同一题ID套最新答案。缺匹配依据暂停相关批改，不影响无关任务。

按计划+general/english限定错误范围，先摘要再有界context；区分手误、概念/语法缺口、提示依赖、迁移失败、坏题和软件故障，不凭失败次数就断言长期不足。原题修正、原题无提示复测与新情景迁移分别设计；补充课见[英语补充](english-remediation.md)。

## 7. 交付前整链自检与工具协作

完成正文后，从声明的学习起点按实际顺序读到练习；不要凭块标题或作者自己已知的知识补脑。新课和既有课都执行，未改的链也需按本次审查范围核对。先按学习者当时可见的信息检查，再跨段对照同一过程：

- **关系与先修**：首次使用新对象、机制、术语、缩写、公式符号或操作时，必要解释是否已出现且可见？读者是否知道陌生名词/符号指什么，而不只是见过它的全称？开头是否堆了尚未理解的结论？引用前课有无实际依据？
- **解释职责与负荷**：按§5对照相近任务的输入、路径、结果与学习用途，定位跨组件/远距离复述；明确各处为何保留或如何合并。必要重复与无效重讲分别裁定，不能只删除summary/steps交差。
- **概念展开与阅读路径**：从真实连续阅读看，读者是否能定位当前问题、辨认对象关系并跟住关键变化？不同问题是否被一串同级标题伪装成一层？本可直接呈现的对应关系、属性维度、状态/量的变化，是否仍需从几段文字中自行拼出？按展示审核§2改写其实际信息表达，补过渡和可理解的局部示意，不以换块型/字号/配色判通过。正确的短文与因果叙述可继续保持正文。
- **顺序与引用**：移动/拆合后，逐一核对“下一块、前面、如下、见案例”等指向，按实际顺序打开目标；优先使用可辨认的内容标题和实际支持的引用。同步核对大纲、稳定ID、题目与review_reference来源，不编造链接能力。并列机制的流程是否被误串，几种“顺序”是否各自说明用途和条件？
- **独立检验**：只给声明的前置和常显正文，能否解题并说明理由？关键状态、推理和核验是否还在？新情景是迁移还是未教内容？参考是否完整且与题目条件一致？

发现缺陷回到受影响的骨架和正文，连带修正题目/参考/组件，再按新顺序复读该链。重排不自动要求拆块或改题；同一语义对象保持稳定ID。正确结构可保留，但NOOP需要实际内容复核依据，旧的“已发布”不能代替本轮检查。

修订交付用少量实际位置和前后解释顺序说明：原先哪里先用后教/重走过程，现在哪里首次解释、哪里完整演示、其他位置为何保留或合并；同时说明保住的理解与覆盖。仅改标题、元数据、引用来源、折叠状态或revision，不能据此报告教学重编排完成。工具成功而内容缺陷未修时，分别报告已写入与未通过的内容项；问题表只记有问题/有争议的位置、证据、改法和未决项，不为正确简单段落重复长报告。

结构校验、内容审核、真实渲染是三道独立关：CLI validate只验包结构；作者按授权来源逐条复核事实/教学语义，`course quality-check`只读分析包与可选回执；最后必须由实际StudyFlow桌面端或浏览器Vue页面加载准确候选/版本，检查真实视口并保存渲染回执。若当前CLI无渲染/截图能力，回执必须来自外部真实渲染器；quality-check读取`--rendering-receipt`不等于它执行了渲染。没有真实宿主或回执格式未核实就标“真实呈现未验”，不以结构验证、零告警、截图占位或手写HTML替代。技术断言、公式条件、分类口径和数值需按授权来源复核，去重/重排不代表事实已核实；缺依据列未决。工具的蓝图引用和英语`teaching_chain_list`只是结构/清单，不会认证解释链。三关分别记录对象版本、结果、时间和证据；未读/未验明确列出。

先用少量不同主题样本验证方法，再扩批；加入合理复用的保留对照，并含一个未被规则点名的新任务，避免只会修已知案例。未实际运行独立审查不称独立验证；自审和用户阅读感受分别报告。

## 8. 交付、修订与长期闭环

授权写入后走实际CLI导入或原位preview/apply，再回读计划归属、顺序、知识点/题数、content_revision与当前状态。实际材料更新成功会重置目标课程当前学习，保留笔记/历史；失败、无变化及幂等重放不能反复重置。存量旧状态按明确课程授权使用[维护](course-maintenance.md)reset-learning，不要求先完成旧题，也不将purge当常规修法。批改历史证据仍按原始材料解释。

长期方向按[工作区治理](learning-workspace-governance.md)拆有限阶段，滚动细化后续少量课，把真实反馈用于先修、负荷与检验设计；没有证据写未知，不将课量/发布/无错题当掌握。英语按[按需取词](vocabulary-selection.md)，具体考试数字与目录预算留计划。内容、协议、呈现、真实学习效果分别报告。
## 9. 作者资料归档与会话恢复

草稿、蓝图、来源清单、内容复核记录及工具回执保存在独立Agent协作工作区的`course-archive/`与`records/`；目标、计划、参考原件和每次使用日志分别按[工作区结构](workspace-structure.md)归档，不要放进软件源码仓库或CLI数据目录。发布后归档实际提交的包、稳定ID、CLI返回的course ID/content revision和验证回执；每次用于规划/制课的CLI学习事实及每次批改回执也要写入相应记录，确保下个会话能复用依据。课程库中的生成内容仍以CLI读取结果为准，不能直接改归档文件假装已经修订数据。归档不含学习者答案、笔记、凭据或整库导出。

跨会话恢复从协作工作区的`AGENTS.md`、`INDEX.md`和`state/current.md`开始，再按当前任务读取最近相关决定/记录；不递归读取全部历史课程。按[入口与工作区恢复](entry-workflow.md)初始化和维护这些文件。
